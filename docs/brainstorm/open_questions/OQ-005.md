# OQ-005 — What are the current delivery and maintenance constraints?

## Resolution — 2026-09-06 (user)

Prope is now maintained independently by the repository owner as a personal graduation-thesis
project at the National Economics University (NEU). The repository therefore assumes one maintainer with no
dedicated operations team. The academic schedule is managed outside the product repository and does
not gate runtime design decisions.

## Question
What delivery schedule and maintainer capacity constrain the project?

## Why it matters
Scope and operational complexity must fit a single maintainer. This confirms the surviving part of
A-012: one command brings the stack up, and the system remains debuggable by one person.

## What we know already
- The application already runs as a Docker Compose stack.
- There is one active maintainer and no dedicated operations team.
- Thesis milestones are external project-management information, not application configuration.

## Options
Resolved by the repository owner.

## Recommendation
Keep deployment and maintenance procedures viable for one person; revisit only if the operating
model gains dedicated maintainers or managed infrastructure.
