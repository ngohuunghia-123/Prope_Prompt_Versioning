# OQ-004 — Which model provider runs the eval suite, who pays, and is there a spending cap?

## Resolution — 2026-08-08 (user)

> "Provider, Model user toàn quyền kiểm soát trên 1 dashboard."

Prope does not choose a provider. The workspace registers its own providers and credentials from a
dashboard and selects the provider and model per prompt. Bring-your-own-key: the workspace's own
credential pays for both eval runs and gateway traffic.

**Consequences applied**
- New constraint: provider credentials encrypted at rest, never returned by a read API, redacted in
  logs and audit records. Prope now holds third-party secrets, which widens OQ-006.
- A-024: provider, model, and generation parameters are part of the revision, so changing the model
  creates a revision and goes through review like any other change.
- A-025 (credential handling), A-029 (optional per-workspace spend ceiling, default off),
  A-030 (only providers returning a `usage` object are supported in the MVP).
- The success metric "token counts within ±2% of provider-reported usage" stays valid, because
  A-030 makes a `usage` object a support condition rather than an assumption.

## What this does not answer
Nothing blocking. The two facts that were genuinely yours — who pays and who picks — are settled by
making both the workspace's decision. The spend ceiling defaults to off (A-029) because it is now
the workspace's own money; overturn A-029 if a hard ceiling is wanted for the demo account.

## Options
1. One provider, one cheap model, live calls, hard per-run cap.
2. Live calls plus a recorded-response cache.
3. Replay-only for the demo.
4. **Workspace-configured providers, BYOK.** ← selected (not among the options I offered)
