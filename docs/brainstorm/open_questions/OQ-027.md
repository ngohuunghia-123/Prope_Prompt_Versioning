# OQ-027 — The vocabulary count is 30 in six places and 31 in five. Which number does AC-6 assert?

**Raised by Phase 4 planning (04-CONTEXT.md, D-60), 2026-08-10.** The build ships either way —
`blocks_build: false` — and the deviation is recorded here rather than absorbed, per
`.planning/BSP-LINK.md`: *a spec that disagrees with the code is information; raise an `OQ-NNN`
naming the exact field and the conflict; do not patch the spec to agree.*

## The conflict, stated exactly

`docs/modules/property-history.lock.yml`'s change_log for 2026-08-09 records that ADR-0054's
`user_tombstoned` took the vocabulary *"from 30 registered actions to 31, propagated to every place
the count is stated — ADR-0024, ADR-0038, ADR-0053, A-120, A-124, tech_stack.md, interfaces.md and
six lines in this file."*

**The propagation updated one line per file and left the rest.** Both numbers are now live in the
authorities, and in two files they are live in the same document:

| File | Line | Says |
|---|---|---|
| `docs/adr/0024-…-registered-payload.md` | 1 (title) | `closed 30-name vocabulary` |
| `docs/adr/0024-…-registered-payload.md` | 13 | `**30 event types from five modules**` — and the table below it lists **nine** access-control events, without `user_tombstoned` |
| `docs/adr/0024-…-registered-payload.md` | 53 | `one of 31 registered names` |
| `docs/adr/0024-…-registered-payload.md` | 120 | `a fixed asset with a number attached to it — 30` |
| `docs/architecture/interfaces.md` | 229 | `**31 registered actions across 5 writers**` |
| `docs/architecture/interfaces.md` | 248 | `must be in the 30-name closed vocabulary (ADR-0024)` |
| `docs/architecture/interfaces.md` | 312 | `A 30-value enumeration maintained in five lock files` |
| `docs/brainstorm/assumptions/A-120.md` | 15 | `one closed list of 31 names` |
| `docs/brainstorm/assumptions/A-120.md` | 25 | `All 30 values live in one column of one table` |
| `docs/brainstorm/assumptions.md` | 128 | `the vocabulary is closed at 30` |
| `docs/modules/release-control.lock.yml` | 106 | `Two naming schemes in one 30-value enumeration` |

## Why it matters more here than a stale number usually would

`property-history` AC-6 (requirement **PH-06**, Phase 5) is an **asserted set equality**: the seeded
`history_action_registry` compared against the union of five lock files' event lists, *"31 names, no
extras and no omissions."* The whole design intent of AC-6 is that the vocabulary stops being a
number maintained by hand in six places. A criterion whose own authorities disagree about the
cardinality is the exact defect AC-6 exists to make impossible, arriving one layer up.

**ADR-0024's Context table is the serious half, not the title.** It is the only place in `docs/` that
lists the five modules' events side by side, so it reads as a normative list; it omits
`user_tombstoned`; and a reader who derives the vocabulary from it — rather than from the five lock
files' `outputs` blocks — gets 30 names and a red AC-6.

## What Phase 4 did meanwhile

Derived the vocabulary from the **five writing modules' `outputs` blocks**, which is the source AC-6
names, and got **exactly 31 with no adjustment** — `user_tombstoned` is already inside
`access-control.lock.yml` `outputs`, so nothing had to be added by hand. The migration seeds those
31 and the derivation is recorded in
`.planning/phases/04-schema-privilege-ordering-and-the-closed-vocabulary/04-CONTEXT.md` (D-60) so
Phase 5's AC-6 has a written baseline to compare against rather than re-deriving it.

## What a resolver has to choose between

1. **31, and correct the six stale lines.** What the build does, what the lock file says, what
   ADR-0038 and ADR-0054 say, and what the derivation produces. Costs six one-line edits across four
   files, one of which is a table row in ADR-0024 that has to gain `user_tombstoned`.
2. **30, and remove `user_tombstoned` from the registry.** Would require reversing ADR-0054, which is
   Accepted and was a user decision. Not seriously available; recorded so the option set is complete.

There is no third option in which both counts are right.
