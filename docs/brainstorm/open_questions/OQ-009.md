# OQ-009 — What cost increase counts as a regression, and does it ever block?

## Resolution — 2026-08-09 (user)

**Option 1. Warn at ≥ +20%. Never block.**

The threshold and the block behaviour remain configuration values as FR-08 requires — defaulting to
20% and to off — but the default is now a decision rather than a placeholder. The review screen shows
the warning above the decision buttons; nothing about cost can refuse a release.

This closes `positioning.md` §12 T2 in favour of `BRIEF.md` §5③: the demo may show a cost gate, and if
it does it must be described as configurable policy rather than default behaviour. It also keeps the
product's one hard gate singular — a release is refused for exactly one reason, that the revision is
not `Approved`, and that refusal lives in a database constraint.

**Consequences applied**: [[A-016]] flips from an agent default to a user decision. `evaluation`'s lock
records the resolution against its `prope_evaluation_cost_delta_ratio` histogram, which is the metric
the threshold reads.


## Question
What percentage or absolute increase in eval-run cost should raise a warning? And should the system
ever be able to block a release on cost, or is it warn-only for this build?

## Why it matters
FR-08 requires the block/warn policy to be **configurable**, which means someone has to pick the
default and the threshold. `positioning.md` §12 T2 records the unresolved tension: the positioning
demo shows cost blocking a release on stage, while the priority matrix puts S9 at P2, "defer and
validate". Whether a red gate appears in the demo is a pitch decision, not a code decision.

## What we know already
- `BRIEF.md` §5③: MVP shows delta plus warning, does not hard-block; any blocking shown on stage
  must be described as configurable policy, not default behaviour.
- Only 2/11 enterprise respondents have ever experienced an unexpected cost increase.

## Options
1. Warn at ≥ +20%, never block.
2. Warn at ≥ +20%, block at ≥ +50%; both configurable, defaults off.
3. Display the number, no threshold logic at all.

## Recommendation
A-016 records option 1 as the working default. The threshold number itself is a judgment about your
own cost tolerance, so I am not fixing it silently.
