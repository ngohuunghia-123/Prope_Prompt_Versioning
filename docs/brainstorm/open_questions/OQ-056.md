# OQ-056 — The `credential` field list declares one nonce; AES-GCM envelope encryption needs two

**Raised by Phase 10 planning, 2026-08-11.** `blocks_build: false` — plan 10-01 adopts an answer and
records it as UNCONFIRMED. Raised because **the declared field list cannot be implemented as written
without a cryptographic misuse**, and the alternative edits a lock file by fact.

## The problem, stated once

`data.owns.credential.fields` lists exactly one `nonce`. ADR-0014 requires **two** encryptions:

1. the secret, under a per-credential 256-bit data key (DEK);
2. the DEK, under the key-encryption key (KEK).

AES-GCM's security collapses under nonce reuse with the same key. The wrap is where reuse would be
**systemic rather than local**, because one KEK wraps every DEK in the system: reusing a nonce across
two wraps under the same KEK leaks the XOR of the two data keys and makes authentication tags forgeable.

There is no implementation of the declared field list that is also correct. Reusing `nonce` for both
operations is not a shortcut; it is the misuse.

## The two options

**A — prefix the wrap nonce to `wrapped_dek`.** `wrapped_dek` stores
`nonce(12 bytes) || AESGCM(kek).encrypt(nonce, dek, aad)`. The declared field list stays literally true.
`wrapped_dek` becomes one self-contained value that cannot be paired with the wrong nonce. Cost: two
`bytea` columns in one row mean two different things, and the framing exists only in code.

**B — add a `dek_nonce bytea NOT NULL` column.** Every stored value means exactly one thing and the row
is self-describing. Cost: it adds an undeclared column to the highest-liability table in the system,
which is the silent widening ORCHESTRATION §5 exists to refuse; and it re-introduces the failure A
removes — two columns that must be updated together, in the one operation (the KEK re-wrap) that
touches both.

## What phase 10 shipped

**Option A.** The deciding argument is the re-wrap. `rewrap_data_key` moves `wrapped_dek` and
`kek_version` while leaving `ciphertext` and `nonce` **byte-identical** — and that byte-identity is the
sharpest available proof of ADR-0014's own claim that a KEK rotation *"does not touch a single
ciphertext"*. With the prefix, the re-wrap writes exactly two columns and the assertion is *"these two
changed and those two did not"*. With a separate `dek_nonce`, it writes three and the assertion has one
more moving part.

The framing is documented in three places so the "undocumented convention" cost is paid rather than
deferred: a `COMMENT ON COLUMN` in the migration, `crypto.py`'s module docstring, and a named
`WRAP_NONCE_BYTES = 12` constant the slice is written against.

## Reversal cost, and why it only grows

Changing the layout is a **data migration that must decrypt every credential and re-encrypt it** — the
exact migration ADR-0014 was written to avoid. It is cheap only while the pilot holds no real
credentials, which A-020 currently guarantees (*"no real corporate prompts in the pilot until OQ-006 and
OQ-013 are answered"*) and will not guarantee forever.

## The question

Should `data.owns.credential.fields` be amended to add `dek_nonce`, or does the prefix framing stand?
