# OQ-155 - Should the migration skill emit static relationship hints?

**Raised 2026-08-19 by ADR-0066.** `blocks_build: false`, `blocks_pilot: false`.

## What v1 does and does not do

The ask included *track relationship*. ADR-0066 excludes it from v1: the skill reports call sites and
their enclosing functions as context for the manifest reviewer, and does not attempt to emit a
conversation graph.

The reasoning is that a **wrong** chain is worse than no chain, because it draws a picture somebody
trusts. Static recovery of a call graph across dynamic dispatch, configuration-driven routing and async
queues is hard to get right, and the failure is silent. Once the SDK is in place the chain is threaded
by construction (ADR-0065) and observed rather than inferred.

## The case for adding hints anyway

The runtime answer only exists **after** the migration ships. During the manifest review - which is
exactly when a person is choosing namespaces and names for forty prompts at once - knowing that three of
them are called in sequence from one function is genuinely useful, and it is information the agent
already has on screen.

A hint that is presented as a hint does not carry the trust problem. The distinction is between
*emitting a graph* and *annotating a row*.

## What would settle it

The first real manifest review. If reviewers ask *which of these run together* and have to go back to
the source to find out, the hints are worth adding as annotations. If they name prompts fine without
them, this closes.
