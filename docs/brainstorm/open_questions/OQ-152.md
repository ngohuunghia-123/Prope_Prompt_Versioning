# OQ-152 - Which languages does the SDK cover, and what does an old SDK meeting a new gateway do?

**Raised 2026-08-19 by ADR-0065.** `blocks_build: false` for the first SDK, `blocks_pilot: true` for
the second.

## What changed

Until ADR-0065 every artefact Prope shipped ran on Prope's own VM: 7 services, 2 images (ADR-0033), all
deployed together, all upgraded together. An SDK runs in a **customer's** process, at a version Prope
cannot force, against a gateway that keeps moving.

## The questions

**Which languages.** Python is first because the gateway is Python and the pilot's applications are
Python. JavaScript/TypeScript is the obvious second and is where the market's cheapest integrations live
- PromptLayer's `node --import promptlayer/register` touches no source at all. Beyond those two, the
honest answer may be *none*, and to document INT-022 instead: it is an OpenAI-compatible endpoint and
any language can already call it.

**What an old SDK must do.** The requirement is that the answer is never *fail*. INT-022 is additive
today - unknown fields in the `prope` block are ignored - but nothing asserts that, and an SDK pinned at
v1 against a gateway two quarters newer is exactly the case nobody tests until a customer reports it.

**Whether the SDK version reaches the call record.** A support question that begins *which SDK were you
on* is unanswerable today. A version string on the request is cheap; a version string that becomes a
metric label is a cardinality decision (ADR-0030).

## What would settle it

The first customer who is not on Python. Until then, one SDK and a documented wire format is the
proportionate answer, and this file exists so that shipping the second one is a decision rather than a
drift.
