# OQ-012 — The gateway is a hard dependency of production traffic. On what terms?

## Resolution — 2026-08-08 (user)

> "Có, Prope là hard dependency. Prope là một nơi trung gian để gắn system prompt và gọi model,
> ngoài ra Prope còn lưu lại lịch sử request/response, sử dụng cho mục đích truy xuất, cải tiến sau
> này (tích hợp LangFuse). Tôi dự định một prompt sẽ có fallback answer do người viết (hoặc AI
> generate trước) để fallback nếu có lỗi xảy ra. Về latency, tôi dự định áp dụng thuật toán redirect
> trước, lưu logs sau, giảm thiểu tối đa latency. Logs sẽ được lưu trong Prope."

| Sub-question | Answer |
|---|---|
| 1. Is Prope allowed to be a hard dependency? | **Yes**, accepted. No consumer-side fallback is assumed. |
| 2. What happens on failure? | A **fallback answer** stored on the revision is served. |
| 3. Latency strategy | Forward first, log after. Logging never sits on the response path. |
| 4. Consumer-side cache | Not used. Prope resolves every call; a short server-side cache remains (A-031). |

## What is still open

**The availability target itself.** You accepted the dependency but did not state what uptime the
gateway is expected to hold, and there is no number to design against or to tell a consuming team.

**The hole the fallback does not cover.** The fallback answer is stored *in Prope*. It protects
against a provider failing; it does nothing when Prope itself is down, which is precisely the
scenario the hard-dependency decision creates. `BRIEF.md` §3 says this is the event that triggers
the developer veto and kills the product for the marketer too. Two ways to close it exist and both
are yours: publish an uptime target and accept the risk explicitly with consuming teams, or let the
client SDK cache the last successful resolution locally so a Prope outage degrades instead of stops.

**The latency number.** A-031 carries a provisional p95 of 50 ms of added latency so step 2 can
proceed. Your strategy answers *how*; the budget answers *how much is too much*, and a developer
will ask for that number before pointing production traffic at it.

## Recommendation
None of the three blocks step 2. Answer them before any consuming team is onboarded, not before the
module map.
