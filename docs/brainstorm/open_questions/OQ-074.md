# OQ-074 — The searchable body is the *latest* revision's, so the body production is actually serving can be un-findable

**Raised by Phase 13 planning, 2026-08-11.** `blocks_build: false` — plan 13-01 implements the corpus
exactly as ADR-0048 specifies it, and plan 13-04 asserts it. Raised because implementing it made a
product consequence visible that no authority states.

## The problem, stated once

ADR-0048 bounds the search corpus at *"the **latest** revision's body"*, and the owed AC-11 pins it from
the other side: *"a term matching only a NON-latest revision's body returns nothing."* Both are
deliberate and both are argued — indexing every revision is a 20× cost on the only number anyone wrote
down, and historical hits are false positives against the task H-01 measures.

**"Latest" is `max(revision_number)`, and it has nothing to do with `status`.** So:

1. A prompt is registered, revised to revision 7, approved and released. Production serves revision 7.
2. Somebody opens the editor and saves revision 8 as a `Draft` — which is the ordinary, encouraged act
   this whole product exists to make safe. Nothing is approved and nothing is released.
3. `search_text` is rewritten from revision 8. **Revision 7's body — the text production is serving
   right now — is no longer in the index.** A search for a phrase that appears only in it returns
   nothing.

The failure shape is the one ADR-0048 names as the worst available for a register: *"indistinguishable
from 'nobody wrote a prompt about that'"* — no error, no metric, no failed query. Here it is produced by
correct behaviour rather than by drift, which is why the trigger test cannot catch it.

It is partly softened and not closed: the prompt is still findable by title, purpose, tags, and by every
revision's change summary — including revision 7's. What is lost is finding it **by a phrase in the text
production is running**, which is close to the sentence `00_context.md#problem` opens with.

## The candidates

**A — leave it.** ADR-0048's argument stands, the change-summary fold covers the common recall case, and
a draft is what the author most recently meant. Cost: the scenario above, silently.

**B — index the latest **and** the released revision's body.** Two bodies per property instead of one:
64 MB at A-050's cap instead of 32 MB, still an order of magnitude under the 640 MB the ADR rejected.
The released body is already reachable in one indexed read (`released_version_id` is a column on the row
the trigger is writing). Cost: the trigger's recompute also has to fire when the released pointer moves —
one more trigger event on `prompt_property`, on a column `set_released_revision` already writes — and
`search_text` becomes a **third** copy of a prompt body rather than a second, which widens T-017 and
OQ-006 by one more column-worth of text.

**C — index the latest *approved* revision instead of the latest.** One body, and it is the one a
reviewer is most likely to search for. Cost: a brand-new prompt with only `Draft` revisions is findable
by nothing but its title until somebody approves it, which is worse for the *"non-developer creates and
submits a revision"* success metric than the problem it fixes.

## What phase 13 shipped

**Option A, unchanged**, because ADR-0048 decided the corpus explicitly and a planner is not the right
place to reverse it. Plan 13-04 asserts the specified behaviour, including the half that makes this
question concrete: a term present only in a non-latest body returns nothing.

**The reason this is worth a question rather than a comment** is that Option B is cheap **now** and stops
being cheap later: it is one extra branch inside a trigger that does not exist yet in production, versus
a backfill of `search_text` across every property plus a re-index once the pilot holds data.

## What the answer changes

Option A: nothing. Option B: one additional `UPDATE OF released_version_id` trigger event and one more
sub-select in `registry.compose_search_text`, plus a one-statement backfill. Option C: one `WHERE
status = 'Approved'` in the same sub-select, and a re-read of AC-11, which asserts the latest-body rule
directly.
