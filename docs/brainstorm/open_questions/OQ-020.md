# OQ-020 — INT-021 registers `get_run_totals(run_id)`. The build takes the workspace too.

**Raised by Phase 2 plan 02-04 while implementing D-20, 2026-08-10.** The code ships either way —
`blocks_build: false` — and the deviation is recorded here rather than absorbed into the spec, per
`.planning/BSP-LINK.md`.

Third of the three deviations this phase raises, and its own file because it blocks a different
upstream field from OQ-018 (`call-ledger.lock.yml` `data.owns`) and OQ-019
(`call-ledger.lock.yml` `apis.exposes`). This one blocks `docs/architecture/interfaces.md`. A
resolver can accept any one without accepting the others.

## The conflict, stated exactly

`docs/architecture/interfaces.md` INT-021 registers **`get_run_totals(run_id)`** — one argument.

`src/prope/call_ledger/seams.py` ships **`get_run_totals(sessionmaker, workspace_id, run_id)`** —
the workspace before the run.

Everything else about INT-021 is honoured unchanged: the six-field return
(`input_tokens`, `output_tokens`, `cost`, `currency`, `unpriced_count`, `unknown_usage_count`), the
counts as part of the answer rather than as diagnostics, currency travelling with the figure with no
FX conversion, and *raises -> run error at evaluation, and no delta*.

## Why the one-argument form cannot work, structurally

This is not a style preference and it is not "add a second argument for convenience". **There is no
path in this system on which a `run_id` alone identifies anything.**

Under ADR-0045 every `ledger` table carries a deny-by-default tenant policy comparing `workspace_id`
against `current_setting('app.workspace_id')`. A `prope_app` read issued with **no** workspace set
matches nothing and returns **zero rows** — the policy working exactly as designed. Combined with
D-19's own-transaction shape, that means:

- The function must set a tenant **before** any read it makes.
- The lookup that would resolve the workspace *from* the `run_id` **is itself a read**.
- So it would resolve nothing, forever, silently — a run that exists would report as an empty run.

Plan 02-03 hit the identical wall from the other direction, with a workspace-enumerating query for
the retention sweep, and recorded the same finding.

**The alternative a resolver would have to accept is a fifth `SECURITY DEFINER` function** — a
routine that bypasses the policy to answer "which workspace does this run belong to". Exactly four
are sanctioned (`access.lookup_session`, `access.lookup_api_key`, `evaluation.claim_next_run()`,
`access.list_workspaces()`) **and a test asserts the set is exactly those four**. Adding a fifth to
avoid an argument is spending a privilege escalation on a parameter.

The caller passes the workspace it already holds. That is `check_spend_ceiling`'s posture in the same
module, and it is the rule access-control lives by: **callers supply the subject** (ADR-0020).

**The schema already assumed it.** Phase 1's `ix_call_record_workspace_id_run_id` — added with a
comment naming this phase — leads with `workspace_id`. The one-argument form could not have used it.

## The identity-model change, stated plainly

The noun that is now primary is the **(workspace, run)** pair. `workspace_id` is promoted to the
leading identity component and `run_id` is demoted to a discriminator within it.

The companion invariant is asserted rather than assumed:
`tests/integration/test_run_totals.py::test_a_run_belonging_to_another_workspace_is_invisible_and_returns_zeroes`
writes a run into one workspace, proves through `migrate_engine` that the rows exist, and shows the
other workspace's context reads zeroes. A one-argument convenience wrapper added later would have to
break that test, which is why it is written.

## Why this does not block the build

`blocks_build: false`. The function exists and is tested; evaluation, its only consumer, is Phase
16/17. What the answer settles is which signature Phase 17 is written against.

## The shape of the possible answers

1. **Amend INT-021 to `get_run_totals(workspace_id, run_id)`.** Matches the build, matches the index,
   matches `check_spend_ceiling`, matches ADR-0020's "callers supply the subject". Changes no code.
2. **Keep the one-argument signature and add a fifth `SECURITY DEFINER` resolver.** Requires
   amending the sanctioned set, amending the test that asserts it is four, and accepting a privilege
   escalation whose only job is to save a parameter.
3. **Keep the one-argument signature and pass the workspace out of band** (a context variable, an
   ambient session). Rejected on sight: it is the implicit-tenant pattern ADR-0040 and
   `db/session.py` exist to refuse, and it would make the tenant a thing a caller can forget.

**A recommendation:** option 1.
