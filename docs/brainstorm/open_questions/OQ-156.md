# OQ-156 - The manifest holds real prompt bodies on a customer's disk. What protects it?

**Raised 2026-08-19 by ADR-0066.** `blocks_build: false`, `blocks_pilot: true`.

## The problem

ADR-0066's dry-run default is what makes the skill safe against A-020: a run ends with a **manifest**, a
file listing every candidate prompt with its extracted body, its variables and its source location.
Nothing is uploaded and nothing in the repository changes.

But that file is a plaintext inventory of every prompt in the customer's product, sitting in their
working directory, in a repository somebody may commit. **A migration that leaks prompts into version
control has moved the problem rather than solved it** - and it has moved it somewhere worse, because a
git history is not deletable the way a Prope row is.

The bodies were already in the repository, so this is not a new disclosure of the *content*. It is a new
disclosure of the *collection*: one file that says here is every prompt this product uses, which is
exactly the artefact an attacker would otherwise have to assemble.

## The options

- **Git-ignore by default and say so loudly.** Cheapest, and it is what ADR-0066 already requires.
  Depends on the customer's tooling honouring it and on nobody using `git add -f`.
- **Write outside the repository** - a temp directory or an OS config path. Removes the commit risk and
  makes the manifest harder to review in the tool the reviewer is already in, which is the whole point
  of it being a file.
- **Encrypt at rest with a key the person supplies.** Strongest, and it makes the review step require a
  decrypt - friction at exactly the moment ADR-0066 wants the reviewer to actually read the thing.
- **Never write bodies to the manifest** - reference source locations only, and have the reviewer read
  the prompts in their own source. Elegant, and it breaks the *extraction* review: the whole value of
  the manifest is showing what the canonical body **became** after A-011 and A-078 normalisation, which
  is not what the source says.

## What would settle it

The first white-glove integration. Whether the manifest is treated as a working file that is deleted
after the run, or as an artefact somebody keeps, decides which of these is proportionate.
