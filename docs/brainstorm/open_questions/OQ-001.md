# OQ-001 — Is the five-feature list the complete MVP scope, or does import/ingestion stay in?

## Resolution — 2026-08-08 (user)

> "USP #1 không nằm trong MVP, chúng sẽ được đưa vào sau như một tính năng tích hợp."

Option 1 selected. Import and ingestion are out of the MVP entirely and will return later as an
integration feature. Prompts enter by manual registration only.

**Consequences applied**
- `00_context.md#scope` — import/ingestion moved to Out of scope with this resolution cited.
- Demo evidence item #1 in `BRIEF.md` §10 ("import a real repo + a real Sheet in under 2 minutes")
  and the "N discovered, M governed" screen are not deliverable from this build. The demo narrative
  needs a different opening beat; that is a pitch task, not a build task.
- `BRIEF.md` §12 risk #3 ("ingestion quality is the riskiest technical item, do it in week 1")
  no longer applies to this cycle.
- `positioning.md` USP #1 is now a roadmap claim with no shipping code behind it. Per
  `BRIEF.md` §12 risk #9, it must be presented as roadmap, not as capability.

## Question
The MVP specified was: registry, version diff, fixed evaluation, cost delta, HITL release.
`prope_source_of_truth.md` §16 defines the MVP as add + **import** prompt, registry/search, owner,
revision history, diff, statuses, access, one reviewer, approve/request-changes, property history,
and a simple approved-revision API. Which list is the scope?

## What we knew already
- `positioning.md` §12 T1 already recorded that auto-scan is not in the source-of-truth MVP.
- `BRIEF.md` §12 risk #2 names scope as the second-largest risk.

## Options

2. Five features + one narrow importer.
3. Five features + importer + approved-revision export/API.
