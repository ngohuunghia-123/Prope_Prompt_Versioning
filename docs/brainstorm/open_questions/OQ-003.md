# OQ-003 — What does "promote" promote to in this MVP?

## Resolution — 2026-08-08 (user)

> "Nội bộ, SDK tôi đang dự định dùng luôn OpenAI compatible. Trong hệ thống, mỗi prompt tương ứng
> với 1 'model', ví dụ gọi model 'ecom/agent-pipeline' trên OpenAI SDK sẽ nối vào model và system
> prompt quản lý trên trang web phiên bản mới nhất đã được promote."

Prope exposes an **OpenAI-compatible gateway**. A prompt property is addressed as a model name.
Calling `ecom/agent-pipeline` through any OpenAI SDK resolves to the currently released revision,
applies its system prompt and model binding, and forwards to the configured provider.

**Consequences applied**
- `00_context.md#scope` — gateway and usage recording moved into In scope; "API/SDK for runtime
  retrieval" removed from Out of scope.
- New constraint: OpenAI wire compatibility, including streaming and error bodies.
- New glossary terms: Model name, Gateway, Released revision, Usage record.
- A-021 through A-023, A-026, A-027, A-030 record the resolution rules I decided.

## The part of the answer that contradicts the answer

You answered "nội bộ", but the mechanism you described is not internal — it is the request path.
An OpenAI-compatible endpoint that resolves a prompt at call time means every production request
passes through Prope, and Prope holds the provider credential and issues the upstream call.

That reverses a stated anti-goal. `positioning.md` §6 lists "không nằm trên hot path" as
anti-positioning, §12 T3 flags it as an unresolved tension, and `BRIEF.md` §3 states the reason:
the developer persona has veto power and exercises it the first time Prope causes a production
incident, at which point the marketer's tool dies with it.

It is a defensible reversal — the gateway is what makes Used by, cost per revision, and blast
radius fall out of an action someone was already taking, which is the design law in `BRIEF.md` §7,
and it is the only way a restore changes production without a redeploy. But it is not internal, and
the conditions that make it survivable are **OQ-012**, which is now open.
