# A-047 — The diff is computed on demand and never stored

**Statement**: Comparing two revisions runs the diff at request time. No diff is persisted. The output
is a line-level diff of the prompt body (A-015) plus a field-level comparison of provider, upstream
model, generation parameters, and fallback answer.

**Rationale**: A stored diff is derived data with no independent truth: it doubles on every edit, and
the day the diff algorithm improves, every stored diff is wrong while the revisions it describes are
still right. With bodies capped at 32 KiB (A-050) recomputation is cheap enough to fit the 300 ms
render target. The field-level half exists because A-024 put the provider, model, and parameters on the
revision — a reviewer approving a "prompt change" that silently swapped the model would be approving
something they cannot see in a body diff.

**Impact if wrong**: Adding a cache keyed by the two version IDs is additive; the revisions are
immutable, so such a cache can never go stale.
