# A-068 — A revision approval does not expire; the release screen states its age

**Statement**: An approval remains valid indefinitely. There is no expiry timer, no scheduled
re-approval, and no automatic invalidation when newer revisions are created. Instead the release screen
states the approval's age, its reviewer, and how many revisions have been created since — and releasing
an approved revision that is no longer the newest is allowed and flagged, not blocked.

**Rationale**: Scheduled re-review is explicitly out of scope (`00_context.md#scope`), and an expiry
would mostly manufacture re-approval theatre: the same reviewer clicking the same button on unchanged
text. The real risk — releasing a stale approval believing it is current — is a display problem, and
displaying the age costs one field. Restoring an older approved revision is a legitimate act (A-010), so
age alone cannot be disqualifying.

**Impact if wrong**: A timestamp comparison and a status filter. One conditional.
