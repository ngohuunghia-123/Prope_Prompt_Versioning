# A-089 — provider-access always requests usage from the provider; it is never a caller option

**Statement**: Every upstream request provider-access composes asks for token usage —
`stream_options.include_usage` on a streamed OpenAI-compatible call, and the adapter's equivalent
elsewhere. No caller can turn it off, and no caller has to remember to turn it on. The usage object is
returned alongside the response. If it is still absent, tokens and cost are recorded as **unknown**
and `prope_provider_access_usage_missing_total` increments; they are never estimated from length.

**Amends A-083 and ADR-0013**, which assigned the forcing to the gateway. That was written before
this module was locked, and it is in the wrong place: provider-access composes the upstream request,
so the gateway cannot set a flag on a request it does not build. The gateway keeps the caller-facing
half — stripping the extra usage-only chunk from a stream whose caller did not ask for it, since that
is a fact about the caller's wire contract and nothing else.

**Rationale**: Two success metrics and every cost delta behind a release decision depend on this
number, and BR-07 forbids inferring it. Unconditional beats configurable because the failure of a
configurable version is silent: the metric stays green on the calls that opted in and says nothing
about the ones that did not.

**Impact if wrong**: One line moves back across the seam. The half worth keeping under any answer is
that the request is composed in exactly one place.
