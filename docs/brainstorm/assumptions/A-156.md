# A-156 — A call is forwarded only when it is not addressed to a namespace this workspace uses

**Statement**: ADR-0059's forwarding mode is entered when, and only when, the consumer key is
observe-enabled and the model string is **not addressed to a namespace this workspace uses**. Two cases:

1. **No namespace at all** — `ModelName.parse` refuses the string, because it has no `/` or is outside
   A-021's shape. Decided syntactically, with **zero reads**. `gpt-4o`, `claude-sonnet-4`,
   `gemini-2.0-flash` all land here, and this is the common case.
2. **A namespace this workspace does not use** — `openrouter/…`, `meta-llama/…`. Checked against the
   union of `registry.folder` slugs and the namespaces observed on `prompt_property`, cached on the
   gateway's existing 30 s TTL.

Anything addressed to a namespace the workspace **does** use resolves or refuses exactly as it does
today, for every key. Unknown name, no release, unapproved pin and scope refusal remain four
byte-identical 404s.

**Rationale**: this replaces [[A-153]], which said the same thing one unit too fine and was therefore
unreachable. A-153 keyed on `MissReason.UNKNOWN_MODEL`, and no real unmanaged model name produces that
value: a bare name fails `ModelName.parse` before `resolve_binding` is called at all, and a
slash-carrying name is refused by `may_resolve` as `NOT_PERMITTED` before resolution runs, because a
key's scope is a list of prompt names and a provider's model is not one. ADR-0062 records the trace.

The namespace is the right unit for three separate reasons, and it is worth having all three written
down because only the first is obvious.

**It is the unit that is decidable.** The syntactic case needs nothing but the string, which means the
overwhelmingly common shape of an unmanaged call is answered before any table is opened.

**It is the unit that does not leak.** Deciding per *name* means an attacker with a leaked key learns
that `finance/pricing` refuses and `finance/nothing` forwards — the registry enumeration [[A-116]]
exists to close, arriving through a door nobody classified as a read, and charging the workspace a
provider call per probe. Deciding per *namespace* refuses both, because `finance` is a namespace the
workspace uses.

**It is the unit authority is already expressed in**, as of [[A-157]] and ADR-0061. A rule whose unit
matches the permission model's unit needs no reconciliation later.

**Impact if wrong**: the failure is in the safe direction and it is visible. A namespace a workspace
uses but has not created yet is refused for up to one cache TTL and then behaves; a namespace a
customer uses for *both* their Prope folders and their provider's model ids is the ambiguous case, and
it resolves toward Prope — the call is refused rather than forwarded, which is the direction every
other refusal in this product fails in.
