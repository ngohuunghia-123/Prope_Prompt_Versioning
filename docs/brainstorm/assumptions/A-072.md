# A-072 — A release is a compare-and-set on the released pointer, carrying the previous version ID

**Statement**: Every release request carries `expected_current_version_id`. The pointer write is refused
if it no longer matches the prompt's current released revision; the refusal names what is actually
released now. The accepted value is stored on the release row as `previous_version_id`. Releasing the
revision that is already released is refused as a no-op rather than appending a release row that changes
nothing. The release row and the pointer command commit in one transaction (A-012: one process, one
database).

**Rationale**: Two reviewers releasing two different revisions of one prompt within the same second is
not exotic — it is the normal shape of an incident. Without the check, the later write wins silently and
one reviewer believes they released something that is not in production, which is the worst lie this
module could tell. Storing the previous version also gives the release log a backwards chain for free,
so "what was in production before this" needs no window function.

**Impact if wrong**: A parameter and a WHERE clause.
