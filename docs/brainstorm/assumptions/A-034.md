# A-034 — The fallback fires on upstream failure only, never on caller failure

**Statement**: The fallback answer is served when the upstream provider returns a 5xx, times out,
rate-limits, or the credential is rejected. It is **not** served when the caller is at fault: unknown
model name, a pin to an unapproved or nonexistent revision, no access, or a malformed request. Those
return an OpenAI-shaped error naming the reason.

**Rationale**: A fallback exists to protect an end user from a transient provider outage. Serving one
for a misconfiguration converts a loud, fixable bug into a product that quietly answers every request
with the same canned text — the developer would have no signal that their model name was wrong. BR-03
also forbids resolving an unapproved revision, and answering anyway with a fallback would technically
honour the letter of that rule while destroying its purpose.

**Impact if wrong**: One classification table in the gateway.
