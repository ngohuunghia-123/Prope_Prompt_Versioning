# A-112 — A prompt grant carries a level: viewer or editor

**Statement**: `prompt_grant` is (prompt_id, grantee_user_id, level, granted_by, granted_at) where
`level` is `viewer` or `editor`. Viewer may read the prompt, its revisions, its diff, its activity, and
its eval runs. Editor may additionally create revisions and edit the eval suite. **No grant confers
approve, release, withdraw, or break-glass** — those five permissions come from role bindings only.

**Rationale**: "Grant access" is defined in the glossary as making a private prompt visible to a team,
which is the viewer case; but a prompt with two people working on it is the ordinary case in a group
where 11/11 report teammates using different prompts for the same task, and forcing that through
workspace-wide roles would mean granting edit on everything to allow edit on one.

The line is drawn at the review boundary on purpose. The non-negotiable constraint separates edit,
review/approve, and release as permissions; letting an owner hand out approve rights per prompt would let
a workspace's separation be dissolved one prompt at a time by the person with the most incentive to.

**Impact if wrong**: A third level is a value in an enum. Removing a level after grants exist is a
migration, which is why only two ship.
