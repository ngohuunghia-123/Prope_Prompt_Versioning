# A-056 — The spend-ceiling value is owned by call-ledger; evaluation asks it a yes/no

**Statement**: The optional monthly and per-run spend ceilings from A-029 are stored by `call-ledger`,
alongside the price tables and the spend totals they are compared against. Evaluation calls
`check_spend_ceiling(workspace_id)` before dispatching the first case of a run and receives `allowed` or
`refused` with a reason — never a spend figure. A refused run is recorded with `status: refused` and the
reason shown to the actor.

**Rationale**: A ceiling is a threshold on a number, and the module that owns the number should own the
threshold; splitting them means the comparison happens somewhere that has to fetch both halves. Call
Ledger already owns `price_table` and every priced usage row, so it is the only module that can answer
the question without reading another module's data. Returning a boolean rather than the total also keeps
a reviewer who may run evals from seeing billing figures they may have no right to
(`00_context.md#constraints`, private by default).

**Impact if wrong**: One table and one function move. The seam — evaluation asks, call-ledger answers —
survives either way, and it never inverts the forbidden `call-ledger → anything` direction because
evaluation is the caller.
