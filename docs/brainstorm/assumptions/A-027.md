# A-027 — The eval runner calls a revision through the same resolution path as the gateway

**Statement**: Running an eval case against a revision uses the same resolve-and-forward code the
gateway uses for production traffic, with the revision pinned. There is no second code path that
builds the provider request differently.

**Rationale**: If eval and production assemble the request differently, a suite can pass on a
revision that then behaves differently in production, and the pass/fail badge on the review card
becomes a lie. Sharing the path also makes the cost delta (A-006) measured with the same accounting
as the production cost figures.

**Impact if wrong**: Splitting the paths later is easy; discovering they had silently diverged is
not, which is why this is written down rather than assumed.
