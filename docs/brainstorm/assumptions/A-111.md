# A-111 — Effective permission is the union of role bindings and per-prompt grants; there are no negative grants

**Statement**: `may(actor, action, subject)` allows the action if **any** of the actor's workspace role
bindings grants it, or if a `prompt_grant` on that subject grants it. Nothing subtracts. A user holding
two roles holds the union of their permissions. The caller supplies the subject's `owner_id` and
`access_level` as parameters, because access-control may not read the table they live on (ADR-0020).

**Rationale**: Union is the only rule whose outcome does not depend on evaluation order, and "why can't
this person do this" is the support question this module will be asked most. Under union it has one
answer that can be read off two small tables; under deny-overrides it is a search.

Nothing in the source documents asks for subtraction. BR-01's private-by-default is a *starting state* —
a prompt nobody has been granted is invisible — not a rule that removes a permission somebody else
added.

**Impact if wrong**: Adding deny rules later is a schema column and a change to one function, but every
existing grant would need re-reading under the new semantics, which is why this is `moderate` rather than
`cheap`.
