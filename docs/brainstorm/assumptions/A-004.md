# A-004 — The eval suite belongs to the prompt, not to the revision

**Statement**: Each prompt property owns one or more named suites of 10–20 hand-authored eval cases
(A-062, amended 2026-08-08 — this assumption originally said exactly one). Each suite is versioned
separately from the prompt's revisions, so the same suite version can be run against the candidate
revision and the current trusted revision and the results are comparable. Changing a suite is a
distinct, recorded action.

**Rationale**: A comparison between two revisions is only meaningful if both were measured with the
same yardstick. Attaching cases to a revision would make every diff run against a different suite.
BR-10 already argues that editing the eval contract is a different permission from editing prompt
text, which presupposes the contract is a separate object.

The amendment does not weaken any of this: the yardstick argument now holds *per suite*, and a
comparison never pairs runs of different suites or different suite versions.

**Impact if wrong**: A schema change and a rewrite of the comparison query.
