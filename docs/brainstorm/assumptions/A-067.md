# A-067 — At most one revision per prompt is In review; a newer submission supersedes the open task

**Statement**: Submitting a revision is refused while another revision of the same prompt is In review,
unless the submitter chooses to supersede: the older review task is marked `superseded`, the older
revision returns to Draft, and a new task opens for the newer revision. Approvals already recorded
against the older revision are never altered — they remain valid and it remains releasable.

**Rationale**: Two open reviews on one prompt produce two reviewers approving two candidates for a
single released pointer, and whichever is released second silently wins. The reviewer cannot see the
race from the review screen. One queue per prompt makes the conflict a decision at submit time, when the
person who caused it is present, instead of a surprise at release time.

**Impact if wrong**: A uniqueness constraint and a supersession rule to remove, plus a review queue that
must then show which candidate is newer. Moderate rather than cheap because stored `superseded` tasks
would need reinterpreting.
