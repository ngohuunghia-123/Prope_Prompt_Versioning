# A-161 - Integration is a migration, and the SDK plus the skill are how it is paid for

**Statement**: Prope does not attempt to be adoptable without a code change. The integration path is a
first-class SDK (ADR-0065) plus an agent-assisted migration of the customer's own repository
(ADR-0066). The forwarding mode built under ADR-0059 stops being the adoption story and becomes the
migration audit (ADR-0064).

**Rationale**: an observation delivers none of the four non-negotiables. It has no approval, no
revision, nothing editable, and the prompt still ships from the customer's repository - so the on-ramp
was being optimised while the destination stayed unreachable. The ask was also the market's most
expensive rather than its cheapest: forwarding requires a stored, decryptable provider credential and a
position in front of production traffic, where PromptLayer asks for one asynchronous instrumentation
call and Langfuse publicly argues against proxies at all.

The reversal is affordable because the expensive half is already built. Prope's inventory machinery -
fingerprint grouping, timestamp masking, variable inference, adopt-into-a-real-revision - is the thing
no comparable ships, and it keeps every line of code under the new reading.

**Impact if wrong**: if customers will not run the skill and will not let Prope integrate for them,
Prope has no adoption path at all and the answer is [[OQ-151]] - become an OpenTelemetry backend and
compete as an observability product with a governance story. That is a strategy change rather than a
code change, which is why this is marked expensive.
