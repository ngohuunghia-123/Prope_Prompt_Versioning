# A-018 — Vietnamese UI copy, English status labels and API vocabulary — behind an i18n layer

**CONFIRMED AND EXTENDED BY THE USER 2026-08-09** (OQ-010 resolved). The copy decision stands exactly
as written below. What the answer added is structural and is recorded as **ADR-0053**: every
user-facing string comes from a keyed message catalogue from day one, `vi` is the only catalogue that
ships, and the API keeps returning a machine `code` the client translates rather than a translated
`message`. See also [[A-150]], which handles the consequence for registry search that this decision
created.

**Statement**: Interface copy is in Vietnamese. The five statuses (Draft, In review, Approved, In
use, Retired), the API field names, and the technical vocabulary (`version_id`, `rollback`) stay in
English. Brainstorm and specification artefacts under `docs/brainstorm/` are written in English.

**Rationale**: The team's own documents (`BRIEF.md`, `positioning.md`, `business-analysis.md`) and
the demo audience are Vietnamese, while `prope_source_of_truth.md` §18 rule 9 requires statuses to
stay literal and defines the whole language system in English. Keeping the artefacts in English
matches the source of truth, which declares itself the canonical context for agents.

**Impact if wrong**: A copy pass.
