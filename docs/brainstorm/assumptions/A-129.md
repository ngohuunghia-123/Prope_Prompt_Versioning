# A-129 — Caddy is the single ingress and terminates TLS

**Statement**: Exactly one process is reachable from outside the VM: Caddy. It terminates TLS, serves
static assets, and reverse-proxies everything else to the FastAPI application. No other container
publishes a port to the host — PostgreSQL, RabbitMQ, Prometheus and Grafana are reachable only on the
compose network.

**Rationale**: TLS is not optional and is not a consequence of any UI decision. A consumer API key
travels in an `Authorization` header on every gateway call (A-113), and the constraints table treats
credentials as secrets throughout; serving `POST /v1/chat/completions` over plaintext would put a
bearer secret on the wire on every request. Caddy is chosen over nginx for one reason that matters at
this scale — automatic certificate issuance and renewal, so TLS is not a recurring manual task for a
team A-012 describes as having no dedicated operations capacity.

Making it the *single* ingress is the second half. RabbitMQ's management UI, Prometheus and Grafana all
want a port, and each published port is a separately authenticated surface on a host holding workspace
provider credentials. Reaching them over an SSH tunnel instead costs an operator thirty seconds and
removes three internet-facing services.

**Impact if wrong**: Caddy is replaceable by nginx or Traefik with a configuration rewrite and no
application change. The single-ingress property is the part worth keeping — losing it is how a
management UI ends up on the public internet without anyone deciding it should be.
