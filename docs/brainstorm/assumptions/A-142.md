# A-142 — Global interface conventions: what an in-process seam means, how a failure crosses one, and the one broker envelope

**Statement**: Every interface in `docs/architecture/interfaces.md` inherits the conventions below.
They are decided once here so thirty blocks cite a line instead of inventing thirty dialects. This
assumption **adds to** [[A-045]] and ADR-0003 rather than restating them — ids, the error envelope,
cursor pagination, `/healthz` + `/readyz`, RFC 3339 timestamps ([[A-003]]) and not-found-never-forbidden
([[A-116]]) are already settled there and are not re-decided.

## 1. What "in-process call" means

**A Python function call inside whichever container the caller is running in.** Both `app` and `worker`
run the *same image* with a different command (ADR-0026, ADR-0028, ADR-0033), so every module's code is
present in both processes. Twenty of Prope's thirty seams are in-process, and **none of them is remote**:
there is no HTTP hop, no serialization, no partial failure, and no timeout between two Prope modules.

The consequence worth stating, because it is the thing an implementing agent gets wrong: *the same seam
runs in two processes.* `provider-access.dispatch()` is called by the gateway in `app` and by
evaluation's executor in `worker`; both are local calls, and any per-process state behind the seam
(a cache, a semaphore, a rate limiter) exists **twice**. That is already recorded for the credential
cache ([[A-092]]), the resolution cache (ADR-0012), the login limiter ([[A-130]]) and the admission
semaphore (ADR-0046). It is a property of the deployment, not of any one module.

## 2. How a failure crosses an in-process seam

**The default is: it raises, and the caller does not catch it.** A raised exception reaches the
module's own edge and becomes a 5xx in the [[A-045]] envelope. This is what makes "fails closed" true
for the permission oracle without any code that says so — an unavailable `may()` cannot become an allow
if nobody is catching it.

Exactly **four seams deviate**, and each deviation is a recorded decision rather than a style:

| Seam | Behaviour | Why |
|---|---|---|
| `check_spend_ceiling()` (INT-020) | **Fails OPEN** — returns `allowed: true` and counts it | Guards an optional, off-by-default feature; blocking a reviewer over a billing lookup is the worse trade ([[A-104]]) |
| `enqueue()` (INT-018) | **Never raises into the caller**, ever | It runs after the response is flushed; raising there is a log line at best and a crashed request task at worst ([[A-037]], [[A-087]]) |
| `dispatch()` (INT-015) | Returns a **typed `DispatchError`** for upstream failure | An upstream failure is data the caller must branch on — the gateway serves a fallback, evaluation records a run error. It is not exceptional (ADR-0017) |
| `get_model_catalogue()` (INT-016) | **Soft** — an unavailable catalogue degrades the picker, never refuses a save | [[A-091]]; it is a validation aid, not a gate |

Everything else raises. `append()` raising is load-bearing rather than incidental: it fails the
caller's transaction, which is the entire mechanism behind *no state change without a trail*
(ADR-0023, ADR-0024).

## 3. Timeouts

**No in-process seam carries a timeout**, because none of them can hang on anything but the shared
database connection, which has its own. The single exception is `dispatch()`, which takes an explicit
`deadline_ms` from its caller because it is the only seam that reaches the internet (INT-023).

## 4. Versioning

- **Internal seams are versioned by the commit.** Every module ships in one image from one repository;
  a signature change and its callers land in the same build. Their `Version` column reads `in-repo` and
  that is not a placeholder — a version number on a seam that cannot skew is a number nobody maintains.
- **`/api/v1` is frozen for the MVP.** Its only client is the SPA, which ships from the same commit
  (ADR-0052). Backward compatibility is not owed *within* a deploy; [[A-141]] owns the one case where a
  client outlives its server, and answers it with a banner rather than a version gate. A `v2` prefix
  appears when a client outside this repository exists, and not before.
- **`/v1` on the gateway is not ours to version.** It is OpenAI's wire shape, pinned by
  `00_context.md#constraints` (INT-022, ADR-0050).
- **The broker envelope carries `schema_version`** and evolves **additively only**: a field may be
  added, and a consumer ignores fields it does not know. A field is never removed, renamed, or retyped
  in place — a redelivery from before a deploy must still parse after it.

## 5. The broker envelope, and the fact that there is one queue

`prope.call_record` is the **only** queue in Prope. ADR-0028 was argued over three asynchronous
workloads; two of them subsequently chose something else on their own merits — evaluation takes a table
claim (ADR-0049) and release-control's sweep is a timer (ADR-0051) — so the broker ended the stack pass
carrying one workload. That is worth knowing before someone adds the second.

Message envelope, on top of the call-record payload:

```
schema_version   integer, starts at 1
call_id          the CALLER's ULID, generated at request time (A-099) — the idempotency key
workspace_id     the tenant, so the drain can group a batch (ADR-0040)
occurred_at      RFC 3339 UTC (A-003)
producer         "gateway" — source=gateway | eval on the payload is a different field (A-098)
```

- **Delivery is at-least-once.** Durable queue, persistent messages, publisher confirms (ADR-0028).
- **Consumers must be idempotent on `call_id`.** The drain's upsert absorbs both duplicate shapes
  ADR-0041 creates ([[A-099]]).
- **DLQ naming is `<queue>.dlq`** — so `prope.call_record.dlq`. One per work queue, configured from the
  start (ADR-0028).

## 6. Correlation

`X-Request-Id` is accepted on every inbound HTTP request and generated when absent. It is echoed in the
[[A-045]] error envelope's `request_id`, bound into the `structlog` context for the life of the request
(ADR-0030), and carried on the broker envelope's payload. It is **never a metric label** — ADR-0030's
cardinality rule is unconditional and a request id is the worst possible label.

## 7. Idempotency on the management API

**No `Idempotency-Key` header, deliberately.** The two writes where a duplicate would change an outcome
already carry their own guard, chosen for their own reasons: `expected_current_version_id` on a release
is a compare-and-set ([[A-072]]), and the call record upserts on `call_id` ([[A-099]]). A duplicate
revision — the realistic double-submit — is immutable, visible in the revision list, carries its own
required change summary, and changes nothing about what is released. Adding a key store to prevent a
harmless row is a component with a lifecycle, against [[A-012]].

## 8. Authentication, by seam class

| Class | Mechanism |
|---|---|
| Management API (INT-024…INT-029) | Server-side session row via `HttpOnly` `Secure` `SameSite=Lax` same-origin cookie (ADR-0029, ADR-0052). No JWT, no CORS, no CSRF token |
| Gateway (INT-022) | Consumer API key in `Authorization`, hashed at rest, verified in constant time (ADR-0021, [[A-113]]) |
| In-process (INT-001…INT-021) | **None.** The caller authenticated at its own edge. `dispatch()` is deliberately not re-checked — a second check on the hot path is a second thing that can disagree with the first |
| Egress (INT-023) | The workspace's own credential, decrypted only in provider-access (ADR-0014) |

**Rationale**: these are the fields that would otherwise be answered thirty times, and the answers are
already implied by decisions the build has made — they were just never collected in one place where a
seam block could cite them.

**Impact if wrong**: sections 1–4 and 6–8 are edits. Section 5 is the only one with a migration cost:
the envelope's field names are on the wire between two processes, so changing one after real traffic
exists means draining a queue before a deploy, which is the failure mode the additive-only rule exists
to avoid.

Related: [[A-045]] and ADR-0003 for the management-API conventions this builds on · [[A-141]] for the
one place a client and a server can disagree · [[A-099]] for the idempotency key everything here leans on.
