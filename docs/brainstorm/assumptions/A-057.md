# A-057 — A dispatch failure is `outcome: error`, never `fail`, and any error withholds the cost delta

**Statement**: `case_result.outcome` has three values, not two: `pass`, `fail`, `error`. An assertion
that evaluated to false is `fail`. A case whose dispatch never produced a response — timeout, 429 after
retries, 5xx, malformed body — is `error`, carries an `error_code`, and is excluded from the pass rate.
If any case in either the candidate or the baseline run ended in `error`, the cost delta is **withheld**
with the reason stated, rather than computed over the cases that happened to succeed.

**Rationale**: A failure is evidence about the prompt; an error is evidence about the network. Merging
them makes a rate-limited key look like a bad revision, and the reviewer's only defence against that is
noticing the pattern by eye. The withheld delta follows from A-006: the unit is *one full suite run* on
each side, and a delta computed over 17 of 20 cases on one side and 20 on the other is not that unit —
it is a smaller number that looks like a saving. Better a blank with a reason than a plausible wrong
figure above a decision button.

**Impact if wrong**: A three-valued enum and one guard on the delta. Showing a partial delta later means
adding a clearly-labelled partial mode, not changing the model.
