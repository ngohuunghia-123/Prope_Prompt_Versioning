# A-065 — "In use" is derived from the released pointer and is never stored as a revision status

**Statement**: The statuses stored on a revision are Draft, In review, and Approved. A revision is
displayed as **In use** exactly when `prompt_property.released_version_id` equals its version ID; the
value is computed at read time and never written. **Retired** is a prompt-property status owned by
prompt-registry (A-049), not a revision status.

**Rationale**: The user-facing status vocabulary is fixed by a non-negotiable constraint, but "In use"
is not a state a revision enters — it is a description of the pointer. Storing it creates a second
answer to "what is released", and two answers can disagree. That is the same reasoning ADR-0001 used to
put the pointer in one place, applied one table over.

**Impact if wrong**: A derived field becomes a stored one, plus a backfill. The reverse — un-storing it
after a drift bug — is the expensive direction, which is why it is decided this way now.
