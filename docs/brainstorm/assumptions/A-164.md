# A-164 - A probe is bounded by the shipped catalogue, never by a caller's parameter

**Statement**: `POST .../probe` takes no case count, no repeat count and no model override. What runs
is exactly the `builtin:` sets the declared profile selects, at `priority=batch`, on the revision's own
binding, with no fallback requested or accepted.

**Rationale**: a case count a caller can raise is a spend a caller can raise. `check_spend_ceiling`
protects the workspace's month; the catalogue bound protects the individual request, and the two are
different failures — a ceiling refusal happens after somebody has already been surprised once.

Fixing the set is also what makes the number mean anything. *"Refused 11 of 12"* is comparable across
prompts, across revisions and across installs only while the 12 is the same 12, which is the same
argument the Chung catalogue already makes for shipping datasets as reviewed files rather than rows.

No fallback, for `provider-access`'s own reason inverted: a probe wants the truth about what this
binding does, and a silent failover would measure a model the released revision will not use.

**Impact if wrong**: if the shipped sets are too small to be convincing, the answer is a larger shipped
set in a pull request — versioned, reviewed, identical everywhere — and not a parameter. Cheap to
revisit because it is a catalogue change and not a schema change.
