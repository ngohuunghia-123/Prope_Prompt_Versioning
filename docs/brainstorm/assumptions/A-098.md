# A-098 — One call_record table with source = gateway | eval; bodies only for gateway

**Statement**: Gateway calls and eval-case dispatches are rows in one `call_record` table,
distinguished by `source`. For `source = eval`, `run_id` and `case_id` are set, `consumer_key_id` is
null, and no `call_body` row is ever created (A-055). For `source = gateway`, `version_id` is NOT
NULL, enforced by a database constraint.

**Rationale**: Both spend the same workspace's money on the same credential, so a spend ceiling that
counted only one of them would be wrong in the direction that matters — a ceiling exists to catch a
runaway eval loop, and gateway traffic is what pushes a workspace close to it first. One table means
one price path, one monthly total, and one answer to "what did this workspace spend".

Bodies are the asymmetry, and it is A-055's: an eval case's output belongs on `case_result`, where a
reviewer reads it side by side with the baseline's, and duplicating it into the body store would put
the same content under two different retention policies.

**Impact if wrong**: Splitting the table later is a migration, which is why it is moderate. The
alternative — two tables from the start — would have needed a union in every place spend is computed,
and the union is where a source gets forgotten.
