# A-032 — The fallback answer is a field on the revision, reviewed and approved with it

**Statement**: The fallback answer lives on the revision alongside the prompt body and the model
binding. Editing it creates a new revision and goes through the same review and release path.
Reviewing a revision means reviewing its fallback answer too, and the review screen shows it.

**Rationale**: A fallback answer is text that reaches an end user under the product's name — it is
production content, not configuration. BR-06 requires every change to produce an immutable revision,
and BR-02 requires every production prompt to resolve to an owner, a revision, and an approval
record. A fallback editable outside the revision would be the one string in the system that reaches
users without an approval, which defeats the point of the gate.

**Impact if wrong**: Moving it to a prompt-level field is a schema change and the loss of the
approval guarantee on that field.
