# A-108 — People sign in with email and password against Prope's own user table; no SSO in the MVP

**Confirmed by the user 2026-08-09 (step 4), and promoted from `agent` to `human`.** This assumption
flagged itself below as *"the default most worth overturning early"*; it was put to the user during the
step-4 global baseline and kept. ADR-0029 records the decision, the rejected alternatives, and the one
mechanical requirement any future federated option must respect: **Prope still mints a local session
after the callback**, because a self-contained token is a cached authorisation decision and ADR-0022
forbids caching authorisation. `module_map.md` named this as the sole reason access-control scored
`Estimable: no`; that reason is now closed, and OQ-006 narrows to data classification alone.

**Statement**: A human actor authenticates with an email address and a password stored as an argon2id
hash, and receives a **server-side session** row referenced by an HTTP-only cookie. There is no OIDC,
no SAML, no Google or Microsoft sign-in, and no magic link. `user` and `session` are access-control's
tables.

**Rationale**: A-012 caps the system at one `docker-compose up` with no component that needs its own
runbook, and OQ-011 has not established that the demo runs anywhere but a laptop. An identity provider
is an external dependency, a client registration someone has to obtain, and a redirect flow that breaks
differently in every environment — none of which follows from anything in the source documents. A magic
link is ruled out by A-071's decision that no email ships in the MVP.

Server-side sessions rather than self-contained tokens because ADR-0022 makes immediate revocation a
property of this module, and a stateless token is a cached decision with no way to invalidate it.

**Impact if wrong**: Adding OIDC later is additive — a second credential type against the same `user`
row, and the session and permission machinery is unchanged. What is not free is the reverse: if the
group requires SSO from day one for the pilot, local passwords become an account-management surface
nobody wanted. **This is the default most worth overturning early**, because the cost of the answer
arriving late is larger than the cost of either answer.
