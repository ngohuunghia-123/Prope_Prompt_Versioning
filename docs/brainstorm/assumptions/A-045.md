# A-045 — Global management-API conventions: ULID ids, one error envelope, cursor pagination, /healthz and /readyz

**Statement**: Identifiers are ULIDs with typed prefixes (`prm_`, `rev_`, `rel_`, `evr_`, `usr_`,
`prv_`); the management API returns one error envelope `{error: {code, message, details?, request_id}}`;
lists are cursor-paginated (`limit` default 50, max 200); every service exposes `/healthz` and
`/readyz`; a subject the actor may not see returns not-found, never forbidden. The gateway is exempt
from the error envelope and returns OpenAI-shaped errors (A-026). Full reasoning and rejected
alternatives in ADR-0003.

**Rationale**: These are the fields that repeat in every lock file. Deciding them once means seven more
modules cite a line instead of inventing a dialect; deciding them per module means eight dialects and
the same question asked eight times.

**Impact if wrong**: The envelope, pagination, and health endpoints are edits. The id format is a
migration once data exists, which is why it carries an ADR.
