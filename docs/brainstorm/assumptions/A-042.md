# A-042 — Evaluation never calls release-control; release-control reads run state when it renders

**Statement**: Submitting a revision for review may start an eval run. A finished run notifies nobody.
The review screen reads the latest run summary for the candidate revision when it is opened, and shows
`running`, `passed`, `failed`, or `error` from that read. The dependency runs one way:
`release-control → evaluation`.

**Rationale**: The natural design — submit triggers a run, the run reports back — is a cycle between two
feature modules, and cycles between feature modules are the ones that make parallel work collide. Pull
also fails better: if the runner dies, the review screen says the run has not finished, instead of
waiting forever for a callback that is not coming. The eval suite is 10–20 cases in under 120 s
(`00_context.md` Success), so polling costs a reviewer nothing.

**Impact if wrong**: Adding an event or a websocket later is additive and touches one screen.
