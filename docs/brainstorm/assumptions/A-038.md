# A-038 — Streaming responses are accumulated and logged after the stream closes

**Statement**: For a streaming call the gateway relays chunks to the caller as they arrive and
accumulates a copy. The call record is written once the stream closes. If the client disconnects
early, the partial body is written with `outcome = truncated`. Accumulation never delays a chunk.

**Rationale**: Streaming is the case where "log after" is easiest to get wrong — buffering the whole
response before relaying it would destroy the streaming behaviour the OpenAI compatibility exists to
provide, and the user's instruction is explicit that latency comes first. Logging truncation rather
than discarding it keeps the token and cost figures honest, since the upstream provider still
charged for what it generated.

**Impact if wrong**: A change in the writer's assembly step.
