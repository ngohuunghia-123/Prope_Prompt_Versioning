# A-109 — The `workspace` table belongs to access-control; it is the tenancy root

**Statement**: `workspace` — id, name, slug, created_by, created_at — is owned by **access-control**.
Every workspace-scoped table in every other module carries a `workspace_id` that refers to it as a
value, and access-control is the only module that writes it.

**Rationale**: `workspace_id` appears on almost every table in the map — `prompt_property`,
`eval_suite`, `provider_config`, `call_record`, `workspace_spend`, `spend_ceiling` — and the bounded
contexts table assigned nobody the row it points at. An unowned table is how two writers appear later;
A-081 caught the same gap for `api_key` while locking the gateway, and this is the second instance of
the same pattern.

Access-control is the right owner rather than merely an available one: *workspace* is already in its
ubiquitous language, membership is the only thing that makes a workspace mean anything, and creating one
necessarily creates its first role binding (A-117). Any other owner would have to call access-control to
finish the job.

**Impact if wrong**: A table moves. Nothing joins across it today, because no module may join across
module tables in the first place.
