# A-091 — The model catalogue is discovered from the provider, refreshable, manually extensible, and holds no prices

**Statement**: When a configuration is verified, provider-access reads the provider's own model list
and stores it as `model_catalogue` rows. It can be refreshed on demand. A model the endpoint omits
can be added manually (`source: manual`). A model that disappears from the list is marked
`available: false` rather than deleted. The catalogue holds identifiers and capability flags —
never a price, a rate, or any cost column.

**Rationale**: Hand-entering model names produces typos that surface as a 404 from the provider on a
production call, and the provider already publishes the authoritative list. Manual entry stays because
provider model lists are routinely incomplete — fine-tuned deployments and Azure deployment names are
the common cases. Marking rather than deleting keeps a revision bound to a retired model explicable:
"the provider no longer serves this" is a better answer than a dangling reference.

Prices are excluded because Call Ledger owns money (A-030, A-056), and a cost column here would be a
second place to look for a number that must be effective-dated to stay reproducible.

**Impact if wrong**: A refresh schedule or a paging strategy is additive. The part worth keeping under
any answer is that the catalogue is a cache of the provider's truth, not a hand-maintained list.
