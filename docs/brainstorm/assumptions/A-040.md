# A-040 — Placeholder retention: bodies 30 days, metadata indefinite, bodies readable by the prompt's owner only

**Statement**: Until OQ-013 is answered, request and response bodies are deleted 30 days after they
are written; call-record metadata is kept indefinitely; and reading a body requires being the
prompt's owner or holding an explicit `read_bodies` permission. Deletion is a real delete, not a flag.

**Rationale**: A placeholder is needed so the schema has a retention column and the deletion job
exists from day one — retrofitting deletion onto a store that never had it is how retention policies
end up unenforceable. 30 days is short enough to bound the liability and long enough to be useful for
the later divergence-review screen. The narrower read permission exists because a body may contain a
third team's customer data that the prompt's owner has no standing to read.

**Impact if wrong**: A configuration value and a permission check. The part that would be expensive
is not having built deletion at all, which this assumption prevents.
