# A-077 — The caller supplies the conversation; the system prompt is the released revision's

**Statement**: The revision's body is the system message and it is always first and always alone. The
caller's `messages` array supplies `user`, `assistant`, and `tool` turns. A message with role `system`
is refused with an OpenAI-shaped `400` naming the model name, with no upstream dispatch. The same rule
applies to any generation parameter the revision owns (A-024): the caller cannot override the
provider, the model, or the parameters.

**Rationale**: Prope's claim to the Developer persona is that the text running in production is the
revision that was diffed, evaluated, and approved. If a caller can contribute system text, the text in
production is a concatenation nobody reviewed, and every eval result describes a different prompt from
the one that runs. Refusing is loud and fixable in one line by the consumer; appending or silently
dropping fails invisibly, for as long as nobody looks. Full reasoning and the four rejected shapes in
ADR-0011.

**Impact if wrong**: Allowing an appended system message later is additive and would need a field on
the revision saying whether that prompt permits it, plus a marker on the call record. Retrofitting the
governance claim after a year of concatenated traffic is not.
