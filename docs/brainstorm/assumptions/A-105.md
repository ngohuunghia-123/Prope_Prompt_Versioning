# A-105 — Stored bodies have no read path in the MVP

**Statement**: Request and response bodies are written to `call_body` and deleted at retention.
Nothing reads them: no endpoint, no export, no admin viewer, no debug route, and no join from another
module's query. The absence is asserted as a test against the route table itself, so a new endpoint
cannot quietly add one. Full reasoning and rejected alternatives in ADR-0018.

**Rationale**: call-ledger has no outbound dependencies by design (`call-ledger → anything` is a
forbidden edge), which means it cannot ask access-control anything, which means it cannot check a
permission — so it must expose nothing that needs one. A body-read API is exactly the thing that
would.

This is also the cheapest possible position from which to answer OQ-013's access half. With no
reader, "who may read a body" is a question about a surface that does not exist yet, so the answer
becomes the design of a new feature rather than a retrofit onto one already in use. Building the
viewer now would turn a question that blocks the pilot into one that blocks the build.

Nothing is lost: `00_context.md#scope` already puts trace explorers and analytics dashboards out of
scope, and A-039 makes Langfuse an export target for later — an export is a reader, and it inherits
this decision.

**Impact if wrong**: Building the reader is additive. A-040's `read_bodies` permission is deferred,
not deleted, and remains the right shape when it arrives.
