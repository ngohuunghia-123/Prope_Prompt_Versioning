# A-046 — Global observability conventions: structured logs, prope_<module>_<name>_<unit> metrics, bodies never logged

**Statement**: Logs are structured JSON with a fixed base field set (`ts`, `level`, `request_id`,
`actor_id`, `workspace_id`, `module`, `action`, `outcome`, `duration_ms`). Metrics are named
`prope_<module>_<name>_<unit>`. Prompt bodies, fallback answers, request and response bodies, and
provider credentials never appear in a log line, a metric label, or a history event — the only place a
body is ever written is the Call Ledger's body store, under OQ-013's policy.

**Rationale**: `00_context.md` makes credential redaction a non-negotiable constraint, and the whole
call-body question is Critical and unresolved; a body that leaks into application logs escapes whatever
retention policy OQ-013 eventually sets, because logs are not the store that policy governs. Naming is
decided rather than asked because it is not user-visible.

**Impact if wrong**: Renaming metrics and adding fields is an edit. The no-bodies-in-logs rule is the
part worth keeping regardless of backend.
