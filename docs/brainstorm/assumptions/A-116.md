# A-116 — Not-found when the actor cannot see the subject; forbidden naming the permission when they can

**Statement**: A refusal takes one of two shapes. If the actor may not see the subject at all, the
response is **not-found**, identical to the response for an id that does not exist. If the actor may see
the subject but not perform the action, the response is **forbidden**, and it names the missing
permission. The gateway is the exception in one direction only: a scope refusal there returns the same
not-found shape as an unknown model name, always, because a consumer key must not be able to enumerate
the registry (A-081).

**Rationale**: This refines A-045, whose blanket "a subject the actor may not see returns not-found,
never forbidden" is scoped to visibility and says nothing about the other case — and release-control's
lock already promises the other case in writing, refusing "naming the release permission". Both are
right; they answer different questions, and leaving that implicit is how one of them gets implemented as
the other.

The split is the useful one. Not-found is what stops an existence oracle: BR-01 makes prompts private by
default, and a forbidden response on a private prompt tells you it exists, which is the leak the
constraint exists to prevent. Once someone can already see the prompt, hiding *why* they cannot act on it
protects nothing and produces the worst support conversation in the product — a button that does nothing
with no way to find out what to ask for.

**Impact if wrong**: An error-shape change in one place, because both shapes come out of one envelope
(A-045, ADR-0003).
