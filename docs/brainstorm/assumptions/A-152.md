# A-152 — Canary is a temporary second resolution target

An Approved candidate may receive 5–50% of eligible production conversations while the existing released revision remains baseline. Assignment is a stable hash of workspace, prompt and caller-supplied `conversation_id`; calls without that identifier always use baseline. Promotion remains a recorded human release decision and stopping the canary restores 100% baseline traffic.

This intentionally supersedes the earlier single-pointer-only product assumption for an active canary window. Call records continue to carry the version actually served, so comparison uses ledger facts rather than inferred allocation.
