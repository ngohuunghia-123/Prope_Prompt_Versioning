# A-055 — Eval dispatch submits usage for pricing only; outputs live in `case_result`, never in `call_body`

**Statement**: An eval case's dispatch does not create a gateway-style call record. Evaluation sends
call-ledger the usage rows for a run — input tokens, output tokens, model, timestamp, tagged
`source: eval` — and receives priced totals back. The model's output text is stored once, on
`case_result`, because the reviewer needs to read old and new side by side (A-005).

**Rationale**: The module map assigns Call Ledger the job of pricing what evaluation submits, not of
logging what evaluation ran. Writing the output into `call_body` as well would put the same text in two
tables with two retention policies and two access rules, and OQ-013's answer would then have to be
applied twice and could be applied inconsistently. One body, one home, one policy. Tagging the usage
`source: eval` still lets a workspace see its full spend without duplicating content.

**Impact if wrong**: A tag and an insert. If eval calls later need to appear in the call-record view,
the metadata is already in the ledger; only the join changes.
