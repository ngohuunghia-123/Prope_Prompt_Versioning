# A-163 - The Usage Profile is declared by a person and never inferred

**Statement**: the four axes a readiness finding is filtered by — `audience`, `untrusted_input`,
`acts`, `sensitivity` — are set by a person on `registry.prompt_property` and read by
`prompt-readiness`. No model, no heuristic and no traffic analysis may write or guess any of them.
An undeclared profile reads as the conservative worst case (`public / third_party / irreversible /
personal_data`) behind a visible *undeclared — assuming worst case* badge.

**Rationale**: the profile is the input every rule in the module reads, so a wrong value is not one
wrong finding — it is a wrong card. A model guessing that a prompt is customer-facing and then
lecturing about it is exactly the false positive the module exists to avoid, which makes inference the
bug rather than the feature.

The conservative default is what makes the declaration cheap to skip and still safe. A default plus a
one-dropdown correction is a trade a person makes gladly: the correction is made once and permanently
silences a class of finding. **A guess has to be argued with every time**, and the arguing is what
turns a panel into wallpaper.

**Impact if wrong**: if nobody declares, every prompt is judged as public and the card is noisy — which
is uncomfortable but safe, and measurable directly through
`prope_readiness_findings_suppressed_total`. If that counter sits near zero, the profile is decoration
and the migration that added the columns was not earned. Reversing the other way — adding inference —
is expensive rather than cheap, because every finding recorded under an inferred profile has an
admitting clause nobody signed.
