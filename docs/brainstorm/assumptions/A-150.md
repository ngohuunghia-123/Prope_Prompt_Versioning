# A-150 — Registry search folds diacritics, in the trigger, not in the index expression

**Statement**: `prompt_property.search_text` is written by its trigger as **unaccented, case-folded
text**, and a search term is unaccented and case-folded the same way before the trigram match runs.
The stored `purpose`, `title` and revision body are untouched — only the derived search column is
folded. The `unaccent` extension is created by `prope_migrate` as part of the migration that creates
the column.

## Why this exists

ADR-0053 answered OQ-010: the product ships in Vietnamese. ADR-0048 chose a trigram index over a
trigger-maintained document column, and it was decided before anything had established what language
the indexed text would be in. That is the pattern this pack keeps finding — **a decision resting on a
premise a later decision removed** — and here the premise is silent rather than stated, which makes it
the harder kind to notice.

Concretely: a user searching `tieu de` does not find `tiêu đề`, and a user searching `TIÊU ĐỀ` does not
find `tiêu đề` unless the fold is applied on both sides. Vietnamese has six tone marks over a
seven-vowel base, so the number of ways to type a word without its diacritics is not a corner case —
it is how people type when they are in a hurry, which is the state a person is in when they are
searching for a prompt.

## Why in the trigger and not in the index

`unaccent()` is **STABLE, not IMMUTABLE** — it depends on a dictionary that a superuser can change —
so PostgreSQL refuses it directly in an index expression, and the usual workaround is an `IMMUTABLE`
wrapper function that lies about that dependency. ADR-0048 already maintains the column by trigger, so
the fold belongs where the column is written: no wrapper, no lie, no fifth `SECURITY DEFINER`-shaped
object to explain. The trigram index is then an ordinary index over an ordinary column.

The cost is that changing the fold requires rewriting the column, which is one `UPDATE` over one table
in a single-instance database — the same cost ADR-0048 already accepted for any change to the document
composition.

**Impact if wrong**: search recall on accented text, correctable by rewriting one derived column.
Nothing reads `search_text` except the search query, and it must never appear in an API response —
that constraint is unchanged and is asserted by prompt-registry's T-017 test.
