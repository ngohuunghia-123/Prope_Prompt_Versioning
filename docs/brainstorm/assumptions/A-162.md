# A-162 - An open observation is work outstanding, and an empty inbox is the success condition

**Statement**: under ADR-0064 the observation inbox is a punch list produced by auditing a migrated
application. Rows mean *the migration missed this*; zero open rows is the state a migrated workspace
drives toward. `adopt` is the corrective action and `dismiss` is a legitimate, common resolution rather
than an exception.

**Rationale**: this inverts ADR-0059's reading, where rows were the product working and more was
better. The schema does not change - `adopted_at` and `dismissed_at` are still the two facts - but
every surface that renders a count has to mean the opposite thing by it, and an empty state that reads
*no observations yet* is correct under the old reading and actively misleading under this one.

Naming it as an assumption rather than leaving it inside the ADR is deliberate: it is the sentence a UI
author needs and the least likely to be re-read from a decision record.

**Impact if wrong**: if audits routinely produce large, permanently open inboxes, the punch-list
framing is wrong and the inbox is an inventory after all - in which case the honest response is to
revisit [[A-161]] rather than to add bulk actions, because a bulk-adopt button recreates the read-only
room at a different address.
