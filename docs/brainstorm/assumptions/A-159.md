# A-159 — Accepted: a leaked key can enumerate a workspace's namespaces, and still not its prompt names

**Statement**: under [[A-156]], an observe-enabled key learns which namespaces a workspace uses, by
observing which model strings are forwarded and which are refused. A string in a used namespace is
refused; a string in an unused one is forwarded. That difference is observable and it is accepted.

**What is not disclosed, and this is the line**: nothing about *names*. `finance/pricing` and
`finance/nothing` are both refused, byte-identically, whether the first exists or not. [[A-116]]'s
property — *a scope refusal returns the same not-found shape as an unknown model name, so a leaked key
cannot enumerate the registry* — holds inside a namespace, unchanged, which is where the registry
actually is.

**Rationale**: the weakening is what buys the feature, so it is priced rather than waved through.

*The unit disclosed is coarse and low-cardinality.* A workspace has folders, not thousands of them, and
they are named for teams and products — `support`, `checkout`, `marketing`. The prompts inside them are
the asset.

*The key already implies most of it.* Under [[A-158]] a key carries `scope_namespaces`, so its holder
was told some namespaces by being issued the key at all. The residual disclosure is the namespaces it
was **not** given, which is a smaller set than the one it holds.

*Each probe costs the attacker a provider call in the victim's account* — forwarding is the disclosing
answer, so enumeration is not free and it is not silent. It appears in `prope_gateway_observed_call_total`,
in the workspace's spend total under `source = observed`, and as observation rows nobody adopted. This
is the rare disclosure channel that is also an alarm.

*The alternative leaks worse.* Deciding per name rather than per namespace discloses which individual
prompts exist, which is the thing A-116 was written for. ADR-0062 rejects it for exactly this.

**The case this does not cover**, named because acceptance without its boundary is not acceptance: a
workspace whose *namespace names themselves* are sensitive — a folder per customer, a folder per
unannounced product. There, the coarse unit is the secret. Nothing in this design detects that, and the
mitigation available today is that observe is off by default and per key ([[A-152]]), so a workspace in
that position simply does not enable it. If that becomes common, the answer is an allow-list of
namespaces a key may be told about, which is additive.

**Impact if wrong**: the mode is a nullable column per key. Turning it off is one `UPDATE`, effective on
the next request with no TTL to wait out (ADR-0022).
