# A-061 — Assertions are an extensible registry keyed by the suite's declared output modality

**Statement**: `eval_suite` carries `output_modality`. Each assertion type is registered against one or
more modalities; the authoring UI offers only the types valid for the suite's modality, and a run
refuses to start when the suite's modality does not match the shape the target actually returned.

Registered at MVP: `text` (the eight deterministic types in A-005), and `structured` — a response whose
content is JSON or a reference such as an asset URL, asserted on shape and presence: JSON-schema
validity, required key, forbidden key, value equality at a path, a URL resolving to a fetchable asset of
a stated content type, asset count, latency, cost. Adding a modality means registering assertion types
against a new key, not altering the run model, the comparison, or the review summary.

**Rationale**: Prope routes to *any* OpenAI-compatible target, including agents that create images or
return structured data (user — 2026-08-08). The transport stays chat-completions and the gateway's
surface does not widen (A-026), but the `content` coming back is no longer assumed to be prose. The eight
types in A-005 are all string operations, and hardcoding them as *the* assertion set would bake "the
output is prose" into `case_result`, the authoring UI, and the evaluators — three places that would each
need finding later. The mismatch check exists because the failure it prevents is silent: text assertions
run against a URL would all fail, and a reviewer would read that as a bad prompt.

The honest limit, stated rather than engineered around: for a target that creates an asset, a
deterministic assertion can only reach the *structure* of the response — that an asset came back, how
many, of what type, how fast, at what cost. Whether the image is any good is exactly the subjective
judgment A-005 refuses to score; it goes side by side for a human, which for this modality means the old
asset next to the new one.

**Impact if wrong**: One column and a lookup table.
