# A-082 — `GET /v1/models` lists only prompts with a current release that the key may resolve

**Statement**: The list contains a prompt property only if it has a current released revision **and**
the calling key's scope permits it (A-081). Each entry uses the OpenAI model shape with `id` equal to
the model name. Prompts with no release, retired prompts, and prompts outside the key's scope are
absent — not present-and-flagged.

**Rationale**: `GET /v1/models` is what most OpenAI clients call to validate configuration (A-026), so
its job is to answer "what can I call right now". A name in that list that then returns model-not-found
is a lie told by the endpoint whose whole purpose is configuration validation, and it would send a
developer to debug their client. Filtering by key scope as well as by release keeps the endpoint from
becoming a registry enumeration tool for a leaked key, which is the same reason a scope refusal returns
not-found rather than forbidden.

**Impact if wrong**: A filter clause and, if unreleased prompts should be discoverable later, an
additional field. Additive either way.
