# A-127 — LangChain and LangGraph are removed; nothing in Prope is a graph

**Statement**: `langchain`, `langchain-openai` and `langgraph` are removed from the dependency set,
along with the boilerplate `src/agents/` tree they support. Prope makes upstream model calls with a
plain HTTP client against a configurable base URL.

**Rationale**: The inherited stack row in `00_context.md#constraints` names LangGraph, but it arrived
with the prototype template rather than from the problem — the repository uses it only in
`src/agents/graph.py`, a boilerplate example node and example tool wired to nothing. Nothing in
`00_context.md#scope` is a graph. The gateway resolves a model name to a released revision and forwards
**one** call (A-022, A-084 — *"the gateway does not retry upstream; it sets one deadline"*). Evaluation
runs N cases against deterministic assertions (A-005, A-053 — one attempt per case). A-011 fixes a
prompt body at *"one plain-text system message with optional `{{variable}}` placeholders"*, and A-094
settles the provider surface as one OpenAI-compatible adapter. There is no branching, no tool loop, and
no state carried across model turns anywhere in the MVP.

Keeping the libraries would add a large transitive dependency tree and, more expensively, a second
mental model for what a "call" is — one that would tempt future work into expressing dispatch as a graph
in a system where ADR-0015 already fixes the OpenAI shape as the internal dispatch contract.

**Impact if wrong**: Reinstating either library is `pip install` and an edit, not a migration — which is
why this is an assumption rather than an ADR. What it would not restore automatically is anything built
in the meantime against the plain-client shape, so the cost grows slowly rather than staying flat.
