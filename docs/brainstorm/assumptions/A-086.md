# A-086 — An authenticated call that is refused still writes a call record; an unauthenticated one does not

**Statement**: Once a consumer key has been authenticated, every call writes a call record — including
the refusals: unknown model name, no release, key not permitted, pin not Approved, caller-supplied
system message, missing variable. Their `outcome` is `caller_error` and their token count and cost are
zero. A call that fails **authentication** writes no call record; it increments
`prope_gateway_auth_failure_total` and nothing else.

**Rationale**: A refused call is the one a developer needs to see, and "my requests are not arriving"
with an empty record is the hardest support conversation there is. Authentication failures are
excluded for the opposite reason: there is no authenticated workspace to attribute the record to, so
storing it would mean a body of unknown provenance sitting in a workspace's ledger — and an
unauthenticated endpoint that writes to durable storage on request is a way to fill someone's disk.

**Impact if wrong**: A branch on the write path. Note that a refused call's stored body is still a
body, so it inherits OQ-013's policy exactly like a successful one.
