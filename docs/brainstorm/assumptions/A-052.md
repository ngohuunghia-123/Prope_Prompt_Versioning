# A-052 — Retiring a prompt is refused while it has an active release

**Statement**: A retire request on a prompt property whose `released_version_id` is set is refused, with
a message naming the active release. To retire, the release must first be withdrawn — a recorded
decision on `release-control`'s surface with an actor and a reason. After withdrawal the gateway returns
a model-not-found error for that model name; it never silently keeps serving a retired prompt.

**Rationale**: `00_context.md` records Prope as an **accepted hard dependency** of consuming products'
request paths. Under that constraint, retiring a prompt is an outage in someone else's product, and it
must not be reachable by one owner tidying up their list. Refusing the retire converts a silent
production break into a decision with a name on it.

**Impact if wrong**: A guard clause. The consequence worth noting is a discovery, not a risk: this adds
a **withdraw release** action to `release-control` that no earlier document listed, to be confirmed when
that module is locked.

**Confirmed 2026-08-08** while locking release-control. Withdraw is specified in A-069 and ADR-0009: a
`release` row with `kind = withdraw`, its own permission, a mandatory reason, and a new prompt-registry
command `clear_released_revision`. The gateway then returns model-not-found rather than serving the
previous revision or the fallback answer.
