# A-066 — Changes requested returns the revision to Draft; the fix is a new revision

**Statement**: A `changes_requested` decision returns the revision to status Draft and closes its review
task. The decision is not lost: it is an `approval` row with `decision = changes_requested`, a mandatory
comment, and a `changes_requested` history event. The author's fix is a new immutable revision (A-002),
never an edit to the rejected one.

**Rationale**: The status vocabulary is fixed by a non-negotiable constraint (`00_context.md` — Draft,
In review, Approved, In use, Retired) and contains no rejected state. Inventing one would break the
constraint to store information the decision log already holds better, with an actor and a reason
attached.

**Impact if wrong**: Adding a sixth status is a migration plus a copy change — but it would also need
the constraint row reopened, since the vocabulary is the user's.
