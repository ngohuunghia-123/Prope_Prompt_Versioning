# A-028 — A restore to a previously released revision needs no new approval

**CONFIRMED BY THE USER 2026-08-09** (OQ-002 resolved, option 1). The exemption covers the repetition
of a decision, never the decision itself: a restore to an Approved revision that has never been
released is an ordinary release and still requires one.

**Statement**: A restore whose target revision is Approved **and** was already released at least
once under a recorded approval proceeds without a fresh release decision. It requires a one-line
reason, and it appends a release event with `kind = restore`. A restore to an Approved revision that
has never been released is an ordinary release and does require the release decision.

**Rationale**: No new judgment is being made — the organisation already approved both the revision
and the act of releasing it, and a restore only returns to a state it previously accepted. It is
also the only reading that makes the ≤5-minute restore target in H-05 reachable during an incident.
The narrower case (approved but never released) is excluded because there the release decision
genuinely has not been made yet.

**Impact if wrong**: One conditional in the release path. If you choose "not exempt", the break-glass
route (A-009) already covers the incident case without new code.
