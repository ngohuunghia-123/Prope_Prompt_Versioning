# A-051 — Proposed default: an owner is one person; transfer is an explicit recorded action

**Statement**: Until OQ-008 is answered, `owner_id` on a prompt property references exactly one person.
Ownership transfer is an explicit action recorded in property history with both parties named. A leaver
is handled by transfer, not by orphaning: a workspace admin may reassign any prompt whose owner is no
longer a member, and that reassignment is itself a history event.

**Rationale**: The survey's finding is that 9/11 do not know who owns a prompt — a team-shaped owner
would reproduce exactly that, because "the growth team owns it" is not an answer to "who do I ask".
Accountability wants a name. The design is kept cheap to reverse by never denormalising the owner's
name or email anywhere: `owner_id` is a single indirection that can point at a principal table instead
of a user table if OQ-008 answers "team".

**Impact if wrong**: One foreign key and the resolution of "who do I notify". Moderate rather than
cheap because notification and permission checks both read it.
