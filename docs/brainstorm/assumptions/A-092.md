# A-092 — Decrypted credentials live only in a 60 s process-local cache; a rotation is effective within 60 s

**Statement**: A credential is decrypted inside provider-access and held in an in-memory cache keyed
by `provider_config_id`, TTL 60 seconds. It is never persisted, never logged, never shared between
processes, and never crosses a module seam. Nothing invalidates the cache — it expires. A rotation is
therefore effective in every process within 60 seconds.

**Rationale**: The cache exists because the alternative is an unwrap and a decrypt on every gateway
call, and the gateway's entire added-latency budget is 50 ms (A-031). Cryptography on the hot path is
exactly what envelope encryption's key hierarchy is meant to let you avoid.

TTL-only, with no invalidation, is the same answer ADR-0012 reached for the resolution cache and for
the same structural reason: A-012 rules out a broker and no module has an inbound edge into this one,
so there is no mechanism for an invalidation message to arrive on. Inventing one would mean reversing
a dependency direction to shave 60 seconds off an operation nobody performs under time pressure.

The 60-second window is safe in the case that matters. A credential is rotated either routinely — in
which case both keys work — or because it leaked, in which case the workspace revokes it at the
provider and the stale cached copy simply fails with `credential_rejected`. The window delays the new
key taking effect; it does not extend the old key's life.

**Impact if wrong**: Shortening the TTL trades latency for freshness and is a constant. Removing the
cache entirely is also possible and costs a few milliseconds per call — worth doing only if a
compliance answer demands it, because the gateway's budget has no room to spare.
