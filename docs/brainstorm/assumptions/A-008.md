# A-008 — Who may approve is determined by permission alone; self-approval is recorded, never blocked

**Statement**: Any actor holding the approve permission may approve any revision they can see,
**including one they authored**. There is no author-based exclusion and no person-level segregation
rule anywhere in the system. Where the approver is also the author, the `approval` row records
`self_approved = true`, the property-history event carries the same fact, and
`prope_release_self_approval_total` counts it. It is recorded so it is countable — it is never refused.

**Rationale**: User decision, 2026-08-08. Access is a permission question, and the workspace decides who
holds approve; a rule that overrides the permission grant makes the RBAC matrix a partial answer to its
own question.

The earlier agent-decided version over-read its own source. `BRIEF.md` §9.2 argues that the person who
writes a change to production should not be the **only** person who releases it — an argument for the
existence of a control, not for an author-based exclusion. A workspace that wants that separation
expresses it by not granting approve to authors, which is the same control located where it belongs.

The practical cost of the old rule was concrete: in a small team it made break-glass the only route
forward whenever no second reviewer was available (A-009), trading a documented approval for a release
with no approval at all. Recording self-approval instead of refusing it preserves the signal without
producing that trade — the same shape as ADR-0005, where failing evidence is acknowledged rather than
blocked.

**Impact if wrong**: One validation rule to reinstate. The `self_approved` field means the pilot data
needed to decide that would already exist.
