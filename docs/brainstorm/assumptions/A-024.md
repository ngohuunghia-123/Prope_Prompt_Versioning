# A-024 — Provider, model, and generation parameters are part of the revision, and the caller cannot override them

**Statement**: A revision stores the provider configuration reference, the upstream model, and the
generation parameters (temperature, max tokens, and similar). Changing any of them creates a new
revision and goes through the same review as a text change. At the gateway, the `model` field of the
incoming request is the prompt reference and is never treated as an upstream model name; where the
revision sets a generation parameter, the revision wins over the value the caller sent.

**Rationale**: BR-06 requires every change to produce an immutable revision, and BR-07 requires cost
to be attributable to a revision — both fail if the model can change underneath a revision. The
override rule follows from BR-02: if a caller can swap the model at call time, the approval record
no longer describes what ran, and the whole approval chain is decorative.

**Impact if wrong**: Relaxing the override rule is a per-field allowlist. Moving the model binding
off the revision is not — it would invalidate every stored cost comparison.
