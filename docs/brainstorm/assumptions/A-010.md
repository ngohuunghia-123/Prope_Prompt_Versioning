# A-010 — Restore may only target a revision that was previously Approved, and is recorded as a release event

**Statement**: Restore is not a separate mechanism. It is a release whose target is a revision
already in status Approved, written to the release log with `kind = restore` and the reason for the
restore. A revision that was never approved cannot be restored to.

**Rationale**: BR-03 already forbids releasing anything unapproved, and modelling restore as a
release keeps one audit trail instead of two. Whether restore additionally needs its own approval is
the open half of OQ-002; this assumption covers only the target-eligibility rule, which does not
depend on that answer.

**Impact if wrong**: An added field on an existing event type.
