# A-102 — The price table is append-only and effective-dated, and is this module's audit trail

**Statement**: `price_table` rows are never updated and never deleted. Superseding a price is a new
row with a later `effective_from`; correcting a typo is the same operation. `spend_ceiling` carries
`updated_by` and `updated_at` on the row. **call-ledger writes no property-history event**, and this
is not an omission.

**Rationale**: A-014 requires an append-only history event for every state change on a **prompt
property** — that is what property-history is, by its glossary definition. A price row and a spend
ceiling are neither, so A-014 does not reach them. Recording them there anyway would require a
`call-ledger → property-history` edge, and the map's forbidden rule is `call-ledger → anything`
without a carve-out.

That leaves an audit obligation with no central place to live, and the answer is to put it in the
shape of the data. An append-only effective-dated table *is* a history: every price that was ever in
force is still there with the date it took effect and who entered it. It is a stronger guarantee than
an event log beside a mutable table, because there is no version of the price that the log could
disagree with.

Allowing an in-place edit "just for typos" was rejected in ADR-0019: a typo fix and a price change are
indistinguishable in the schema, so permitting one permits both.

**Impact if wrong**: If a compliance answer wants these in the central log, the edge has to be added
and the forbidden rule gains its first carve-out with a written reason — which is the right way for
that to happen, rather than by having quietly added it now.
