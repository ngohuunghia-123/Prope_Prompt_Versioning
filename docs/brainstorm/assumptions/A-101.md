# A-101 — A missing price is unpriced and a missing usage object is unknown; neither is ever zero

**Statement**: A call with no matching price row stores its real token counts and
`cost_status: unpriced` with a null cost. A call whose provider returned no usage object stores null
token counts and `usage_status: unknown`, with `cost_status: not_applicable`. Neither ever records
`0`. `get_run_totals` returns both gap counts alongside the total, so evaluation can withhold a cost
delta the way A-057 already withholds one on a dispatch error.

**Rationale**: A zero is a number a reviewer acts on. The cost delta exists precisely to inform an
approve decision, so a revision whose cost is unpriced would appear cheaper than its baseline and
would appear so most strongly at the moment the decision is made. An absent figure asks a question; a
wrong figure answers it. This is the same argument ADR-0013 made about estimating tokens — an
estimate that looks like a measurement is worse than an honest gap — and BR-07 makes it
non-negotiable for cost specifically.

Keeping tokens when the price is missing matters too: the call is repriceable later (A-100), and
throwing the tokens away because the money is unknown would make it permanently unrecoverable.

**Impact if wrong**: Nothing to reverse. The nullable columns and the two status fields are the
mechanism; a system that wanted zeros could compute them from these, never the other way round.
