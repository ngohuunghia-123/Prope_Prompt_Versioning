# A-117 — A workspace always has at least one Admin, and the last one cannot be removed or demoted

**Statement**: Creating a workspace creates its creator's Admin role binding in the same transaction.
Any operation that would leave a workspace with zero Admins — removing the member, revoking the role, or
changing it — is refused with a message saying so. A counter records the refusal, and a gauge of
workspaces with zero Admins exists and must always read zero.

**Rationale**: Admin is the only role that can grant roles (A-007). A workspace that reaches zero Admins
is permanently frozen: nobody can add a member, transfer ownership, rotate a provider credential, or
release anything, and there is no operator surface to fix it from — A-012 rules out the kind of ops
capacity that would run a repair script, and no module has a cross-workspace path by construction. The
refusal is cheap; the recovery is not.

Enforcing it at the operation rather than reconciling it afterwards matters because the realistic route
in is mundane — one Admin demotes themself while tidying up, or an Admin who has left is removed by the
only other Admin.

**Impact if wrong**: A refusal to relax. The gauge is what would show it was never needed.
