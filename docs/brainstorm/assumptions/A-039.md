# A-039 — Prope stores raw call records, not traces; Langfuse is an export target, not a rebuild

**Statement**: The MVP stores flat call records keyed by prompt and version ID. It does not model
traces, spans, parent-child relationships, or sessions; it ships no trace explorer, no analytics
dashboard, and no sampling policy. The Langfuse integration is a later export of stored call records,
and Prope does not reimplement what Langfuse already does.

**Rationale**: `BRIEF.md` §8 is unambiguous — do not build tracing or observability, integrate
instead, because Langfuse is free and better at it. Storing call records for traceability is inside
that line; growing a query UI over them is how a project crosses it without noticing. This assumption
exists to make the crossing visible when it is proposed.

**Impact if wrong**: Adding a trace model later is additive, but it would be a scope decision to
raise, not a silent extension.
