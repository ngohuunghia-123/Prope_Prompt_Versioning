# A-049 — Prompt properties and revisions are never hard-deleted; Retired is the terminal status

**Statement**: There is no delete endpoint for a prompt property or a revision. A property reaches the
end of its life as `Retired`, and revisions persist for as long as the property does. Destroying a body
outright — a secret pasted into a prompt, or a deletion obligation — is a deliberate, recorded
redaction, specified with OQ-013's policy rather than a general delete. Full reasoning in ADR-0002.

**Rationale**: The measured problem is lost provenance (`00_context.md#problem`: 5/11 cannot identify
which prompt caused a failure). A revision a release once pointed at is the evidence of what production
ran; a soft-delete flag would make the audit trail lie by omission, and a hard delete would make it
lie outright.

**Impact if wrong**: Adding redaction is additive. Reversing to a mutable store is a migration and a
re-litigation of the audit story, which is why it carries an ADR.
