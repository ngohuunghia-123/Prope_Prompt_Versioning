# A-130 — The gateway shares a process with the UI for now, and the split has a measured trigger

**Statement**: For the pilot, one `app` process serves the management API, ~~the server-rendered UI~~
(**amended 2026-08-09 — ADR-0052 moved the UI to a React SPA served by Caddy; `app` serves JSON**), and
the gateway's `POST /v1/chat/completions`. Splitting the gateway into its own uvicorn process is one
compose block from the same image (ADR-0026). The trigger is not a judgement: it is the gateway p95
histogram showing non-gateway work inside the budget during a load test.

**Rationale**: The risk is CPU, not IO. Everything on the gateway path is IO-bound and shares the event
loop happily. ~~Three~~ **Two** things on the same process are not: A-047's diff is *computed on demand
and never stored* over bodies capped at 32 KiB (A-050); ~~Jinja rendering of a long list is synchronous
work; and~~ argon2id is **deliberately** expensive by design (ADR-0021), burning tens of milliseconds of a
core and tens of megabytes per login. Any of these can land directly inside the p95 that
`00_context.md#success` states as *"p95 < 50 ms"* — and the gateway is *"an accepted hard dependency of
consuming products' request paths."*

The split is not taken now because the budget it protects is itself an agent-decided placeholder (A-031),
OQ-012 has not supplied a real load figure, and an eighth service on the host is a real cost against
A-012. What makes deferring safe is that the measurement already exists: ADR-0030 puts the histogram in
place from the first deployment, so this becomes an observation rather than an argument.

Recording it matters because the failure is otherwise invisible in the obvious place. A gateway p95
regression caused by somebody opening a diff screen looks like a gateway problem, and would be
investigated as one.

**Impact if wrong**: The split costs one compose block and a Caddy route, with no code change — the
image and the application already contain both surfaces. Discovering the need late costs a confusing
incident first, which is what this assumption is written to prevent.

> **Confirmed 2026-08-09 at the gateway's own stack pass, with the trigger sharpened and the price
> corrected.** The decision is unchanged: the gateway ships in `app`, and the split waits for the
> measurement rather than a judgement.
>
> **The trigger is sharper.** This assumption said *"argon2id is **deliberately** expensive by design"*.
> ADR-0043 has since made that a number — `m=47104` (46 MiB), `t=1`, **`p=1`** — and chose `p=1`
> explicitly because of this assumption's co-tenancy on ADR-0033's 4 vCPU. One login is now a known
> ~46 MiB, tens-of-milliseconds-of-a-core event inside a process holding a 50 ms p95. Worth adding: the
> gateway is the **only** surface in `app` with a Success-metric latency budget at all — every management
> route is budgeted at 300–500 ms, six to ten times looser.
>
> **The price is higher than stated above, in one specific way.** ADR-0046 made
> `interactive_concurrency` a **process-local semaphore in `app`**. Moving the gateway out moves
> interactive dispatch with it — but `app` keeps dispatching, because A-090's provider **verification
> probe** calls upstream when a provider config is registered. So the split leaves that probe uncapped
> or needs a third cap column, which is ADR-0046's own written warning: *"A third dispatching process
> would break this the same way ADR-0028 broke ADR-0016."*
>
> **The "no code change" half is restored by ADR-0050**, written in the same pass. Because the gateway is
> now a standalone ASGI application object that the management app mounts — rather than a router on a
> shared one — the split really is `uvicorn prope.gateway:app` against the same image plus a Caddy
> route. So the corrected price is: **no code change, one compose block, one Caddy route, and ADR-0046's
> third column.** That last item is the whole of what this note adds, and it is the item to decide
> before pulling the trigger, not after.

> **Amended 2026-08-09 by ADR-0052 — one of the three costs is gone, and the trigger is weaker.**
> The user chose a React SPA for the UI. Rendering moves to the browser and `app` returns JSON, so
> **Jinja rendering leaves this process entirely.** The strikethroughs above are that change.
>
> **What survives is the part that was always the sharper half.** The co-tenants are now A-047's
> `difflib` diff — still computed server-side by prompt-registry, still bounded by A-050's 32 KiB cap and
> still asserted at 300 ms by its AC-2 — and ADR-0043's argon2id at `m=47104`. Both are *bounded* CPU
> events on known inputs. What left was the one that **scaled with screen size**: a Jinja render of a
> long list grows with the list, and nothing in the locks caps how many prompts a workspace holds.
>
> So this assumption is not withdrawn and its histogram is not retired. It is **less likely to fire**, and
> the failure it was written to prevent — *"a gateway p95 regression caused by somebody opening a diff
> screen looks like a gateway problem"* — is unchanged, because opening a diff screen still costs `app`
> the same computation. Only the painting moved.
>
> **The corrected price from the gateway's pass still stands**, and is now the whole of what to decide
> before pulling the trigger: no code change (ADR-0050), one compose block, one Caddy route — and
> ADR-0046's third cap column for A-090's verification probe.
