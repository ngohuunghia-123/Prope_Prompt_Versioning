# A-103 — The monthly spend total is an aggregate row updated in the writer's transaction

**Statement**: `workspace_spend` holds one row per (workspace, month) with the running cost and call
count, updated inside the same transaction that writes the priced record. `check_spend_ceiling` reads
that one row.

**Rationale**: The ceiling check sits before the first dispatch of every eval run (A-029, A-056), and
the alternative is a `SUM` over the largest and fastest-growing table in the system, which gets slower
every day the product is used. Updating in the writer's own transaction keeps the total consistent
with the rows it summarises — an aggregate maintained by a separate job is an aggregate that is wrong
between runs, and the moment it is wrong is exactly the moment a ceiling is close.

Per month rather than per day because A-029's ceilings are monthly and per-run; a per-run ceiling is
checked against the run's own accumulating cost, not against this table.

**Impact if wrong**: Adding dimensions means adding columns to the key or a second aggregate. The
detail rows are all still there, so any aggregate can be rebuilt from them.
