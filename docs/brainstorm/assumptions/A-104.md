# A-104 — check_spend_ceiling fails open, and counts the failure

**Statement**: If the ceiling cannot be evaluated — the aggregate row is missing, the query times out,
the database is slow — `check_spend_ceiling` returns `allowed` and increments
`prope_call_ledger_ceiling_check_total{result=failed_open}`. It never raises into evaluation.

**Rationale**: A-029 makes ceilings optional and off by default, on the grounds that BYOK means the
spend is the workspace's own money and a mandatory cap would be Prope imposing policy on someone
else's budget. Failing closed would let an off-by-default, optional feature block the review loop that
is the product's core journey — the reviewer sees "cannot run evals" and has no idea it is a database
problem rather than a real limit.

Counting the failure separately from `allowed` is what keeps this honest. A ceiling that is silently
not being enforced looks identical to a ceiling that is not being hit, and the workspace that set one
deserves to be able to tell the difference.

**Impact if wrong**: A flag. The counter is what makes flipping it an informed decision rather than a
guess.
