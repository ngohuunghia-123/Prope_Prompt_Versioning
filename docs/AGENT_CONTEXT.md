## What this is

Prope is an enterprise **prompt asset register**. In the group's own survey (n=11), everyone keeps prompts
in chat history and Sheets, nobody can say which revision is current, and nobody has an approval step before
a prompt reaches production. The root problem is **lost ownership, lost provenance, and lost trust** — not
the absence of somewhere to save text. Prope answers it with immutable revisions of registered prompt
properties, a human approval gate no path bypasses, an append-only history of every state change, an
OpenAI-compatible gateway that resolves a **model name** to the released revision, and a ledger of what each
call actually cost. Source: `brainstorm/00_context.md`.

## Glossary

Use these words. The alternatives in brackets are wrong in product surfaces. Full entries in `brainstorm/00_context.md#glossary`.

| Term | One line |
|------|----------|
| **Prompt property** | One registry record: purpose, owner, model name, access level, revision chain |
| **Revision** | An immutable snapshot of body, provider, model, parameters and fallback answer *(not "version")* |
| **Model name** | The globally unique `namespace/name` a prompt is called by through the gateway |
| **Version ID** | The opaque identifier of one revision; pins a call, traces a release |
| **Trusted revision** | The revision a reviewer approved; the status stays literally `Approved` |
| **Released revision** | The one Approved revision a bare model name resolves to *(shown as "In use")* |
| **Release** | The recorded decision that points the gateway at one Approved revision *(not "publish")* |
| **Restore** | A release whose target is a previously Approved revision *(not "rollback")* |
| **Break-glass release** | A release with no prior approval: reason required, flagged, follow-up task |
| **Gateway** | The OpenAI-compatible endpoint that resolves, composes, forwards, and falls back |
| **Fallback answer** | A stored human-accepted answer returned when the upstream provider fails |
| **Call record** | One gateway call: prompt, version ID, consumer, tokens, cost, outcome, bodies |
| **Eval suite / eval case** | A named set of 10-20 hand-authored cases with deterministic assertions |
| **Cost delta** | Tokens and money, candidate versus released, over the same suite |
| **Grant access** | How a prompt reaches another person *(not "share")* |

Statuses are literal and are not renamed: **Draft, In review, Approved, In use, Retired**.

## The four non-negotiables

From `brainstorm/00_context.md#constraints`. An implementing agent may not trade these away:

1. **Human approval before production.** No auto-release of any kind. Break-glass is the declared,
   counted exception and its 24-hour follow-up task is what keeps it exceptional.
2. **Only `Approved` revisions may be released or resolved** — enforced by a database constraint, not by
   application code.
3. **Edit, review/approve, and release are separate permissions.** Self-approval is recorded, never refused.
4. **Prompts are private by default.** Enforced as not-found, never forbidden, and by RLS underneath.

Plus: provider credentials are workspace-supplied, encrypted at rest, never returned by any read API, and
redacted everywhere. **History rows are never deleted, at the database privilege level** — including when a
person leaves: their `access.user` row is tombstoned and their `actor_id` survives as an opaque value
(ADR-0054, A-151). `actor_id` is a value and not a foreign key, which is what makes that free.
