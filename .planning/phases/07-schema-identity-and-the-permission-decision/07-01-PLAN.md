<objective>
Build the `access` schema and prove it against the thinnest real path there is: a person exists, a
workspace exists with that person as its Admin, the person signs in with a password, gets a
server-side session row, presents the cookie, and is served a `/api/v1` response by a route that has
answered `401` to every request since Phase 2.

**This is the tracer, and it is also the phase's unblocking act.** Four things elsewhere in the project
are waiting on it: `require_session`'s empty body, `access.list_workspaces()`'s absence (plan 07-03),
`EXPECTED_ABSENT_SCHEMAS`'s `access` entry, and the fact that no management route in Prope can be
driven by hand. Everything else in Phase 7 — `may()`, the membership commands, the tombstone, the
owed acceptance criteria — expands off the schema and the session this plan lands.

## D-96 — The whole `access` guarantee stack ships in ONE revision

**Chosen.** Eight tables, seven policies, eight grant blocks, three `SECURITY DEFINER` functions and a
35-row seed, in one Alembic revision.

**Rejected: one revision per kind** (tables / RLS / grants / functions / seed), which the phase-1
research recommended in general and which `alembic/ddl.py`'s own docstring already declines for the
same reason. A tracer's value is proving the stack connects **in a single applied migration**; a chain
of five revisions has four intermediate states in which `access.session` exists and is readable across
tenants, and a deploy interrupted between two of them leaves one of those states running.

**Rejected: deferring the seed to a data migration or to application startup.** ADR-0020's whole point
is that OQ-006's answer is *"a seed rather than a migration"* — which requires the seed to be a
migration object now, so that replacing it later is one file. A startup seeder is a second
provisioning path (the split D-02 refused) and it makes the running matrix depend on which process
booted last.

**Reversibility: costly.** A landed revision is never edited — a change is a new revision. The seed is
the cheap part (delete-and-insert in one statement); the CHECK constraints and the function signatures
are the expensive part.

## D-97 — Three `SECURITY DEFINER` functions land here, not two, and the sanctioned-set test carries a declared not-yet-built list

**Chosen.** `access.lookup_session`, `access.lookup_api_key` **and** `access.list_workspaces` are all
created by this revision.

The ROADMAP's phase goal names *"the two `SECURITY DEFINER` bootstrap functions"*, and that is accurate
about the pair ADR-0042 wrote: those two exist because the reads that produce `app.workspace_id`
cannot consume it. `access.list_workspaces()` is not a bootstrap function — it is ADR-0051's generic
cross-tenant enumerator — and it is nevertheless this phase's, because
`.planning/ORCHESTRATION.md` §4 routes Broken Window #3 here and `src/prope/worker.py`'s
`ObservedWorkspaces` docstring names this phase by number in three places. Creating it in the same
revision as the schema it reads is the only place it can go: it is an `access` object, and plan 07-03
wires it without touching a migration.

**Rejected: deferring `list_workspaces` to Phase 8.** It leaves a real retention gap open for a whole
phase — a workspace with no traffic since process start is never swept — for no saving, since the
revision is being written anyway.

**Rejected: creating `evaluation.claim_next_run()` here so the count is four.** It would put an
`evaluation`-schema object in access-control's migration and create a schema
`EXPECTED_ABSENT_SCHEMAS` declares absent, and a function with no caller for nine phases drifts from
the caller that eventually arrives. The consequence — that the four-and-only-four assertion has to be
written against *sanctioned minus not-yet-built* — is raised as **OQ-045** and implemented in plan
07-06.

**Reversibility: one-way on the count** (a fifth is never the answer), **cheap on the not-yet-built
list** (Phase 16 deletes one line).

## D-98 — The `may()` action vocabulary is a NEW enum, not an extension of `session_auth.ManagementAction`

**Chosen.** `prope.access_control.vocabulary.Action` holds A-115's twenty-five names.
`src/prope/session_auth.py`'s `ManagementAction` is left byte-for-byte alone.

They are two closed lists that share no member: `ManagementAction`'s five are `call_ledger.`-prefixed
route labels, A-115's twenty-five are permission names. **Merging them reddens a shipped test on the
first line** — `tests/architecture/test_route_table.py::test_every_registered_action_is_declared_exactly_once`
asserts `sorted(declared) == sorted(MANAGEMENT_ACTIONS)`, an exact set equality over the enum, and
adding twenty-five members that no route declares breaks it immediately. call-ledger makes **no
INT-001 call at all** (ADR-0018), so its declarations were never `may()` inputs.

That AC-10 reads *"every route declares an action from the vocabulary"* — singular — is the conflict,
and it is raised as **OQ-041** rather than resolved by editing either list. AC-10's cross-module form
cannot run before Phase 23 in any case (`PITFALLS` gap 5).

**Reversibility: cheap.** One enum, one CHECK constraint, one seed.

## D-100 — argon2-cffi is pinned exactly, and the cost is asserted from the produced hash

**Chosen.** `argon2-cffi` is added with an exact `==` pin at whatever the resolver returns for
`>= 23.1` (the floor `docs/modules/access-control.lock.yml` `libraries_frameworks` states), and the
resolved version is written into the pin **and** into the comment beside it.

The pin is not the control. The control is
`tests/unit/test_argon2id_cost_is_asserted.py`, which hashes a password and parses the **encoded hash
string** — `$argon2id$v=19$m=47104,t=1,p=1$…` — asserting the three parameters off the artifact the
library actually produced. ADR-0043 says the defaults *"have already changed once between releases"*;
a test that read `PASSWORD_HASHER.memory_cost` would assert the constructor's arguments back to itself
and pass against a library that ignored them.

**Rejected: pinning the floor `23.1.0` verbatim.** A version pinned because it is the number in a
sentence, rather than because anything was checked, is a pin nobody can defend at the next upgrade.

**Reversibility: cheap.**

## D-101 — `require_session` reads `app.state.sessionmaker` itself, and refreshes nothing

**Chosen.** `require_session(request, session_cookie)` gains a `Request` parameter, reads
`request.app.state.sessionmaker` directly, and calls `authenticate_session`.

**Rejected: `Depends(get_sessionmaker)`.** That function lives in `src/prope/call_ledger/api.py` and
raises with `prope.call_ledger.schemas.ErrorCode`. Importing it into `session_auth.py` — which is
shared infrastructure six modules depend on, and deliberately outside every module's package
(OQ-021) — would make the shared session boundary depend on one module's error vocabulary. Its 503
refusal is reproduced here instead, with the **same machine code string**, `internal_error`, so no new
catalogue key is invented (ADR-0053) and a test asserts the two constants are equal.

**No `last_seen_at` refresh, and that is a decision.** The column exists and is written once, at
creation. Refreshing it would put an `UPDATE` on **every authenticated request in Prope**, on a read
ADR-0022 already refuses to cache — the highest write volume in the system, bought for a column
nothing reads yet. The absence is stated at the column.

**Reversibility: cheap.** The five call sites do not change either way; `Depends(require_session)`
resolves a `Request` without them saying so, and
`tests/integration/test_management_routes.py`'s `dependency_overrides[require_session]` seam is
unaffected because it overrides by object identity.

## D-102 — A no-match runs argon2id against a hash minted at import, never a hard-coded literal

**Chosen.** `ABSENT_USER_HASH` is computed once at module import as
`PASSWORD_HASHER.hash(secrets.token_urlsafe(32))` and used whenever there is no stored hash to compare
against — an unknown email, and a tombstoned row whose `password_hash` is NULL.

A-151 requires that *"the login path treats a NULL hash as no-match **without skipping the hash
comparison**"*, and that is what makes AC-13's timing clause true. The hash has to come from
somewhere.

**Rejected: a hard-coded encoded hash constant.** It costs nothing at import and it drifts silently:
the day ADR-0043's cost is raised, the real path spends the new cost and the absent path spends the
old one, and the timing oracle this constant exists to close reopens with nothing failing. Minting it
from the live `PASSWORD_HASHER` makes drift impossible by construction.

**Rejected: skipping the verification when there is no hash and sleeping instead.** A sleep is a number
somebody has to keep equal to a cost nobody measures, and it is the shape that looks equivalent in a
test and is not under load.

**The cost accepted, stated:** ~60 ms of import time in every process and every test session. That is
one verification's worth, once.

**Reversibility: cheap.**

## D-103 — `role_permission` is seeded by the migration and excluded from the truncate fixture

**Chosen.** The seed is `INSERT`ed by the revision; `tests/conftest.py`'s truncate fixture names
`access.role_permission` in its exclusion list, exactly as plan 04-01 excluded

render so it can be compared against OQ-006's signed-off one. Two sources for it is how the comparison
stops meaning anything.

**Reversibility: cheap.**

## The two things this plan deliberately leaves open, said plainly

**`access.lookup_api_key` has no Python caller in this phase.** The function is created because the
schema is this phase's deliverable and ADR-0042 defines the pair together; `authenticate_api_key` and
`may_resolve` are Phase 8's (INT-003, INT-004). It is not left unexercised —
`tests/integration/test_access_schema_ships_its_guarantees.py` calls it directly and asserts its return
shape and its privilege posture.

**A `workspace_member` row can be written by this plan and removed by nothing.** The removal command,
the role-revoke command and A-117's last-Admin refusal are plan 07-04. Until then the only member a
workspace has is its creator, and the only way to a second one is a hand-written `INSERT` in a test.
That is a bounded, one-plan gap in a module nothing outside this phase calls yet.

### `alembic/ddl.py` — two new emitters, in the existing register

`grant_schema(schema, *, roles)` — `CREATE SCHEMA … AUTHORIZATION prope_migrate` is already inline in
0001 and stays there; this emits only the `GRANT USAGE ON SCHEMA … TO …` line, so a reviewer greps one
helper name for every schema-level grant in the project.

`security_definer_function(schema, name, *, arguments, returns, body, volatility="STABLE")` — emits
the whole sanctioned shape as one call, because **the shape is the security control and a shape
assembled by hand at three call sites is three chances to drop a line**. It must emit, in this order:

```
CREATE FUNCTION <schema>.<name>(<arguments>) RETURNS <returns>
LANGUAGE sql <volatility> SECURITY DEFINER SET search_path = ''
AS $$ <body> $$;
REVOKE ALL ON FUNCTION <schema>.<name>(<argument types>) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION <schema>.<name>(<argument types>) TO prope_app;
```

Its docstring carries the three mitigations ADR-0042 names and **why each is not optional**:

- `SET search_path = ''` — a `SECURITY DEFINER` body runs as the owner, so a caller who can set
  `search_path` could otherwise put a shadowing `access` schema of their own in front of the real one
  and have the owner read it. The empty path means **every object in `body` must be
  schema-qualified**, including `access."user"`; `pg_catalog` remains implicitly searched, so `now()`
  and the operators still resolve.
- `REVOKE … FROM PUBLIC` then `GRANT … TO prope_app` — PostgreSQL grants `EXECUTE` on a new function
  to `PUBLIC` by default, so without the revoke the escape hatch is open to every role including
  `prope_report`.
- The **return type is the fourth mitigation and it is not emitted here** — it is the `returns`
  argument, and ADR-0051's rule is that *"a function that returns tenant identifiers keeps every
  subsequent data read under RLS; a function that returns rows does not."* Say at the parameter that a
  reviewer's job at this call site is to check the return type is identifiers.

Note in the docstring that `LANGUAGE sql` rather than `plpgsql` is deliberate: a SQL-language body
cannot contain control flow, so it cannot contain a decision, which is the property that keeps these
three lookups and not authenticators (ADR-0042: *"the hash comparison stays in the application … a
function that decided authentication would be a security-definer object with a security decision
inside it"*).

### The revision

`CREATE SCHEMA access AUTHORIZATION prope_migrate`, then `grant_schema("access", roles=["prope_app",
"prope_report"])`. Everything after runs inside `assume_migrate_role()` / `reset_role()`.

**Eight tables. Types follow 0003 and 0004: every identifier is `text` (ADR-0003 prefixed ULIDs), every
timestamp is `timestamptz` (A-003), and no foreign key leaves the `access` schema.**

1. **`access.workspace`** — `id text PRIMARY KEY` (`wsp_` prefix), `name text NOT NULL`,
   `slug text NOT NULL`, `created_by text NOT NULL`, `created_at timestamptz NOT NULL DEFAULT now()`,
   `CONSTRAINT uq_workspace_slug UNIQUE (slug)`. **The policy is on `id`, not on `workspace_id`** —
   `enable_tenant_rls("access", "workspace", column="id")`, which the existing helper already supports
   through its `column` parameter. Comment it at the call: this table *is* the workspace, it is the
   tenancy root, and ADR-0042's original second clause for it was retired by ADR-0045 in favour of a
   `GLOBAL_TABLES` entry — so the entry below says *policied on `id`*, which is a statement about
   where the policy is and not an exemption from having one.
2. **`access."user"`** — quoted everywhere, `user` is reserved. `id text PRIMARY KEY` (`usr_`),
   `email text`, `display_name text`, `password_hash text`, `must_change_password boolean NOT NULL
   DEFAULT true` (A-110), `status text NOT NULL DEFAULT 'active'`,
   `created_at timestamptz NOT NULL DEFAULT now()`, `last_login_at timestamptz`,
   `tombstoned_at timestamptz`, `tombstoned_by text`.
   `CONSTRAINT uq_user_email UNIQUE (email)` — and comment that PostgreSQL permits any number of NULLs
   in a unique index, which is precisely what lets any number of people be tombstoned (the lock says
   so in `data.owns`).
   `CONSTRAINT ck_user_status_values CHECK (status IN ('active','tombstoned'))` — cite **OQ-044**,
   which is where the second value came from.
   `CONSTRAINT ck_user_tombstone_is_complete CHECK (status <> 'tombstoned' OR (email IS NULL AND
   display_name IS NULL AND password_hash IS NULL AND tombstoned_at IS NOT NULL AND tombstoned_by IS
   NOT NULL))` — the whole of A-151's column table as one engine-enforced rule. **This is the
   database-first move for AC-13**: a tombstone that cleared two of the three identifying columns is a
   refusal at the engine rather than a bug found by reading. Say that at the constraint.
   **No tenant column and no policy** — the lock and ADR-0042 both say so, and a person is not a
   tenant's property (`unique(email)` is global).
3. **`access.session`** — `id text PRIMARY KEY` (`ses_` prefix; note at the column that ADR-0003's
   named prefixes are `wsp_`, `usr_` and `key_` and that a session id is not among them, so `ses_` is
   this plan's choice, chosen for greppability and recorded here rather than assumed),

   `created_at timestamptz NOT NULL DEFAULT now()`, `expires_at timestamptz NOT NULL`,
   `last_seen_at timestamptz`, `user_agent_hash text`.
   `CONSTRAINT ck_session_expires_after_creation CHECK (expires_at > created_at)`.
   Index `ix_session_user_id ON access.session (user_id)` — the tombstone deletes every session a
   person holds (A-151) and the member-removal path will too, and both are lookups by `user_id` on a
   table read on every request. `enable_tenant_rls("access", "session")`.
4. **`access.workspace_member`** — `workspace_id text NOT NULL`, `user_id text NOT NULL`,
   `added_by text NOT NULL`, `added_at timestamptz NOT NULL DEFAULT now()`,
   `status text NOT NULL DEFAULT 'active'`,
   `CONSTRAINT pk_workspace_member PRIMARY KEY (workspace_id, user_id)`,

   **OQ-044**, and comment that there is deliberately **no pending state** because there is no
   invitation to be pending on (A-110), and that removed rows are **retained** because they are how
   the tombstone knows which workspaces to write its event into (A-151). Tenant RLS.
5. **`access.role_binding`** — `workspace_id`, `user_id`, `role text NOT NULL`, `granted_by text NOT

**Grants.** One `grant_table` call per table, positive form:
`workspace` → `SELECT, INSERT`; `user` → `SELECT, INSERT, UPDATE` (a tombstone is an `UPDATE`; there
is **no `DELETE` anywhere in this schema for `user`**, and that is the privilege half of *nothing
un-tombstones a row*); `session` → `SELECT, INSERT, DELETE` (no `UPDATE`: D-101 refreshes nothing, so
the privilege is withheld rather than merely unused — the same posture 0003 took on `call_body`);
`workspace_member` → `SELECT, INSERT, UPDATE` (removal is a status change, not a delete);
`role_binding` → `SELECT, INSERT, DELETE`; `role_permission` → `SELECT` **only** (D-103);
`prompt_grant` → `SELECT, INSERT, DELETE`; `api_key` → `SELECT, INSERT, UPDATE` (revocation sets
`revoked_at`). Every one of those choices gets one sentence at its call.

**The three functions**, each through `security_definer_function`:

- `access.lookup_session(p_id text) RETURNS TABLE (user_id text, workspace_id text)` —
  `SELECT s.user_id, s.workspace_id FROM access.session s WHERE s.id = p_id AND s.expires_at > now()`.
  The `expires_at > now()` clause is **the whole of session expiry in this system**: the lock's
  `deployment_target` says there is no sweeper and *"an expired row is never returned even if it is
  still present"*. Comment it as such — a periodic delete of expired rows would be housekeeping for
  disk, not for correctness.
- `access.lookup_api_key(p_key_id text) RETURNS TABLE (workspace_id text, key_id text, key_hash text,
  scope_model_names text[], revoked_at timestamptz)` — `SELECT k.workspace_id, k.id, k.key_hash,
  k.scope_model_names, k.revoked_at FROM access.api_key k WHERE k.id = p_key_id`. It returns the
  stored hash and **does not authenticate** (ADR-0042); it does not filter on `revoked_at` either,
  because the refusal is the application's and returning the timestamp is what lets the caller say
  *revoked* rather than *unknown*. Both facts go in the comment.
- `access.list_workspaces() RETURNS SETOF text` — `SELECT w.id FROM access.workspace w ORDER BY w.id`.
  Ordered, so a sweep pass has a stable order (`ObservedWorkspaces.current`'s docstring already
  promises that of the thing this replaces). Identifiers and nothing else, per ADR-0051's rule.

### `src/prope/access_control/identity.py`

`SESSION_TTL` as a `#:` tuning constant with the argument written at it: twelve hours, because a
session TTL here is a bound on an **abandoned** session and not a security control — ADR-0022 makes

`async def sign_in(sessionmaker, *, email, password, user_agent_hash=None) -> str | None` — the shape

failure paths do the same work**:

1. `SELECT id, workspace_id-less` — read `id`, `password_hash`, `status` from `access."user"` by
   `email` on a plain session. One indexed read.
2. `stored = row.password_hash if row is not None and row.password_hash is not None else
   ABSENT_USER_HASH`.
3. `ok = verify_password(stored, password)` — **unconditional**. There is no branch that skips it.
4. If `row is None` or `row.password_hash is None` or `row.status != 'active'` or not `ok`: increment

   `None`, from one `return` statement, so there is nothing for the four paths to differ in.**

   choice is made here so it is at least stable; a workspace switcher is a later feature and
   `docs/architecture/interfaces.md` INT-029 registers no route for one. If there is no active
   membership, `return None` through the same statement.

   `expires_at = now + SESSION_TTL`, update `access."user".last_login_at`, and — per ADR-0043 —
   `if password_needs_rehash(stored): UPDATE access."user" SET password_hash = hash_password(password)`,

**Sign-in is not a history event and must not append one.** The lock says so explicitly:
*"Sign-in successes and failures are NOT events … putting it here would turn the audit trail into an
access log."* Put that sentence at the function.

function (ADR-0029, ADR-0042); and nothing here is cached, by this module or by its caller, because

counted.
