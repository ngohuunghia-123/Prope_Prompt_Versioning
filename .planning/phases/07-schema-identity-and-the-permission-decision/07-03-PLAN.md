## D-108 — the enumerator is bound in the composition root, so no call-ledger module gains an import

**Chosen.** `build_workspace_enumerator(sessionmaker) -> WorkspaceEnumerator` lives in
`src/prope/worker.py`, beside `build_retention_resolver`, and is the only place
`prope.access_control.bootstrap.list_workspaces` is called from outside its own package.

**This is not the forbidden edge, and the distinction has to be written down or somebody will
"fix" it.** `docs/modules/access-control.lock.yml` `forbidden_dependencies` names call-ledger, and the
module map's blanket rule runs the same way. What is forbidden is a **module** depending on another
module. `src/prope/worker.py` is not call-ledger — it is D-13's explicit central composition root,
outside every module's package, in the same position as `src/prope/app.py` and
`src/prope/session_auth.py`. Composing two modules is the entire reason it exists, and ADR-0051 names
`worker` as `list_workspaces()`'s caller in as many words.

The mechanical proof, and it is the acceptance criterion: **`git diff --stat src/prope/call_ledger/`
is empty after this plan.** `sweep_expired_bodies` and `delete_expired_bodies` never learn that an
`access` schema exists.

**Rejected: a `list_workspaces` wrapper inside `prope/call_ledger/retention.py`.** Shorter to wire and
it is the forbidden edge, spelled with an import.

**Rejected: passing the enumerator down from `_amain` only, leaving `run_worker`'s default as the
stand-in.** Then the production path and the test path enumerate differently, which is how the gap
survives its own fix.

**The consequence, stated rather than discovered from a retention alert.** The sweep now visits
exactly the workspaces that have a row in `access.workspace` — not the workspaces that appear in
`ledger.call_record`. Those two sets are the same in production, because every workspace is created
through `create_workspace` and a gateway call carries a `workspace_id` that came from an
`access.api_key` row which is itself workspace-scoped. They are **not** the same in the test rig,
where ledger rows are seeded against bare string workspace ids; see Task 2, which is where that bites.
Record it as a `#:` note at the enumerator, because "a ledger row whose workspace was never created is
never swept" is the kind of sentence somebody needs to find in one grep.

**Reversibility: cheap.** One function and one default argument.

## D-109 — `ObservedWorkspaces` is deleted; the observation *point* survives as a plain callback

**Chosen.** The class goes. `build_retention_resolver`'s `observing` parameter is **retyped** from
`ObservedWorkspaces | None` to `Callable[[str], None] | None`, and `run_worker` gains a matching
pass-through parameter.

**Why keep the seam at all.** `tests/integration/test_worker_jobs.py::_StopOnFirstSighting` subclasses
`ObservedWorkspaces` and overrides `note()` **not to observe anything** but as a timing trigger: it is
called by the retention resolver after a window has been collected and grouped and before the write
transaction opens, so a stop set from there is *"a stop arriving mid-window by construction rather
than by sleeping and hoping."* That test proves T-02-19 — the in-flight window commits before the
worker returns — and it is the only mechanism in the repository that can hit that instant
deterministically. Deleting the observation point would cost a proven property to save a parameter.

**So the class is deleted and the hook is not.** After this plan the hook has exactly one consumer, it
is a plain callable rather than an object with state, and `run_worker`'s docstring already states the
posture that covers it: *"Every parameter after `stopping` exists so this composition is drivable from
a test on the machine it was written on."*

**Rejected: keeping `ObservedWorkspaces` as the default with the real enumerator as an opt-in.** Two
answers to *which workspaces exist*, chosen by a default argument. The stand-in's own docstring rules
this out — *"this class stops being the default"* — and the gap it leaves is measured by a gauge
(`oldest_body_age_seconds`) that would then be reporting on whichever one the deployment happened to
get.

**Rejected: keeping the class and having `note()` do nothing.** A named class whose method is a no-op
is a class somebody re-implements.

**Reversibility: cheap**, and the deletion is the point — Phase 2 left the instruction to delete it
here.

**Add `build_workspace_enumerator(sessionmaker) -> WorkspaceEnumerator`:**

```python
def build_workspace_enumerator(
    sessionmaker: async_sessionmaker[AsyncSession],
) -> WorkspaceEnumerator:
    async def enumerate_workspaces() -> Sequence[str]:
        async with sessionmaker() as session:
            return await list_workspaces(session)
    return enumerate_workspaces
```

Four things must be argued at the code:

1. **A plain session, not `workspace_transaction`.** There is no tenant to set — finding out which
   tenants exist is the whole call — and opening one would be asking the question the function exists
   to answer. `access.list_workspaces()` is `SECURITY DEFINER` and runs as the table's owner, so it is
   not subject to the policy; that is the sanctioned bypass and it is one of exactly four in the
   product.
2. **A session per call, not one held open.** A pass runs every `RETENTION_SWEEP_INTERVAL_SECONDS`
   (300 s by default), so a held connection would be idle for five minutes at a time on a host with
   one PostgreSQL.
3. **The composition-root argument (D-108)** in two sentences: this is not the forbidden
   call-ledger → access-control edge, because this file is not call-ledger, and nothing under
   `src/prope/call_ledger/` learns that the `access` schema exists.
4. **The consequence (D-108's last paragraph):** the sweep visits the workspaces that exist, not the
   workspaces that have ledger rows, and a `ledger.call_body` row carrying a `workspace_id` with no

`sweep_expired_bodies` opens **one transaction per workspace**, and that N is now the number of
workspaces that exist rather than the number this process has seen traffic for. At pilot scale this is
a handful; the sentence exists so the first person to run it at a thousand workspaces finds the note
rather than the behaviour.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `prope_app` -> `access.workspace` | The enumerator reads every tenant's identifier from a session with no tenant context. It is one of four sanctioned bypasses of tenant isolation in the product. |
| enumerator -> retention sweep | The identifiers it returns decide which tenants' rows a subsequent `DELETE` may touch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-07-18 | Information disclosure | `access.list_workspaces()` returning more than identifiers | high | mitigate | ADR-0051's rule, enforced by the return type: `SETOF text`. A function returning identifiers keeps every subsequent read under RLS; one returning rows performs the read with the policy off.
