<objective>
Ship the two seams the gateway calls on **every single request** — INT-003 `authenticate_api_key` and
INT-004 `may_resolve` — and the three routes that create, list and revoke the keys they read.

**These two are the only access-control seams with a stated latency budget**, p95 < 5 ms measured
together at 50 rps cold, because there is no cache by decision (A-114, ADR-0022). Everything in this
plan is shaped by two facts: the answer must be one indexed read plus one constant-time comparison,
and the secret it compares must not survive the function that parsed it.

---

**D-123 — the presented key is parsed into an identity and a secret, and the secret never leaves the
parse's return value.**
Chosen: `parse_presented_key(presented) -> PresentedKey | None`, a frozen slotted value object holding
`key_id` and `secret`, and **every log line, metric label and exception raised anywhere downstream
carries `key_id` and never `secret`.** The parse itself logs nothing at all.
Rejected: **passing the raw `prope_<key_id>_<secret>` string down into the lookup** and splitting it
where it is needed. The lock file names this exact failure: *"the format `prope_<key_id>_<secret>`
makes it easy to log the whole presented string by accident, so the parse must discard the secret
before anything downstream can see it"*. A single string that is sometimes safe to log and sometimes
not is a string somebody logs.
Rejected: **a deny-list of field names in the logger.** A-046 requires a positive allow-list, and
`src/prope/observability.py` argues why at length: a deny-list passes the first time a secret travels
on a field nobody thought to forbid.
Reversibility: **cheap.**

**D-123's companion clause — `authenticate_api_key` returns `None` for every failure and raises for none of them, and the
four failure branches are indistinguishable to the caller.**
Chosen: malformed string, unknown `key_id`, wrong secret, revoked key → `None`. A database failure →
the exception propagates, which becomes a 5xx at the gateway and never an admit.
Rejected: **distinct return values or exception types per branch.** INT-003 says a `null` is an
authentication failure and a raise is a 5xx; anything between the two is a signal a caller can branch
on, and the caller here is the gateway, whose refusal shape is a security requirement.
**The wrong-secret branch still runs the comparison even when the row is absent**, in the shape
ADR-0043 already requires of the login path: an unknown `key_id` compares against a fixed dummy hash
so the timing of "no such key" and "wrong secret" do not separate. Say so at the code; it is one line
and it is the only defence available on a seam with no rate limiter.
Reversibility: **cheap.**

**D-124 — `may_resolve` reads `scope_model_names` and returns a bare `bool`, and default-deny is the
absence of an else branch rather than a check.**
Chosen: `may_resolve(session, key_id, model_name) -> bool`, implemented as membership in the stored
array. An empty array resolves nothing. A revoked key resolves nothing.
Rejected: **a wildcard member, a prefix match or an "all models" flag.** A-081 makes the scope
explicit and default-deny, and states the cost out loud — *"releasing a new prompt does not make it
callable by an existing key ... a consumer who was never granted it sees a not-found with no
explanation"* — as a cost worth watching in the pilot rather than a gap to close with a wildcard.
Rejected: **returning a reason with the `False`.** The refusal must be byte-identical to an unknown
model name (A-081, A-116); a reason is the thing a leaked key would enumerate the registry with.
Reversibility: **costly** — a wildcard added later cannot be un-added from keys already carrying it.

**D-125 — the plaintext secret is returned by exactly one function, to exactly one caller, and the
response model that carries it is the only one in the module with a secret-shaped field.**
Chosen: `create_key(...) -> tuple[ApiKeyRow, str]` and a `ApiKeyCreated` response model carrying
`secret`, used by `POST /keys` and by nothing else. `ApiKeyRead` — the list model — has no such field,
and a test asserts the whole OpenAPI schema contains exactly one property named `secret`.
Rejected: **returning the secret on the read model as `None`.** A nullable field is a field that can
be filled by a later edit, and the assertion "no read path can carry it" then depends on a value
rather than on a shape. This is the same argument `test_no_schema_property_or_parameter_exposes_a_stored_body`
already makes for call-ledger's body store.
Reversibility: **cheap** to keep; **irreversible** in the other direction — a secret that reached a
second response has reached whatever logged that response.

---

**Deliberate gaps this plan leaves.**

- **AC-05, AC-06 and AC-07 are Phase 9's, not this plan's.** This plan builds the mechanisms and
  asserts them at the module: the scope refusal carries no reason, revocation is immediate at
  `authenticate_api_key`, and the secret appears once. **The byte-identical comparison against the
  gateway's unknown-model response cannot be made here** — the gateway is Phase 19 — and
  `tests/security/test_key_scope_refusal_cannot_enumerate` is Phase 9's file with Phase 20 as its
  cross-module completion. Do not claim AC-05.
- **`last_used_at` is written off the critical path**, and this plan chooses the cheapest honest
  shape: it is not written at all in Phase 8, the column stays NULL, and the absence is documented at
  the column with the gateway's phase named. A write on every authentication is a write on the 5 ms
  path, and the lock calls the signal *weak* in its own words; building it now would be building the
  slow half of a weak signal before its consumer exists.
- **No rate limit on the key path.** There is none specified; A-147's T-M3 accepts the absence for
  authenticated management routes and the key path's defence is default-deny scope plus immediate
  revocation. Recorded so the absence reads as inherited rather than as an omission.

One module, two seams, one credential that must not escape it.

**`src/prope/access_control/domain.py` — two additions.**

`@dataclass(frozen=True, slots=True) class PresentedKey` with `key_id: str` and `secret: str`, and a
`__repr__` **overridden to omit the secret**. Write the reason at the override: a frozen dataclass's
generated `repr` puts every field in it, and the places a `repr` reaches — an exception's `args`, a
structlog value, a pytest assertion diff, a traceback in a log aggregator — are exactly the places
A-046 forbids. This is one method and it closes four leak paths that no allow-list can see.

`@dataclass(frozen=True, slots=True) class KeyIdentity` with `workspace_id`, `key_id` and
`scope: tuple[str, ...]` — INT-003's declared return, *"never the stored hash, never the key row"*.
The tuple rather than a list, for `VisibleSubjects`' reason: a caller that could append to a scope is a
caller that could widen one.

**`src/prope/access_control/keys.py` — new. Four public functions and one constant.**

```python
KEY_PREFIX = "prope_"
def parse_presented_key(presented: str) -> PresentedKey | None
async def authenticate_api_key(session, presented: str) -> KeyIdentity | None
async def may_resolve(session, key_id: str, model_name: str) -> bool
async def create_key(session, *, workspace_id, name, scope, created_by) -> tuple[KeyIdentity, str]
async def revoke_key(session, *, workspace_id, key_id, revoked_by) -> bool
```

**`parse_presented_key`.** Split on `_` into exactly three parts, refuse anything else, refuse a
missing prefix, refuse an empty `key_id` or `secret`, and return `None` — never raise. A `key_id`
that is not shaped like a `key_`-prefixed ULID is refused here rather than at the database, so a
malformed presentation costs no round trip. The docstring states the format's whole purpose (A-113,
ADR-0021): the id is embedded in the secret **so authentication is one indexed read plus one
constant-time comparison rather than a table scan**, and that is the property the 5 ms budget rests on.

**`authenticate_api_key`.** Parse; on `None`, count and return `None`. Call
`access.lookup_api_key(key_id)` on a plain session with **no tenant context** — that is what the
`SECURITY DEFINER` function exists for (ADR-0042): the key row is the read that *produces*
`app.workspace_id`, so it cannot be made under it. Then `hmac.compare_digest` **in Python**, and the
docstring must carry ADR-0042's sentence for it: *"the hash comparison stays in the application.
`lookup_api_key` returns the stored hash; it does not authenticate. A function that decided
authentication would be a security-definer object with a security decision inside it."*

Four more things at the code:

- **The dummy-hash branch.** When the lookup returns nothing, compare the presented secret against a
  module-level fixed hash of the same length anyway, then return `None`. One line, and it is the
  reason "no such key" and "wrong secret" do not separate on a timer. Same posture ADR-0043 requires
  of the login path for a tombstoned email, and the docstring should say the two are the same idea
  applied to the two credential types this module holds.
- **Revocation is checked here and is immediate.** `revoked_at IS NOT NULL` → `None`, on the very
  next call, with nothing invalidated because nothing was cached (A-114, ADR-0022). If Phase 7's
  function already filters revoked rows, note that at the branch instead of duplicating it.
- **`prope_access_control_key_auth_total`** with `result = ok | unknown | revoked` — the lock's exact
  closed set — and **`prope_access_control_key_auth_duration_seconds`** with an edge at **0.005**,
  because the budget is p95 < 5 ms and `histogram_quantile` interpolates inside the bucket holding the
  quantile. A malformed presentation counts as `unknown`; say so, because the vocabulary is closed at
  three and a fourth value would be a new series.
- **`key_id` joins `LOGGABLE_FIELDS`** in `src/prope/observability.py`, with the one-line
  justification the existing entries carry: it is an identifier from a `key_`-prefixed ULID space,
  the lock file names it as loggable in the same sentence that names the secret as not, and it is the
  only handle a support conversation about a misbehaving consumer has. **The secret is never added to
  anything.**

**`may_resolve`.** One read of `scope_model_names` for the key, membership test, return. Default-deny
is the shape: the function returns `model_name in scope` and there is no branch that could return
`True` on an empty scope. A revoked key returns `False`. **The docstring carries the refusal-shape
requirement even though this function does not render it** — a bare `bool` with no reason is what lets
the gateway answer a scope refusal byte-identically to an unknown model name (A-081, A-116), and a
future "helpful" reason added here is what would break a security requirement two modules away. Count
`prope_access_control_key_scope_refusal_total`; **the lock declares its label as `key_id` and that is
an unbounded label set** — declare it as the lock says, and record in the SUMMARY and in
`deferred-items.md` that this is the same class of finding as `OQ-030` (`workspace_id` on
property-history's gauge) and that Phase 9, which owns AC-05 and the module's observability sweep, is
where it is decided. **Do not raise a new OQ for it here and do not silently drop the label**; if
`tests/broker/test_publish_confirm_failures.py`'s project-wide walk goes red on it, that is the
finding, and the SUMMARY reports it rather than the walk being narrowed.

**`create_key` and `revoke_key`.** `create_key` generates the secret with
`secrets.token_urlsafe`, mints a `key_` ULID, stores **a fast hash of the secret** in the shape Phase 7's
column expects, stores `last_four` from the secret's last four characters, and returns the identity
plus the plaintext. The plaintext is a **return value and never a field on a stored object**.
`revoke_key` sets `revoked_at` and returns whether a row moved. Neither commits; the route's
`workspace_transaction` owns the boundary, exactly as `grants.py` does.

Write at `create_key`, in one paragraph: the secret is shown once and is not recoverable from the
database, so a dump yields no working key; `last_four` exists so a person can tell two keys apart in a
list and is deliberately four characters and not eight; and the hash is **not argon2** — ADR-0021 is
the record of why the two secrets in this one module use two different primitives, and a reader who
does not find that sentence here will assume one of them is a mistake.

**`src/prope/access_control/schemas.py`** gains `ApiKeyCreate` (`name`, `scope_model_names:

rule that quietly made every key useful.

**`src/prope/access_control/routes/keys.py` — three handlers.**

- `GET /workspaces/{id}/keys` → `ApiKeyPage`, `declares_action(KEY_READ)`, cursor-paginated through
  `PageRequest`. No event: a read is not a state change (A-044).
- `POST /workspaces/{id}/keys` → `201` with `ApiKeyCreated`, `declares_action(KEY_CREATE)`. Inside one
  `workspace_transaction`: `create_key(...)`, then `append(session, draft)` for `api_key_created` with
  `target_type='api_key'`, `target_id=<key_ ULID>`, `scope_prompt_id=None`, `details={}` — the seeded
  registry gives this action **no** detail keys, so a `details` payload of any kind aborts the
  transaction. State that at the call site so a later "let's record the scope" edit lands on the
  reason and on `OQ-047`'s precedent rather than on a red test.
