## D-277 — The forbidden edges are an AST import walk with the reasons quoted, not a layering tool

**Chosen.** `tests/architecture/test_registry_module_boundaries.py` walks every module under
`src/prope/prompt_registry/` with `ast` and asserts no `Import` or `ImportFrom` names
`prope.gateway`, `prope.release_control`, `prope.evaluation` or `prope.call_ledger`, under any spelling —
including a relative import that climbs out of the package. The four are written out as a literal
`FORBIDDEN_MODULES` mapping from module name to **the lock file's own reason, quoted**, so the failure
message is the argument rather than a rule:

| Module | The lock's reason, quoted |
|---|---|
| `gateway` | *"The dependency runs the other way. A registry that calls the gateway puts a management surface inside a latency-critical path."* |
| `release-control` | *"Would close the cycle that A-041 and ADR-0001 exist to break. The pointer is set by an inbound command; this module never asks who approved what."* |
| `evaluation` | *"The registry does not know what a pass is. Run results are read by release-control (A-042), never surfaced here."* |
| `call-ledger` | *"Registry has no business reading live traffic bodies; that read path is gated by OQ-013."* |

**Rejected: `import-linter` or another layering tool.** Release-control's own owed AC-14 asks for exactly
that — *"the import-linter layering contract fails the build on a cross-module model import"* — and it is
**phase 24's**, over the whole eight-module graph. Adding a dependency and a contract file here would
either duplicate that work or pre-empt a decision phase 24 owns, and ORCHESTRATION §5 lists adding
tooling as the thing to raise rather than to do. **Say this at the top of the file**, so phase 24 extends
a graph-wide contract rather than discovering a module-local test that half-does it.

**Rejected: asserting the edges at runtime** by patching `sys.modules`. It proves what one import order
did, not what the source says.

**The write boundary rides along**, because it is the same walk: every `text(...)` constant in the package
whose statement begins `INSERT`, `UPDATE` or `DELETE` must name a table in `registry.`. `data.owns` lists
two tables and `writes_tables_it_does_not_own: none`, and property-history's append — the one write this
module causes outside its own schema — goes through `append(session, event)` (ADR-0023), which is a
function call and not a statement in this package. **That distinction is the assertion**: a module that
started writing `history.history_event` directly would still satisfy every other test in the milestone.

**Reversibility: cheap.**
