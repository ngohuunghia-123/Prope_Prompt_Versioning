## D-273 — The search load condition is read pessimistically, in one workspace, for a grant-list actor, measured at the repository call

**Chosen**, and every one of the four choices is written into the test's docstring because
`OQ-084` records that the specification under-determines all four:

- **One workspace holds all 1,000 properties.** The tenant policy narrows the scan, so spreading the
  corpus across ten workspaces measures a tenth of the table. *"1,000 prompt properties"* against a
  product whose unit of tenancy is a workspace reads as *a workspace with 1,000 prompts*, and it is the
  harder of the two readings.
- **The two filters are `owner` and `tag`.** `owner_id` is high-cardinality and `tags` is an array column
  — the pair whose plan is least predictable. `status` + `access_level` would be two low-cardinality
  CHECK sets that the planner disposes of immediately, which measures nothing about the trigram index.
- **The actor's visibility is a grant list**, not `mode: all`. `mode: all` contributes an empty id array
  and costs nothing; a 500-element `ANY(:ids)` is the disjunct that actually appears in a real workspace
  and the one whose cost varies.
- **The p95 is measured at the repository call**, which is the span
  `prope_registry_search_duration_seconds` observes (phase 13's plan 13-04 put the observation there, and
  D-228 put `0.5` in its bucket edges *because* p95 < 500 ms is the target). Measuring through HTTP would
  fold in session lookup, `visible_subject_filter` and serialisation, and a later regression would be
  attributable to four things instead of one.

**The corpus is built INSIDE the test function, not in a fixture, and this is the trap.** The suite's
autouse truncate is **function-scoped** (`tests/conftest.py`), and phase 13's plan 13-01 extended its
table list to cover `registry`. A session- or module-scoped corpus fixture would therefore be emptied
between tests, and a p95 measured over an empty table passes in about a microsecond. Build it in the
test, measure in the test, and say so at the fixture that is not there.

**Rejected: the literal-minimum reading** — any workspaces, any filters, `mode: all`. It would pass on a
sequential scan, which makes it useless as the guard on ADR-0048's index.

**Rejected: measuring through the route.** See above; and it would also make the number
un-comparable with the metric that will report it in production.

**Reversibility: cheap** — but the *number* is not reversible information: whatever it measures is what
the milestone will be believed to have proved. Record the observed p95 in the SUMMARY.

## D-274 — The corpus is built with bulk SQL, and the trigger's per-insert cost is measured as its own number

**Chosen.** 1,000 properties × 20 revisions is **20,000 revision inserts**, and every one of them fires
`registry.compose_search_text` on the parent (ADR-0048). Building that through `create_revision` would run
the whole command path — an id mint, two A-050 checks, a history append, a metric observation — twenty
thousand times, and the corpus build would dominate the test's wall clock without measuring anything the
test claims.

So the corpus is built with `executemany` over the raw `INSERT` statements
`tests/prompt_registry/__init__.py` already holds, as the owner through `migrate_engine`, in batches. The
trigger still fires — it must, or `search_text` is empty and the search measures nothing — and the test
asserts that afterwards: a sampled property's `search_text` contains a phrase from its latest body.

**And the trigger's cost gets its own small measurement**, because it is a number this milestone
otherwise does not have and it is the one that will matter when somebody proposes indexing more: time 100
of those inserts, report the per-insert mean in the SUMMARY, and assert nothing about it. A measurement
with no threshold is honest; a threshold invented here would be a budget nobody agreed.

**Rejected: building the corpus through the command path.** See above.

**Rejected: skipping the revisions and inserting only properties with a hand-written `search_text`.** It
would halve the build time and it would measure a `search_text` this project's trigger did not produce,
which is the one thing the whole ADR-0048 stack is about.

**Reversibility: cheap.**

## D-275 — The lost connection is a real terminated backend, not a raised Python exception

**Chosen.** `tests/chaos/test_registry_connection_lost_mid_create.py` opens a `create_revision` in one
session, and from a **second** connection (as the owner, through `migrate_engine`) issues
`SELECT pg_terminate_backend(pid)` against that session's backend pid, obtained from `pg_stat_activity` or
from the session itself. Then it asserts, from a third connection, that **no revision row** and **no
history event** exist for that prompt.

**Why not a monkeypatched raise.** `test_plan.chaos` clause 3 says *"database connection lost mid-create;
assert no orphan revision and no orphan history event"*, and the guarantee under test is that the revision
and its `property_history` append share a transaction (ADR-0023 — property-history is a library in the
caller's transaction, not a service). A raised Python exception exercises **SQLAlchemy's** rollback, which
is a different code path from **the server** discarding an in-flight transaction when its backend dies.
Phase 13's plan 13-02 already asserts the first — it makes `append` raise and checks neither row lands —
and phase 13's own `deferred-items.md` §4 says so and routes this here precisely because it is the half
that was not provoked.

**The recovery half is asserted too**, because a chaos test that leaves the pool poisoned is a chaos test
that breaks the next twenty: after the kill, a fresh `create_revision` on a new session **succeeds**. The
engines use `NullPool` (`tests/conftest.py`) so nothing is carried across, which is what makes this cheap
and is worth a sentence at the assertion.

**Reversibility: cheap** on the test; **costly on the run if the restore is not asserted**, which is why
it is.

## D-276 — Chaos clause 1 is asserted in its rewritten form only, and the literal form is refused in writing

**Chosen.** `test_plan.chaos`'s first clause reads *"provider-access unavailable during editor open"*. The
lock file's own amended `failure_modes` row deletes the premise:

> ADR-0026 and ADR-0033 put prompt-registry and provider-access in THE SAME PYTHON PROCESS in the same
> container … There is no state in which provider-access is unavailable and this module is not; if it is
> down, the process is down.

and rewrites the scenario as **a failed upstream catalogue refresh**, with the mitigation *"A revision may
be saved reusing the previous revision's binding … Degraded, not blocked."* PITFALLS gap 2's standing
instruction covers exactly this shape: *"Each phase's plan must use the restated form, not the lock
file's literal text."*

So `tests/chaos/test_registry_degraded_catalogue.py` asserts the rewritten form: with
`get_model_catalogue` returning a **stale or empty** list, a new revision reusing the previous revision's
`provider_config_id` and `upstream_model` **still saves**, and existing revisions still resolve. And the
module docstring **states the refusal**: the literal clause was not asserted, here is the lock's own
paragraph deleting its premise, and here is PITFALLS gap 2. A skipped clause with a written reason is a
decision; a skipped clause with no reason is a hole.

**Rejected: asserting the literal form by monkeypatching `get_model_catalogue` to raise.** It would pass,
and it would be a test of a state the architecture makes impossible — which is worse than no test, because
it would be cited as coverage.

**Reversibility: cheap.**

**The corpus**, built through the real commands in one workspace:

**AC-10 end to end** — the two matches `tsvector` cannot make, through `GET /api/v1/prompts`:

1. `q=thentic` returns P-AUTH. An infix, which `tsvector` cannot match at all — only a prefix via `:*`.
2. `q=refund` returns P-REFUND, whose model name is `support/refund-classifier`. The default text-search

   types into this search box."*
3. `q=tieu de` returns P-VN, and `q=tiêu đề` returns P-VN. Both directions, because folding one side only
   passes the first and fails the second.

route adds is that the composition did not drop the keyword predicate — which is the failure a
repository-level test cannot see.
