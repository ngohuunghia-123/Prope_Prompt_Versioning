## D-264 — The corpus is serialized response BYTES from every route in the census, with a positive control on every path

**Chosen.** `tests/security/test_search_text_never_returned.py` drives every entry in
`REGISTRY_READ_ROUTES` (plan 15-01's written-out census) plus `GET /api/v1/prompts` — the list route,
which is not in the refusal census because it names no subject, and which is **the single most important
path here** because it is the one a `SELECT *` would ruin. Each response's `body` bytes go through one
scan function.

**Every scanned response carries a positive control**, asserted in the same test: the response is
non-empty, its status is what the path is supposed to return, and it contains a marker that **should** be
there — the prompt's title on a list page, its `version_id` on a revision read, an event's `seq` on the
activity read. Phase 12's D-205 established this posture for the credential sweep and the reason is the
same: a scan over an empty body, a 401, or a 404 passes trivially, and the failure looks identical to
success from the outside. `tests/security/__init__.py`'s own docstring already requires it of every test
in the package.

**Rejected: scanning a parsed response.** Phase 12's D-205, quoted rather than paraphrased: *"Parsing is
the application's own account of what it sent"*. A field serialized under an alias, a model that renders
an extra key on a `by_alias` path, a `model_dump()` that includes a private attribute — every one is
visible in bytes and invisible in a dict comparison.

**Rejected: asserting the serialised key set.** That is the allow-list SC3 rules out by name.

**Reversibility: cheap.**

## D-265 — Three markers, not one, because the stored copy is folded

**Chosen.** The scan looks for three things in every response body:

1. **The raw phrase** — a distinctive multi-word string written into a prompt's latest revision body and
   nowhere else (`"marmoset consortium reconciliation"` or similar: no natural-language collisions, no
   substring of any field name).
2. **The folded phrase** — the same string after `public.unaccent(lower(…))`, which is the form
   `registry.compose_search_text` actually stores (ADR-0048, A-150). Include a phrase with a diacritic
   and a `đ` (`"phiếu đổi trả"`) so the folded form genuinely differs from the raw one; if the two are
   identical the marker is doing no work and the test says so.
3. **The literal key `search_text`**, at any depth, matched as the JSON key `"search_text"` in bytes.

**Why three rather than one.** A leak can arrive in two shapes and they look different on the wire. A
`SELECT *` that widened a model leaks the **stored, folded** document under the key `search_text` — marker
2 and marker 3. A well-meaning "searchable summary" field added by a later phase leaks the same text under
a different key — marker 1 and marker 2. And a response that echoes a caller's search term back leaks
neither and is not this criterion's problem. One marker would catch one of the two shapes and the choice
of which would be arbitrary.

**The change summary is a fourth marker and is deliberately NOT one.** `search_text` also folds in every
revision's change summary, and change summaries **are** legitimately returned by the revision list route.
A marker on them would fail on correct behaviour. Say this at the marker set: the corpus is
`title | purpose | tags | latest body | every change summary`, and only the body half is forbidden in a
response. That asymmetry is the reason the markers are body phrases rather than "anything in
`search_text`".

**Rejected: reading `search_text` out of the database and searching for it whole.** It contains the title,
which every list response legitimately returns, so the assertion would fail on correct behaviour. The
marker has to be a substring only the body contributes.

**Reversibility: cheap.**

## D-266 — The contract is scanned as well as the responses, because absence from a fetched response is a weaker claim than absence from the surface

**Chosen.** `tests/architecture/test_registry_response_models.py` asserts two structural things the
byte scan cannot:

1. **No pydantic model reachable from `src/prope/prompt_registry/schemas.py` declares a `search_text`
   field.** Discovered by walking the module for `BaseModel` subclasses and reading `model_fields` —
   never from a written-down model list — and checking both the field **name** and any `alias` /
   `serialization_alias`, because a field aliased to something else still carries the value.
2. **`app.openapi()` contains no component schema property named `search_text`.** The application is built
   with `openapi_url=None` (the schema is generated at build time, not served — `create_app`'s docstring
   says why), but `app.openapi()` still builds it, and `tests/architecture/test_route_table.py` already
   walks it for exactly this reason.

**Why both.** The byte scan proves the field was absent from the responses the test fetched. The contract
scan proves it is absent from the **surface**, including the routes a test forgot and the response
branches a fixture did not reach — an error model, a partial-update echo, a paginated envelope.

**Rejected: relying on the byte scan alone**, on the grounds that the census is complete. The census is
complete *today*, asserted against the assembled route table by plan 15-01. The contract scan is what
covers the response a route returns on the branch nobody exercised.

**Reversibility: cheap.**

1. **What `search_text` is**: title, purpose, tags, the **latest** revision's body, and **every**

**The constants.**

```python
BODY_PHRASE_FOLDABLE = "phiếu đổi trả nội bộ"
```

```python
async def folded(connection, phrase: str) -> str:
```

**The scan.**

```python
def assert_absent(body: bytes, *, markers: Sequence[bytes], where: str) -> None:
```

**The scan.** For every route — `REGISTRY_READ_ROUTES` plus `GET /api/v1/prompts` — issue the request as

1. `assert_present` on the path's own control marker (title on the list, `version_id` on a revision read,

Then the four cases a route-by-route sweep would miss:

3. **The list route with the keyword parameter set to the body phrase.** This is the path where a

   search column in scope, because the developer was holding it in their hand. Assert the prompt **is**
   returned (the keyword matches, because the body is in the corpus) and that the response body carries
   none of the three markers. That pairing — the match works, the document does not come back — is the
   single sharpest assertion in this plan.
4. **Pagination.** Request the list with the smallest page size the API permits and follow the cursor to
   the end, scanning every page. A leak on page two is a leak.
5. **The refusal bodies.** A `404` (an invisible or nonexistent prompt), a `422` (a malformed cursor or an

   `repr` of a row is a leak that no successful response would ever show. If the `500` cannot be provoked
   without editing `src/`, monkeypatch the repository function the handler calls — that is a test seam,
   not a bypass — and say so at the test.
6. **The captured log records.** Attach a structlog capture around the whole sweep and assert none of the
