<objective>
Make a leaked key useless as a map, and make a revocation true the moment it commits.

These are SC2's two halves and they fail in opposite directions. A scope refusal that is *shaped*
differently from an unknown model name turns every consuming product's key into a registry enumerator:
try a name, watch which refusal comes back, learn what exists. A revocation that takes effect *later*
turns an incident-response action into a promise — and ADR-0022 spends five rejected alternatives on
exactly that distinction: *"A stale released pointer serves an approved revision one TTL late … A stale
permission answer serves a **revoked** credential."*

**D-138 — The list of things nobody may cache is a declared tuple in source, and the test reads it.**

AC-6's second clause is *"no code path in any module returns a cached allow."* That is an assertion
about an **absence**, across a codebase that will grow to eight modules, and an absence asserted by a
test holding its own hardcoded list of function names is an absence that stops being asserted the day a
sixth seam appears.

Chosen: `src/prope/access_control/keys.py` gains

```python
#: The seams no caller may memoise, by name. ADR-0022 and A-114.
NEVER_CACHED = ("authenticate_api_key", "may_resolve", "may",
                "visible_subject_filter", "authenticate_session")
```

and `tests/security/test_nothing_caches_an_access_answer.py` reads it. **Two** assertions follow, and
the second is what makes the first honest: the walk asserts no caching of anything named in
`NEVER_CACHED`, **and** a separate assertion compares `NEVER_CACHED` against the five `internal:`
lines in `docs/modules/access-control.lock.yml`'s `apis.exposes` — so a seam removed from the tuple
fails, rather than silently narrowing the walk. That is the shape Phase 5's
`test_event_vocabulary_matches_the_locks.py` established for the same problem.

Rejected: **a decorator (`@never_cached`) on each seam.** A decorator is a runtime object, and the
assertion needed is about source text in *other* modules that do not import the decorator. It would
also add a wrapper on the one path with a p95 < 5 ms budget.

Rejected: **an import-linter contract.** release-control's owed AC-14 introduces `import-linter` at
Phase 24 and nothing here should pre-empt that choice; and a layering contract cannot see
`functools.lru_cache`, which is the thing being forbidden.

Reversibility: **cheap.**

**D-139 — Indistinguishability is asserted at the seam as *same value, same exception, same timing
envelope*, and the byte comparison is routed to Phase 20 by name.**

AC-5's text is *"the gateway's response is byte-identical to its response for a model name that does not
exist."* The gateway is Phase 19 and GATE-10 is Phase 20. `may_resolve` returns a bare `bool` and does
not render anything.

Chosen: this plan asserts the three properties that make the byte-identity *achievable*, at the seam,
and states that it is doing so:

1. **Same value.** `may_resolve(key, an_out_of_scope_released_name)` and `may_resolve(key,
   a_name_that_exists_nowhere)` both return `False`.
2. **Same absence.** Neither raises; neither returns a subclass, a tuple, an enum or anything a caller
   could branch on; and a source-level assertion that the function body contains exactly one `return`
   of a membership test and no `if` that varies the returned object by cause.
3. **Same timing envelope.** Medians within a factor of two over five samples each. `may_resolve` reads
   one column and does a membership test, so both causes do identical work — the assertion exists so
   that a later "look the name up first to give a better answer" change fails a test rather than passing
   review.

Rejected: **asserting nothing until Phase 20.** The three properties above are the ones a Phase 19
implementer would break, and by then the break is two modules away from the test that would have caught
it.

Rejected: **shipping a shared renderer here that the gateway will call.** Access-control does not render
OpenAI's error shape (A-026, INT-022, ADR-0050) and a renderer living here would be an access-control
symbol on the gateway's response path — the wrong direction and a second place the shape is decided.

Reversibility: **cheap.**

Seed: a workspace, a key scoped to exactly one model name `m-in-scope`, and a second model name

**`tests/security/test_nothing_caches_an_access_answer.py` — three assertions and a control.**

**Assertion 1 — the AST walk.** Parse every `.py` file under `src/prope/` with the standard library
`ast` module, in `test_no_sql_interpolation.py`'s exact posture (walk the tree, do not maintain a
hand-written module list, and carry a vacuity guard asserting the walk visited at least one file and
found at least one call). For each module, flag:

- any `functools.lru_cache`, `functools.cache` or `functools.cached_property` decorator on a function
  whose name is in `NEVER_CACHED`, **or** on a function whose body contains a call to a name in
  `NEVER_CACHED`;
- any `async def` or `def` whose body both calls a `NEVER_CACHED` name and performs a subscript
  assignment into a module-level or instance-level container (`self._x[...] = ...`, `_X[...] = ...`)
  in the same function — the hand-rolled memo, which is what a cache actually looks like when nobody
  imports `functools`;
- any `aiocache`, `cachetools`, `async_lru` or `TTLCache` import anywhere under `src/prope/`. None is
  in `pyproject.toml`; the assertion exists so that adding one is a failing test rather than a
  dependency review nobody scheduled.

**Say at the walk what it cannot see**, because a test that overstates its reach is worse than none: a
cache reached through `getattr`, a cache in a dependency, or a cache one function-call away from the
seam call. This is a **source-level absence proof over the shapes a cache takes in this codebase**, and
the behavioural complement is Task 3 plus `tests/integration/test_revocation_is_immediate.py`. Write
that sentence in the module docstring.

**The three things the walk must NOT fire on**, each with a named exemption and a written reason —
because an exemption list that is asserted is a decision and a silently-narrowed walk is a bug:

- `src/prope/access_control/rate_limit.py` — a dict keyed on `(bucket, key)` holding attempt
  timestamps. It holds **no answer**: ADR-0043 says so in the ADR itself and plan 09-02 says so in the
  module docstring, and the exemption's reason is that a structure that can only produce a *denial*
  cannot produce a stale *allow*.
- The gateway's 30 s resolution cache (ADR-0012), when it arrives at Phase 19-20. It caches a
  **released pointer**, not a permission answer, and the whole of ADR-0022's reasoning is that the two
  are different kinds of wrong. Add the exemption **now**, keyed on the module path, with the reason
  and with a comment saying it is expected to become live at Phase 20 — so the Phase 20 executor finds
  a decision rather than a red test.
- `src/prope/property_history/registry.py` (or wherever ADR-0038's process-lifetime action-registry
  cache lives). It caches a **vocabulary**, which is immutable for the process lifetime by decision.

Each exemption is a row in an `ALLOWED_CACHES` mapping from module path to reason string, and a fourth
assertion asserts every key in it **exists on disk** — an exemption naming a file that has been renamed
is an exemption that has silently stopped exempting anything and is now just a dead line.

**Assertion 2 — the declared list is the specification.** Parse
`docs/modules/access-control.lock.yml`, take the `apis.exposes` entries beginning `internal:`, extract
the five function names, and assert the set equals `NEVER_CACHED`. Same posture Phase 5 used for the
event vocabulary. If the parse is fragile, hardcode the five and **cite the lock file's line numbers at
the literal**, which is `EXPECTED_ROUTES`' posture.

**Assertion 3 — the mutation control.** In a `tmp_path`, write a small module that decorates a function
named `may_resolve` with `functools.lru_cache`, run the walk's checker function against that path, and
