<objective>
Finish `read()` and prove ROADMAP **SC3** — *"`read()` is ordered by `seq` descending and never by
timestamp, and performs no permission check."*

Plan 05-01 built one scope so the tracer had a path. This plan builds the other two, the cursor, the
bounds and the two refusals, and then asserts the three properties SC3 names in the forms that can
actually fail: an order the clock contradicts, an order two concurrent commits contradict, and an
absent permission check proven by an import walk rather than by reading a signature.

**Why an import walk is the right proof for "performs no permission check".** A signature review
proves that `read()` has no actor parameter today. It does not prove that a later phase cannot reach
access-control from inside the module — and that is the actual threat, because the person who does it
will be somebody reasonable who wants an audit screen (T-023, and the lock says so twice). The module
declares `dependencies: []`, and that declaration is a statement about `src/prope/`. Making it an
`ast` walk turns *there is nothing to check with* into a checked property.

**D-71 — the cursor is the opaque `hev_` event id, resolved to a `seq` before the page, and an
unresolvable one raises.**
Chosen: `cursor: str | None`, holding an event `id`; one statement resolves it to that event's `seq`
within the scope's workspace; the page statement then filters `seq < :before_seq`. An id that resolves
to nothing raises `HistoryCursorUnknown`.
Rejected: **`str(seq)` as the cursor.** It needs no resolution statement, and it is a cross-tenant
oracle: `seq` is a single global identity sequence, so a cursor rendered into an Activity URL tells its
holder roughly how many events the whole installation has written and how fast. On the one table that
never shrinks (A-121), that is a volume estimate anyone with one workspace can take of every other. It
also breaks A-045's *"the cursor is opaque and the client must not construct one"* in the most literal
way available — a decimal integer invites arithmetic.
Rejected: **resolving the cursor inside the page statement as a scalar subquery.** `seq < (SELECT seq
… WHERE id = :cursor)` is one round trip instead of two, and an unknown id makes the comparison NULL,
which returns **zero rows silently** — a page that reads as *the trail ended here*. ORCHESTRATION §3's
standing rule is *never zero; a refusal names what is missing.*
Cost, stated: a cursored page costs two statements where a first page costs one. Both are index
lookups on a `bigint` and a `text` primary key.
Reversibility: **costly** — the cursor becomes a value in a rendered URL from Phase 15 on.

**D-72 — `read()` refuses a scope whose `workspace_id` disagrees with the session's tenant, and
refuses a session with no tenant at all.** See the `checkpoint:decision` in Task 2, which carries both
options. Adopted: **refuse, by raising `HistoryScopeMismatch`, and pay for the diagnosis only on the
empty path.** `adopted: UNCONFIRMED`. Reversibility: **cheap.**

**D-73 — three frozen scope dataclasses and one statement each, dispatched with `match`.**
Chosen: `PromptScope`, `TargetScope`, `ActorScope`, a `Scope` union alias, and three module-level
`text()` constants each carrying a `#:` block naming the index it is written for.
Rejected: **one dataclass with three optional field groups.** It admits
`Scope(workspace_id=…, scope_prompt_id=…, actor_id=…)`, which names no declared read shape, matches no
index, and has no defined meaning — and the branch that silently picks one of the three is the branch
nobody reviews. INT-007 says *"one of"* three shapes and the type should say the same.
Rejected: **a `dict` scope.** A typo becomes a full-workspace scan rather than a `TypeError`.
Rejected: **one statement with three self-switching-off predicates**, in `PRICE_ROWS`' shape. That
pattern earns its place there because the two reads *"differ only in a predicate and a duplicated
projection is two places for the derived range to drift"*. Here the three reads differ in **which
index they are written for**, and a single statement with three optional predicates gives the planner
one shape to guess at instead of three to match. The projection is duplicated; the access path is the
thing being specified, and it is the thing worth three constants.
Reversibility: **cheap.**

**D-74 — the ordering proof is *inverted* timestamps and *interleaved commits*, not identical
timestamps.** Phase 4's AC-4 already asserts that two events sharing a timestamp order by `seq`, which
proves `seq` is a **tiebreak**. It does not prove `seq` is the **sort key**: an implementation ordering
by `occurred_at DESC, seq DESC` passes it. This plan asserts the two cases that separate them —
timestamps that run backwards against `seq`, and a lower `seq` committing after a higher one. Rejected:
re-asserting identical timestamps here, which would duplicate a Phase 4 test and prove nothing new.
Reversibility: **cheap.**

**D-75 — `dependencies: []` becomes an asserted import walk.**
Chosen: an `ast` walk over every module under `src/prope/property_history/`, asserting that every
`prope.*` import is in a closed allow-list, that `fastapi` appears at no depth, and that the walk found
modules to inspect at all.
Rejected: **leaving it to `grep` in an acceptance criterion**, which is what Phase 4 did for the
FastAPI half. A criterion is checked once, by the executor, on the day the plan runs; a test is checked
on every run for the remaining nineteen phases, which is the interval over which the tempting edge
actually gets added.
Reversibility: **cheap.**

**`domain.py` — two more scope classes and the union.**

```python
@dataclass(frozen=True, slots=True)
class TargetScope:
    workspace_id: str
    target_type: str
    target_id: str
    KIND = "target"


@dataclass(frozen=True, slots=True)
class ActorScope:
    workspace_id: str
    actor_id: str
    KIND = "actor"


Scope = PromptScope | TargetScope | ActorScope
```

Each docstring names the INT-007 shape it is, the index it will be read on, and the screen it backs —
`TargetScope` is release-control's decision trail and provider-access's configuration activity;
`ActorScope` is *a person's actions*, which **no module's `outputs` block names a screen for**, and
whose declared consumer inside this repository is AC-9 in Phase 6. Say that at `ActorScope` rather than
leaving a reader to wonder why it exists: it is in the lock's `apis.exposes`, it has an index, and its
absence would make AC-9 unanswerable.

`Scope`'s alias comment carries D-73's rejected alternative in one sentence — a single dataclass with
optional field groups would admit a scope naming no declared read shape and matching no index, and the
branch that picks one of three from a half-filled object is the branch nobody reviews.

Two new exceptions, beside `HistoryAppendRejected` and in its register (`# noqa: N818` with the same
kind of comment explaining the suffix choice, if ruff asks for one):

- `class HistoryCursorUnknown(Exception)` — fields `cursor: str`, `workspace_id: str`. Its message
  names the cursor and says the event does not exist in this workspace. Docstring: this is raised
  instead of returning an empty page, because an empty page reads as *the trail ended here* and this
  table's whole product claim is that the trail does not end. A cursor that stops resolving is one of
  exactly two things — a client that constructed one (A-045 forbids it) or a cursor from another
  workspace — and both deserve a name.
- `class HistoryScopeMismatch(Exception)` — fields `scope_workspace_id: str`,
  `session_workspace_id: str | None`. Message names both, or names the absence when the session
  carries none. Docstring: see D-72 and Task 2.

**Neither is a `RejectionReason`.** State it: that enum is the closed three-member label set of

**`read.py` — two more statements and the dispatch.**

`READ_BY_TARGET` and `READ_BY_ACTOR`, same projection, same `before_seq` disjunct with the same cast,
same `ORDER BY seq DESC LIMIT :limit`, differing only in their predicates:

```
WHERE  workspace_id = :workspace_id
  AND  target_type = :target_type
  AND  target_id = :target_id
```

```
WHERE  workspace_id = :workspace_id
  AND  actor_id = :actor_id
```

Each gets a `#:` block naming its index —
`ix_history_event_workspace_id_target_type_target_id_seq` and
`ix_history_event_workspace_id_actor_id_seq` — and the read shape the lock declares it for. On
`READ_BY_ACTOR`, add the sentence AC-9 will need: `actor_id` is a **value and not a foreign key**
(A-122), so a person removed from the workspace still matches every event they caused and nothing
cascades — which is exactly why ADR-0054's tombstone cost this module nothing.

The three-way dispatch is one `match` in `read()`, returning `(statement, parameters)`:

```python
match scope:
    case PromptScope():  ...
    case TargetScope():  ...
    case ActorScope():   ...
    case _:
        raise TypeError(...)
```

The `case _` arm is not defensive noise and its comment says why: `Scope` is a union of three concrete
classes, so a fourth would be a new declared read shape — and a `TypeError` naming the object is what a
caller passing a `dict` or a half-built scope meets, instead of a full-workspace scan.

```python
async def seed_history_events(migrate_engine, rows: Iterable[Mapping[str, object]]) -> None: ...
```

phase assert how many round trips a read costs (Task 2's empty-path diagnosis, Task 3's cursored page,

```python
@contextmanager
def counting_statements(engine: AsyncEngine) -> Iterator[list[str]]: ...
```

`sqlalchemy.event.listens_for(engine.sync_engine, "before_cursor_execute")` appending each statement,

**The decision.** `read()` is handed a session whose tenant the *caller* set, and a scope whose
`workspace_id` the *caller* chose. Nothing stops the two disagreeing. Under RLS the disagreement is
already contained — the policy predicate and the explicit predicate are both `workspace_id = …` and
they cannot both be satisfied — so no row from the wrong workspace can be returned. The question is
what the caller sees.

<checkpoint:decision>

**Option A — return an empty tuple and let RLS be the whole answer.**
*Pros:* one statement, no diagnosis, no new exception type. It is literally what INT-007 says about
the backstop, and it is what every other read in this project does.
*Cons:* an empty Activity screen is indistinguishable from *nothing has happened to this prompt*. On
this table, that is the single worst thing a wrong answer can look like: A-121 keeps every event
forever precisely so that the answer to *what happened* is never "nothing", and the lock's own
`failure_modes` rate the silent-but-complete-looking screen as the only failure here that is *"silent
in the direction that matters"*. It also leaves the lock's *"cannot construct a cross-workspace read
even by supplying the wrong ids"* as a statement about rows returned rather than about reads
constructed — the caller **did** construct it and got a plausible answer.

**Option B — refuse, by raising `HistoryScopeMismatch`.**
`read()` compares the scope's `workspace_id` against `current_setting('app.workspace_id', true)` and
raises when they differ or when the setting is absent.
*Pros:* the refusal names what is wrong, which is the standing project rule. It also catches the
adjacent and more likely mistake: a caller that opened a **plain session** instead of a
`workspace_transaction` — today that returns zero rows for every scope, forever, and looks like an
empty audit log. And it makes the lock's containment sentence true as written.
*Cons:* one extra statement. **Where it is paid decides whether this is affordable**, and the naive
placement — a `SELECT current_setting(...)` before every read — costs a round trip on every render of
every Activity screen and makes AC-3's *"returned in one query"* literally false.

**Reversibility: cheap.** One function, one exception class, no data consequence.

**ADOPTED: Option B, with the diagnosis on the EMPTY PATH ONLY. `adopted: UNCONFIRMED`.**

The refinement is what makes it affordable and it is the whole of the adoption:

1. Resolve the cursor, if one was supplied. (One statement; already required.)
2. Run the page statement.
3. **If it returned rows, return them.** A row proves the tenant matched — the policy would not have
   let it through otherwise — so there is nothing left to diagnose and the cost is zero.
4. **Only if it returned nothing**, run `SELECT current_setting('app.workspace_id', true)` and decide:
   the setting is absent → raise `HistoryScopeMismatch` naming the absence and
   `workspace_transaction`; the setting disagrees with the scope → raise naming both; the setting
   agrees → return the empty tuple, which now means what it says.

So a populated read is **one statement**, an empty read is two, and the second one runs exactly where
latency does not matter and where *why is this empty* is the only question anyone has. The cost is
recorded rather than hidden: a prompt with genuinely no events pays one extra round trip per render.

</checkpoint:decision>
