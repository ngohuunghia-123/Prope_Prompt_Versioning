helper, so there is one definition of what "the table" is.

**Reversibility: cheap.**

## D-85 — the framework-absence check is a subprocess import, not only an AST walk

**Chosen.** Two checks, and both ship. An `ast` walk over every module under
`src/prope/property_history/` for a direct `import fastapi` / `from fastapi import ...`; **and** a
child interpreter that imports every module in the package and then asserts `"fastapi" not in
sys.modules`.

**Rejected: the AST walk alone.** It sees direct imports and nothing else. The lock's wording is *"at
no depth"*, and depth is precisely what an AST walk cannot see: a module that imported a helper that
imported FastAPI would pass the walk and fail the property.

**Rejected: the runtime check alone, in-process.** By the time this test runs, `prope.app` has been
imported by another test module and `fastapi` is already in `sys.modules`. The check would pass in a
fresh session and fail in a full run, or vice versa, depending on collection order — which is worse
than not having it. A child interpreter is the only place `sys.modules` means what the assertion needs
it to mean.

**Cost, stated:** one `subprocess.run` per test session, roughly an interpreter start. Phase 6 already
starts child interpreters in `tests/chaos/`, so the mechanism is not new to the suite.

**Reversibility: cheap.**

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the assembled application -> the network | Any mounted path is reachable from Caddy's single ingress. A route that exists is a route somebody can call, and this module's read API performs no permission check and has no way to. |

| a test's claim -> what is actually true | An assertion about an absence is indistinguishable from an assertion that ran against nothing. This is the boundary Task 3 exists to police. |
