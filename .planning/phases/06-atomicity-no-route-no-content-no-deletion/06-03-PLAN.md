lock file says exactly this — the allow-list stops *code* from putting content in fields and *"cannot
stop a person typing it into a free-text box"*, and what is mitigated for the human case is blast
radius rather than occurrence.

## D-86 — `request_id` joins `LOGGABLE_FIELDS`; the Broken Window is closed by adding the name

**Chosen.** `request_id` is added to `LOGGABLE_FIELDS` in `src/prope/observability.py`, with a comment
naming it as ADR-0003's error-envelope correlation id — an identifier minted in
`schemas.py`'s refusal renderer and written to both the response and the log line so that a client
reporting an unexpected refusal can be found by a value it is holding.

**Rejected: an `ALLOWED` entry in the gate for `schemas.py:442`.** An exception for a field that is
plainly an identifier is how an allow-list becomes a file of exceptions. The first entry is always the
easy one, and the gate's value is that its exception list is short enough to read.

**Rejected: removing the keyword from the log line.** That deletes the correlation id, which is the
whole usefulness of ADR-0003's envelope carrying one. The docstring four lines above that call already
argues A-046 for the same line; the omission was the allow-list not keeping up, not the call being
wrong.

**Consequence:** this plan edits a call-ledger file. That is the cross-phase edit Phase 4 declined to
make and routed here, and it is one word plus a comment. The executor also closes the Broken Window in
`.planning/WINDOWS.md`, in both the table and the JSON block, with `open_count` corrected.

**Reversibility: cheap.**

## D-87 — the gate walks the source and refuses the splat, rather than ignoring what it cannot see

**Chosen.** `tests/architecture/test_loggable_fields.py` parses every module under `src/prope/` with
`ast`, finds every call on a module-level structlog logger, and asserts each keyword argument name is a
`LOGGABLE_FIELDS` member. A call carrying `**kwargs` fails with a message naming the file, the line and
the reason.

**Rejected: a runtime capture over exercised paths.** Phase 4 already ships that half
(`tests/security/test_no_history_content_reaches_a_log_line.py`), and it is worth having — but a
runtime capture proves what the test happened to call. The refusal branches, the exception handlers and
the cold paths are exactly where a body ends up in a log line, and they are exactly what a runtime
capture does not reach.

**Rejected: ignoring the splat and documenting the blind spot.** A documented blind spot is a blind
spot. There are zero splat call sites under `src/prope/` today — every one of the current call sites
passes explicit keywords — so refusing the form costs nothing now and costs one refactor later, at the
moment somebody is about to make the gate unable to see their log line. If a splat is ever genuinely
required, it goes in `ALLOWED` with its reason, like every other exception in this repository.

**Reversibility: cheap** — one predicate and an empty exception list.

## D-88 — AC-8's "full pilot dataset" is a synthetic corpus of one event per registered action

**Chosen.** The corpus is one event per registered action — thirty-one rows as the vocabulary stands —
across two workspaces and two prompts, with **every** `detail_key` its registry row allows populated,
and a `reason` on the three actions that require one.

**Rejected: waiting for a real pilot dataset.** A-020 holds the line that no real corporate prompts
enter the pilot until OQ-006 and OQ-013 are answered, so the AC's literal precondition cannot exist
before the pilot — and the phase that owns the AC would ship it unasserted, which ORCHESTRATION §9
forbids. This is a declared deviation from the AC's wording rather than a disagreement with the spec:
A-020 is the spec, and it is what makes the literal reading unsatisfiable. Recorded in
`deferred-items.md` with the pilot named as where the corpus becomes real, not raised as an open
question.

**Rejected: sampling.** The corpus is thirty-one rows. A sample of a set that small buys nothing and
costs the reader a paragraph about statistical confidence.

**What makes it stronger than the literal reading:** a pilot dataset contains the events the pilot
happened to produce. This corpus contains one of **every** registered action with **every** allowed
key populated, which is the whole surface the allow-list governs — including the twenty-eight actions
seeded with an empty `detail_keys` whose correct behaviour is to refuse every key.

**Reversibility: cheap.**

Build the corpus, plant the markers, offer them, and scan every field of every row.

**The six markers, as a module-level mapping `FORBIDDEN_CONTENT`.** One per class the lock file names,
each a distinctive string that could not occur by accident, and each with a comment saying which class
it stands for:

- a **prompt body** — a multi-line string with the shape of a system prompt, containing the token
  `PROPE-MARKER-PROMPT-BODY`;
- a **fallback answer** — `PROPE-MARKER-FALLBACK-ANSWER`;
- a **provider credential** — an `sk-`-prefixed token, `sk-PROPE-MARKER-CREDENTIAL`, in the shape a
  provider API key actually takes, because a marker that does not look like a credential proves only
  that the code is not logging fields it knows are credentials;
- a **password hash** — `$argon2id$v=19$m=65536,t=3,p=4$PROPE-MARKER-HASH`, in argon2id's real
  encoded shape for the same reason (ADR-0029 makes argon2id the hasher);
- an **eval output** — `PROPE-MARKER-EVAL-OUTPUT`;
- a **`prope.variables` value** — `PROPE-MARKER-VARIABLE-VALUE`, paired with a *variable name*
  `customer_tier` that is deliberately allowed to appear.

**Test 1: `test_every_forbidden_marker_is_refused_by_the_allow_list`.** For each marker, open a
`workspace_transaction`, build a `HistoryEventDraft` for a registered action, and put the marker on a
`details` key that is **not** registered for that action — `body`, `answer`, `api_key`, `password_hash`,
`output`, `variable_value` respectively, one per marker so the key name is itself the thing a future
author would reach for. Assert `HistoryAppendRejected` is raised with
`reason is RejectionReason.UNKNOWN_DETAIL_KEY`, and assert the exception's rendered message contains
the offending **key name** and does **not** contain the marker — the lock's rule that a rejected append
names the key and never the value, which is by definition the least safe object on hand.

This test is what makes the rest of the file mean something: without it, a clean corpus proves only
that nobody tried.

**Test 2: `test_the_corpus_holds_one_event_for_every_registered_action`.** Build the corpus in one

- Load the registry through `load_registry(app_sessionmaker)`.
- For every registered action, write one event through the module's public write path with: the
  action's own `target_type`; a `target_id`; a `scope_prompt_id` for the actions whose target is a
