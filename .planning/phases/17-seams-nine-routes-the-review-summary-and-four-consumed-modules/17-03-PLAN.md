<objective>
Open the rest of INT-025 except the comparison. Seven routes: the four that read and write a prompt's
eval suites, the one that lists a named suite's versions, the poll, and the case page. **Four of the
seven are keyed on a `suite_id` or a `run_id` rather than a `prompt_id`, and for those the `SELECT`
joins to `registry.prompt_property` and returns the owner and the access level WITH the child — so a
not-found and a not-permitted come out of one statement, and the correct refusal becomes the cheap one
to write.** That is D-311, and it is 14-02's D-250 applied one module over: the route with no prompt id
in its path is the route where a handler is most likely to read the child first and check afterwards,
which is two round trips and a window in which the answer changes.

`PUT /api/v1/eval-suites/{suite_id}` answers **`201` with the NEW suite id and never `200`**. It calls
Phase 16's `save_next_suite_version`, edits none of Phase 16's writers, and appends `eval_suite_updated`
inside the transaction that inserts the version — property-history is the fifth consumed module and the
one whose absence is silent, because a missing append is a hole in the audit trail rather than a failed
request. `GET /api/v1/prompts/{prompt_id}/eval-suites/{name}/versions` ships with the suite name in the
path, percent-decoded exactly once by the ASGI server and compared to the stored value byte-for-byte:
two authorities write that path and one note in the same lock file forbids it, so the route list is
adopted and the contradiction is raised as **`OQ-092`** with its five consequences stated at the route
rather than discovered by a reviewer whose bookmark broke.

The phase's proof of the two refusal shapes lives here.
`tests/security/test_eval_refusals_are_not_found_or_named.py` asserts, over all seven routes, that a
nonexistent id and an id in another workspace produce **byte-identical** responses — structural, from
RLS returning zero rows, rather than arranged by a handler — and that a visible prompt with a missing
permission produces `403` with the permission in `details` and no renderable prose in `message`. The
byte comparison has one honest complication the plan names rather than hides: every refusal envelope
mints a fresh `request_id` (`src/prope/call_ledger/schemas.py:489`), so the assertion masks that one
value, proves the two masked values were different, and compares everything else.

Deliberately left open, with the plan that closes each. Route 6 (`POST /eval-runs`) is 17-01's and is
already mounted. Route 9 (the comparison), `get_review_summary`, `requires_acknowledgement` and the
rollup are **17-04's**. Pricing, `get_run_totals`, the three-valued `CostDelta` and the claim-time
ceiling are **17-02's**, in this same wave and in disjoint files. The 20-case end-to-end run and the two
p95 numbers are **17-05's**. **Phase 18 owns proving that no output text leaks for a private prompt
(EVAL-06); this plan owes route 8's shape, not that proof, and its test module says so in a docstring
instead of claiming it.** The same-workspace private prompt still answers `403` here where EVAL-06 will
require `404`, for the reason 17-01 recorded: this module reads visibility from RLS alone, D-311
declines `visible_subject_filter`, and the gap is routed to Phase 18 rather than papered over.
