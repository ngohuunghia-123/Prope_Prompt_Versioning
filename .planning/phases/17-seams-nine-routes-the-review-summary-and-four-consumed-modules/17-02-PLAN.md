## D-307a — the `WithheldReason` reconciliation: one enum, one home, seven members, and D-294's spelling wins

Two authorities describe the same enum and neither is a superset of the other.

| Concept | Phase 16, D-294 (lands first, on disk) | Phase 17, D-307 | Authority |
|---|---|---|---|
| a case ended in a dispatch error | `CASE_ERROR` | `case_error` | A-057 |
| a side has rows with no price row | `UNPRICED` | `unpriced_rows` | A-101, ADR-0019 |
| a side has rows the provider reported no usage for | `UNKNOWN_USAGE` | `unknown_usage` | A-101, ADR-0019 |
| the two sides are denominated differently | `CURRENCY_MISMATCH` | `currency_mismatch` | A-107 — no FX |
| there is no released revision to compare against | `NO_BASELINE` | `no_baseline` | A-060 |
| nothing on a side has been priced yet | `NOT_PRICED_YET` | *(absent)* | 16-CONTEXT D-292 |
| the rollup's total, because some suite withheld its own | *(absent)* | `suite_withheld` | A-062, D-308 |

**Adopted: seven members, in one `StrEnum`, with one definition site, and where the two disagree
D-294's spelling wins.** Three reasons, in descending weight.

1. **The value is already a wire code by the time this plan runs.** A `WithheldReason` member's *value*
   is what the SPA's catalogue keys off (ADR-0053). Phase 16 ships it, Phase 16's
   `tests/unit/test_cost_delta_arithmetic.py` pins it, and that test file is **not** in this plan's
   `files_modified`. Renaming `UNPRICED` to `UNPRICED_ROWS` would therefore be a cross-phase edit to a
   test this plan does not own, in order to buy a slightly more precise noun.
2. **`NOT_PRICED_YET` must survive.** 16-CONTEXT D-292 states plainly that Phase 16 ships runs
   completing with a NULL cost and a delta withheld *"for the reason 'not priced yet' rather than for
   A-057's reason"*, and that a Phase 16 test asserts **the code**. Dropping it to reach D-307's count
   of six turns a green Phase 16 test red for no gain.
3. **`SUITE_WITHHELD` must be added.** D-308's fold has no other member to take, and it is the one
   member this phase genuinely contributes.

So the set closes at **seven, not six**, and D-307's *"closed at six … and no seventh"* is a count this
plan does not meet. That is a reconciliation between two phase CONTEXTs, not a disagreement with
anything under `docs/` — **no OQ is owed**. The SUMMARY states which spelling won and why, as the
phase architect's requirement list demands.

**`suite_withheld` is the rollup's alone and 17-04 is its only writer**, and that is asserted rather
than asked for: Task 1's unit test collects the reasons `compute_cost_delta` produces across its whole
branch table and requires the set to equal `set(WithheldReason) - {SUITE_WITHHELD}`.

**Rejected: two enums, one per phase, with a mapping between them.** Two closed vocabularies for one
concept is two catalogues for the SPA and a translation layer whose failure mode is a reason that
renders as its own key.
**Reversibility:** costly — the values are wire codes Phase 23 renders.

## D-307b — `cost_delta_payload()` is the only serializer, and it ships in wave 2 so waves 3 and 4 have somewhere to route

The stated risk is precise: *"a pydantic response model with `amount: Decimal = 0` or an `or 0` in a
serializer turns 'we could not price this' into 'this costs the same'."* Wave 2 has no pydantic model
to test — 17-03 and 17-04 own those. Asserting on `dataclasses.asdict` alone would prove nothing about
what actually crosses the wire.

**Chosen:** `cost.py` ships `cost_delta_payload(delta: CostDelta) -> dict[str, str | None]`, returning
exactly three keys, with `amount` rendered as `str(amount)` and never `float(amount)`. Task 1's test
asserts on `json.dumps(cost_delta_payload(...))` for all seven members. Every pydantic model in 17-03
and 17-04 that carries a cost delta **constructs its field from this function** rather than declaring
three fields of its own; the SUMMARY records that obligation for the wave 3 and wave 4 executors.

**A decimal is a string over the wire, never a float.** `json.dumps` cannot encode `Decimal`, so the
alternatives are a string or a lossy binary float. A money figure that has been through a float is a
money figure nobody can reconcile with `ledger.workspace_spend`. This is a wire-shape decision Phase 23
renders, so it is **reportable** under ORCHESTRATION §6 and belongs in the SUMMARY's ledger section.

**Rejected: leaving serialization to the route models and asserting only the dataclass.** That is the
exact seam the risk names, left unguarded, with a test that would have passed.
**Reversibility:** costly for the string-vs-number choice, cheap for the function's home.

## D-317b — `price_run` lives in `pricing.py` and takes the binding it was dispatched against

`17-CONTEXT`'s `<specs>` sketches `async def price_run(sessionmaker, *, run_id, workspace_id) -> None`
in `src/prope/evaluation/runs.py`. Two changes, both stated rather than discovered:

**The home is `pricing.py`.** `runs.py` holds `submit_runs`, which is 17-01's, and `runs.py` is not in
this plan's `files_modified`. Two plans in two waves writing one module is the lost update
ORCHESTRATION §8 describes.

**The signature gains `provider_config_id` and `upstream_model`.** `EvalUsageRow` requires both and
neither is a column on `case_result` (16-CONTEXT's field list: `id, workspace_id, run_id, case_id,
outcome, assertion_results, output_content, latency_ms, input_tokens, output_tokens, error_code,
attempt_count, created_at`). They live on the revision's binding, which the executor **already holds**,
because it is what it dispatched against. Passing them in is A-030's rule stated as a signature: the
values priced are the values called. Re-reading `get_revision` at pricing time would be a second read
of a second thing that merely ought to be the same.

This is an internal signature inside one phase, not a registered seam — **no OQ**, recorded in the
SUMMARY.
**Reversibility:** cheap.
