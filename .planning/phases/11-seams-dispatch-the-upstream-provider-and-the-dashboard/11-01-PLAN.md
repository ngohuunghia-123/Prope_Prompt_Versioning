<objective>
Give provider-access the outbound seam it will live on for the rest of the build, proved on the
thinnest real path: one interactive dispatch composed from a `provider_config_id`, an upstream model,
generation parameters and messages, sent to **a real HTTP server over a real socket**, and returned as
a `DispatchResult` carrying the provider's response and its usage object.

The reason it is a socket and not a mocked transport is the criterion this plan owns. **SC3 — "a
dispatch that times out or 5xxs issued exactly one upstream request" — is a property of the HTTP
client's configuration, not of Prope's control flow.** Most clients retry something by default, and a
test that counts calls to a stubbed transport counts Prope's loop rather than the wire. So the count
is taken at the server that received the requests, and the assertion is arithmetic on a number the
server incremented.

---

**D-180 — `httpx`, one client per validated target, cached; not one client per dispatch.**

Chosen: `httpx` (ADR-0047 names it), with `upstream.py` holding a small cache of
`httpx.AsyncClient` objects keyed on **`(provider_config_id, scheme, host, port, validated_address)`**
and a TTL. Every dispatch runs the guard and looks the client up by the key the guard produced.

Rejected: **a fresh `AsyncClient` per dispatch**, closed at the end. It is the obviously correct-looking
option and it is what "construct the transport bound to the surviving address" reads like on first
pass. It pays a full TLS handshake — one to two round trips to a third party — on **every gateway
call**, inside a 50 ms added-latency budget of which this module's share is 10 ms of overhead plus the
upstream call. The handshake is upstream time rather than overhead, so it would not even show up in
the number this module is measured on, which is worse: it would spend the product's budget where the
module's own metric could not see it.

Rejected: **one process-wide client with the address passed per request through `extensions`.** httpx
pools connections by `(scheme, host, port)`, so a pooled connection opened to yesterday's resolution
would be reused for today's request. That is ADR-0047's hole rebuilt inside the connection pool, and it
is invisible — the guard runs, passes, and the bytes go somewhere else.

The cache key is what makes the chosen option faithful: **the validated address is part of the key**,
so a resolver that answers differently produces a different key, a different client and a different
pool. The guard still runs on every dispatch; only the socket is reused, and only when the answer has
not moved.

Reversibility: **cheap.** The cache is one dict behind one function.

**D-181 — The dispatch-time address guard ships in this phase; PA-11's assertions do not.**

Chosen: `address.py` ships now with the scheme allow-list and the non-global-range refusal, because
the alternative is an SSRF primitive open for two phases while a test suite drives it. The **rejection
policy is an injected predicate** with a production default, and phase 12 owns PA-11 — the save-time
refusal, the restated AC-11 with a resolver that answers public then private, and the assertion that
the connection went to the first answer.

Rejected: **shipping a permissive guard and letting phase 12 add the teeth.** A phase that leaves a
documented server-side request forgery primitive open, on the one module with outbound egress, in
order to keep a plan boundary tidy, has chosen the wrong boundary.

Rejected: **hard-coding a loopback exemption for tests.** The stub provider is on `127.0.0.1`, so
something has to give — but an exemption compiled into production code is a bypass that ships. The
predicate is a parameter with a production default; tests install a permissive one exactly as
`dependency_overrides` is used for `require_session`, and **this plan asserts the default refuses
loopback**, so the seam cannot hide the guard.

Consequence, stated: phase 12 must not build a second guard. If it finds this one insufficient it
replaces the predicate and the tests, not the module.

Reversibility: **cheap.**

**D-182 — `dispatch()` returns a value for every upstream condition and raises only for a caller
contract violation.**

Chosen: `dispatch(...) -> DispatchResult | DispatchError`. Every timeout, refusal, status and transport
condition becomes a `DispatchError` value. Exactly two things raise: an unknown `provider_config_id`
(a caller bug — the id came from a revision the caller resolved) and a dispatch issued from a process
that installed no admission gate.

Rejected: **raising a typed exception hierarchy** and letting callers catch. INT-015 is explicit —
*"Returns a typed `DispatchError`, never raises on upstream failure"* — and it says why: two consumers
branch **oppositely** on the same failure (the gateway serves a fallback, evaluation records a run
error), and an exception makes the branch a `try/except` whose default arm is "propagate", which is the
one behaviour neither consumer wants.

Rejected: **returning `None` on failure.** ORCHESTRATION §3's *never zero, and no fourth state* — a
refusal names what is missing. `None` names nothing and forces the caller to re-derive the class the
adapter already knew.

Reversibility: **one-way in practice.** Two modules build against the return type; changing it later is
a signature change in both plus their tests.

**D-183 — The error-class vocabulary is ADR-0017's eight, not INT-015's seven. `OQ-060`.**

`docs/adr/0017-…` Decision names eight classes: `credential_rejected`, `rate_limited`,
`upstream_unavailable`, `timeout`, `model_not_available`, `content_filtered`, `invalid_request`,
`provider_contract_violation`. `docs/architecture/interfaces.md` INT-015 names seven — `timeout`,
`rate_limited`, `credential_rejected`, `upstream_5xx`, `bad_request`, `content_filtered`, `transport` —

Chosen: **ADR-0017's set.** The tiebreak is not ADR precedence (which is lower than `interfaces.md`) —
it is that the **lock file's own `failure_modes` and `alerts` blocks use ADR-0017's names**
(`upstream_unavailable` on the mid-stream row, `invalid_request` on the bad-parameter row,
`model_not_available` on the retired-model row, `ProviderContractViolation` in `risks`), and the lock
file is authority 1. INT-015 is the outlier.

The missing name matters to this phase rather than being cosmetic: **a registered provider that stops
returning a usage object is `provider_contract_violation`**, and INT-015's list has nowhere to put it.

Raised as **`OQ-060`**, naming both files and both lists. **Phase 10 owns the classification table

**The question.** ADR-0047 requires that a dispatch connect to the address it validated **for that
dispatch**. httpx binds address resolution to the transport and pools connections inside it, so the
lifetime of the client object decides whether the pinning survives connection reuse.

**Option A — one `httpx.AsyncClient` per dispatch**, built with a transport bound to the address the
guard just returned, closed when the dispatch ends.
*Pros:* the pinning property is trivially true and needs no argument — there is no pool to reuse, so
there is no connection that could predate the validation. The code is short and there is no cache to
get wrong or to leak. Nothing has to be said about invalidation, because nothing is retained.
*Cons:* a full TLS handshake to a third party on **every** gateway call. That is one to two extra
round trips inside the product's 50 ms added-latency budget, and it lands in `upstream_duration_seconds`
rather than in `dispatch_overhead_seconds`, so the module's own 10 ms metric would stay green while the
budget it is a share of was being spent. It also multiplies against streaming, where the connection is
held open anyway and the handshake is pure loss.

**Option B — a client cache keyed on `(provider_config_id, scheme, host, port, validated_address)`
with a TTL**, so a repeat dispatch to the same validated address reuses the pool.
*Pros:* the handshake is paid once per target rather than once per call, which is what the latency
budget assumes. The guard still runs on **every** dispatch — only the socket is reused. The pinning
property survives because the validated address is **part of the key**: a resolver answering
differently yields a different key, therefore a different client, therefore a different pool, and the
old client is never consulted.
*Cons:* a cache is a lifetime to manage. Clients have to be closed on eviction or the process leaks
sockets, and the TTL is one more number nobody has measured. It is also a second place — beside the
credential cache — where "expiry, never invalidation" has to be argued rather than assumed.

**Reversibility: cheap.** One dict behind one function, in one module, with no data consequence.

**ADOPTED: Option B. `adopted: UNCONFIRMED`.**
The deciding argument is where the cost lands rather than how much it is. Option A spends the
product's latency budget in the one place this module's own metric cannot see, which makes the
regression undetectable from the dashboard that exists to detect it. Option B's cost is a cache, and a
cache whose key contains the security-relevant value is the shape that cannot silently lose the
property — the failure mode of a wrong key is a cache **miss**, which costs a handshake, not a
connection to the wrong host. Recorded in `deferred-items.md` and owed a numbered item in `11-UAT.md`.

**`dispatch()`'s signature, written once and not re-derived downstream:**

async def dispatch(
    sessionmaker: async_sessionmaker[AsyncSession],
    *,
    workspace_id: str,

    parameters: Mapping[str, Any],

Two things about that signature need writing down at the signature itself, because both are places a

**`src/prope/provider_access/address.py` — resolve, then pin.**

- `PinnedTarget` — frozen, slotted: `scheme: str`, `host: str`, `port: int`, `address: str` (the
  literal IP the guard validated), and `origin: str` (the `scheme://host:port` form used for the
  `Host` header and for building URLs). Its docstring says the whole of ADR-0047 in three sentences:
  the address is what the socket connects to, the **host is what TLS verifies against**, and connecting
  to a bare IP with certificate checking relaxed would trade an SSRF hole for a TLS one.
- `ALLOWED_SCHEMES = frozenset({"https", "http"})`, with a comment recording that `http` is present
  only because a self-hosted OpenAI-compatible endpoint on a private network is a legitimate pilot
  configuration and that **phase 12 owns whether it survives** — the guard's private-range refusal
  already makes most `http` targets unreachable, so leaving it in is not the same as allowing it.
- `def is_globally_routable(address: str) -> bool` — the production policy. Parse with
  `ipaddress.ip_address` and refuse anything that is loopback, link-local, private, multicast,
  reserved, unspecified, or not `is_global`. Write at the function that `169.254.169.254` — the cloud
  metadata address — is link-local and is the specific address ADR-0047's redirect clause names.
- `async def resolve_and_pin(base_url: str, *, is_allowed: Callable[[str], bool] = is_globally_routable) -> PinnedTarget`
  — parse the URL, refuse a scheme outside the allow-list, resolve the host with
  `loop.getaddrinfo`, and return the **first** answer that `is_allowed` accepts. If the host is already
  a literal address, `getaddrinfo` returns it and the same check applies; say so, because "it is
  already an IP so there is nothing to resolve" is how this check gets skipped.
- Refusals raise `AddressRefused(reason)` with `reason` from a **closed** set —
  `scheme_not_allowed`, `unresolvable`, `blocked_address` — matching the lock file's
  `verification_total{result=fail, reason=blocked_address}` label value. Never quote the resolved
  address in the exception message: an error body that names the internal address the attacker was
  probing is a scan result returned by the server.
- `is_allowed` is injected for the reason D-181 gives. State at the parameter that the **default is the
  production policy** and that a test installing a permissive one is a test seam and not a bypass,
  and that this plan asserts the default refuses `127.0.0.1`.

**`src/prope/provider_access/upstream.py` — ADR-0047's client, and the only place a socket is opened.**

- `#: DEFAULT_CONNECT_TIMEOUT_SECONDS = 5.0` — a `#:` tuning-constant comment in `retention.py`'s
  voice: `deadline_ms` is the caller's budget for **the answer**, and a connect that has not completed
  in five seconds has not started spending it. Capped rather than derived so a caller with a 60 s
  evaluation deadline does not wait a minute on a host that is not there.
- `def timeout_for(deadline_ms: int) -> httpx.Timeout` — `connect=min(deadline_ms/1000,
  DEFAULT_CONNECT_TIMEOUT_SECONDS)`, `read=deadline_ms/1000`, `write=connect`, `pool=connect`. ADR-0047:
  *"`httpx.Timeout` carries `connect` and `read` separately, so `deadline_ms` maps onto the phase that
  actually matters rather than one aggregate."* Record at the function why there is **no outer
  wall-clock deadline** wrapping the request: on a stream the read timeout is per-read, which is the
  inter-chunk gap the caller actually cares about, and an outer `asyncio.timeout` would cancel
  mid-stream and destroy the partial usage the lock file's mid-stream failure mode requires be kept.
- `class PinnedTransport(httpx.AsyncHTTPTransport)` — the subclass ADR-0047 asks for. It is constructed
  with the `PinnedTarget` and rewrites the connection target to `target.address` while leaving the
  request's `Host` header, the URL and the TLS server hostname as the configured host. Two lines of
  docstring per property, and a third recording that `retries=0` is passed **explicitly** to `super()`
  even though it is the default, because A-088 is a guarantee and not a hope.
  **Read httpx's actual transport API on disk before writing this** — the mechanism for pinning
  (an explicit connection target, a resolver hook, or a `NetworkBackend`) is a fact about the pinned
  version, and the plan names the property rather than the attribute. If the version pinned in Task 1
  offers no clean seam, that is a finding: report it, and implement the pin at the lowest seam that
  exists rather than reaching for a hostname and hoping.
- `async def client_for(target: PinnedTarget, provider_config_id: str) -> httpx.AsyncClient` — D-180's
  cache. Key `(provider_config_id, target.scheme, target.host, target.port, target.address)`; value a
  client plus its creation time; TTL `#: UPSTREAM_CLIENT_TTL_SECONDS = 300.0` with the argument written
  out (long enough that a busy configuration never pays a handshake, short enough that a rotated
  base URL's old pool is gone within five minutes without anything invalidating it — the same
  expiry-not-invalidation shape as ADR-0012 and A-092, and the third instance of it in the project, so
  say that). Evicting **closes** the client; a leaked `AsyncClient` is a leaked socket.

- `async def post_chat_completion(client, target, *, path, headers, body, deadline_ms) -> httpx.Response`

  client, with the ADR-0047 sentence at both. No loop, no `while`, no `except ... : continue` anywhere
  in this module. Add a module-level docstring paragraph stating that fact as a rule a reviewer can
  check by reading, and note that `tests/unit/test_exactly_one_attempt.py` checks it by counting at the

**`tests/provider/_stub_provider.py` — a real server, and the reason it is real.**

An `asyncio.start_server` HTTP/1.1 responder on `127.0.0.1:0`, small enough to read in one sitting.
It must:
- count every request it receives on `request_count`, and record each request's method, path, headers
  and body on a list, so a test can assert **what** was sent as well as how many times;
- serve a scripted queue of responses, so a test can say "500 then 200" and observe that the second was
  never asked for;
- be able to hold a connection open without answering, so a read timeout is a real timeout;
- be able to answer `302` with a `Location`, so "redirects disabled" is observable;
- be able to refuse the connection outright (bind, then stop), so a connect failure is real.

the spy would read `1` and the provider would have seen `2`, which is the exact failure the criterion
is written to exclude. Note also that `Authorization` is captured here on purpose: it is the only way to

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider-access -> the workspace's upstream provider (B3) | **Prope's only outbound internet egress.** The destination is named by a dashboard-editable field and the request carries a bearer credential. |
| the upstream provider -> provider-access | The response body, the error body, and the redirect target are all attacker-influenced input from a third party the workspace chose. |
| `credential` row -> this process's memory | The only place in Prope where a third-party secret exists in plaintext. |
| process -> stdout / metrics registry | Log lines and metric labels leave the process and are retained by whatever scrapes them. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Information disclosure / elevation | `address.py` -> `upstream.py` (T-025, B3) | critical | mitigate | Scheme allow-list plus a non-global-range refusal at dispatch time, and the connection made to the **address that was validated** with the hostname preserved for SNI.
