<objective>
Make **SC5** true: *"a response from a non-OpenAI-shaped adapter is a valid OpenAI chat-completions
object, and an unmodelled field from a compatible provider survives unchanged."* Two clauses that pull
in opposite directions — one demands a translation, the other demands the absence of one — and the whole
of ADR-0015 is the argument for why both hold at once.

The same plan builds **INT-016**, `get_model_catalogue()`, because the catalogue is the other thing this
module translates from the provider's own vocabulary and because prompt-registry (phase 13) is the first
consumer of it.

---

**D-187 — One `Adapter` protocol, one production implementation, and a deliberately non-OpenAI-shaped
adapter that exists only in the test suite.**

AC-9's first clause — *"given a non-OpenAI-shaped provider adapter, when a response is returned, then it
is a valid OpenAI chat-completions object"* — is **unassertable in the MVP as specified**, because A-094
and OQ-016 fix the MVP at one adapter kind and that kind is already OpenAI-shaped. A test written
against the only adapter proves that an OpenAI-shaped response is OpenAI-shaped.

Chosen: `adapters.py` defines a `Adapter` protocol — `translate_response`, `translate_chunk`,
`list_models` — with exactly one production implementation, `OpenAICompatibleAdapter`, selected by the
`provider_config.adapter` column whose declared value set is `{openai_compatible}`. The **test suite**
supplies a second implementation, `RenamedFieldsAdapter`, over a wire shape that deliberately differs
in the places a real second adapter differs: the choices key, the message container, the finish reason's
name and vocabulary, and the usage field names. It is registered through an **injected registry**, never
through the production selector, so the production value set stays closed at one.

Rejected: **shipping a second production adapter** (Anthropic, Gemini). OQ-016 is resolved — one
adapter is the whole MVP and the second is post-MVP work the user will build. Adding one to make a test
pass is scope this phase does not own.

Rejected: **asserting the clause with a hand-built dict** that is neither adapter's output. It proves
the assertion function works.

Rejected: **routing the clause forward to whichever phase builds the second adapter.** There is no such
phase; post-MVP is not a phase number. A criterion routed to nowhere is a criterion dropped.

What this **does** prove, stated plainly so nobody over-reads it: that the translation boundary exists,
that a shape which is not OpenAI's can reach the caller as one, and that the SDK validates the output.
What it does **not** prove: that any particular real provider's shape translates correctly. That is the
second adapter's own test suite when it is built, and the `adapter` column is what makes it additive.

Reversibility: **cheap.**

---

**D-188 — Translation is mapping-in, mapping-out. Runtime code never constructs a typed model, and the
SDK is the oracle only.**

Chosen: every adapter method takes a `Mapping[str, Any]` and returns a `Mapping[str, Any]`. The
OpenAI-compatible adapter's `translate_response` is **the identity for every key it does not have to
touch** — it validates that the required OpenAI keys are present and returns the provider's own mapping,
copied but not filtered. `tests/contract/` parses the result with the real `openai` SDK's model.

Rejected: **pydantic models for the response.** ADR-0015 rejected *"normalise, but strip unknown fields
for safety"* in as many words, and named the failure precisely: *"nothing errors, a field is just
gone."* A pydantic v2 model with `model_config = {"extra": "allow"}` is the tempting middle — it keeps
unknown fields — and it still fails, because `model_dump()` reorders and re-types what it round-trips
and because the moment one field is declared, its **absence** becomes a validation error on a provider
that omits it. The whole point is that Prope's ignorance costs the consumer nothing.

Rejected: **the `openai` SDK as the client** so its models come for free. Three independent grounds are
already written into the lock file and ADR-0047: A-088's exactly-one-attempt against the SDK's default
of two retries, this criterion's unknown-field pass-through against its typed models, and ADR-0047's
address pinning against a client that owns its own connection. It is the right tool as an oracle and the
wrong one as a client, and this plan asserts the distinction with a source walk rather than trusting it.

Reversibility: **one-way in practice** — the return type is built against by two modules.

---

**D-189 — The catalogue is soft in both directions: an empty list, never a raise, and never a delete.**

Chosen: `get_model_catalogue(sessionmaker, *, workspace_id, provider_config_id)` returns
`list[CatalogueEntry]` and returns `[]` for a configuration that has no rows, for a configuration that
does not exist, and for a configuration that is disabled. It never raises for any of those. A refresh
that cannot reach the provider **leaves the stored catalogue exactly as it was** and reports the failure
to its caller; it does not empty the table.

INT-016 is the registry's **one soft seam** and says why: *"treating a third party's incomplete model
list as authoritative would block a legitimate revision."*

Rejected: **raising for an unknown configuration.** It would make the picker's failure mode a 500 in
prompt-registry, and prompt-registry's own permission check has already happened by then — an unknown id
at this seam is a caller bug that a raise would turn into an outage of the revision editor.

Rejected: **deleting rows the provider stopped listing.** `available: false` instead, so *"a revision
bound to a model the provider has retired still explains itself instead of pointing at nothing"* — the
lock file's own sentence, and the reason `ProviderModelUnavailable` can name a model at all.

Consequence, stated: `[]` is ambiguous between *no such configuration* and *a configuration with no
models*. That ambiguity is INT-016's intent (the picker degrades identically for both) and it is why the
**management** route `GET /providers/{id}/models` — plan 11-05 — answers not-found for an unknown id
while this **internal** seam does not. Two callers, two correct answers, one store.

Reversibility: **cheap.**
</objective>

```
class Adapter(Protocol):
    name: str
    def translate_response(self, payload: Mapping[str, Any]) -> Mapping[str, Any]: ...
    def translate_chunk(self, payload: Mapping[str, Any]) -> Mapping[str, Any]: ...

    def translate_model_list(self, payload: Mapping[str, Any]) -> Sequence[DiscoveredModel]: ...
```

Five methods, and the shape is the point: **a second adapter is these five functions and a test suite**,
not a change anywhere else. Write that at the protocol, quoting ADR-0015's consequence that *"adding a
provider whose API is not OpenAI-shaped is a real adapter with a real test suite, not a configuration
entry."*

**`OpenAICompatibleAdapter` — the one production implementation, and most of it is the identity.**

`translate_response` **validates and returns**, it does not rebuild. Concretely: assert the payload is a
mapping and carries `choices` as a list; then return it. Write the paragraph that stops the next reader
from "tidying" this into a constructor:

> This function looks like it does nothing and that is the decision. ADR-0015 rejected *"normalise, but
> strip unknown fields for safety"* by name, because Prope does not know what a provider will add next
> and a consumer using a provider-specific field would find Prope silently deleting it — *"nothing
> errors, a field is just gone."* Building a response here means enumerating the keys, and enumerating
> the keys is the strip.

`translate_chunk` is the same, one level down. `compose_request` is where the model, messages and the
caller's verbatim parameters are assembled — plan 11-02's forced keys move here so there is one composer
rather than one per path, and 11-02's `FORCED_UPSTREAM_KEYS` constant moves with them. **Keep 11-02's
argument text at the new site**; a decision that loses its reasoning in a refactor is a decision that
gets reversed.

`list_models_request` returns `("/v1/models", {})` — the path relative to `base_url` and any extra
headers. `translate_model_list` maps the OpenAI `{"data": [{"id": …}]}` shape to `DiscoveredModel`
values. On `supports_streaming`: OpenAI's model list does not report it, so the discovered value is
`True` for every model with a comment saying it is an **assumption of the wire protocol** rather than a
fact from the provider, that a model which does not stream will fail its first streaming dispatch with
`invalid_request` (A-097's category, a revision defect), and that the manual-entry route in plan 11-05 is
how a workspace corrects it. Never invent a capability probe; that is an upstream call per model.

**`adapter_for(name: str, *, registry: Mapping[str, Adapter] | None = None) -> Adapter`.** The production
registry is a module constant holding exactly one entry. `registry` is the injected seam D-187 needs —
default `None` means the production one. An unknown adapter name raises `UnknownAdapter`, and the
docstring says why a raise rather than a fallback to the one that exists: a configuration whose adapter
column holds an unrecognised value was written by something that should not have, and silently treating
it as OpenAI-compatible would send a workspace's credential to a provider under a protocol nobody
selected.

**`DiscoveredModel`** — frozen, slotted: `model_id`, `display_name`, `supports_streaming`. **No price
field, no cost field, no currency field**, with the one-line reason at the class: money is call-ledger's
(A-030, A-056), and the two tables key on `(provider, model)` with no seam between them **by decision**
(the lock file's last risk row), so a price field here would be the seam growing by accident.
