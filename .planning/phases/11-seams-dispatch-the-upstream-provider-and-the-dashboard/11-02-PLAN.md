<objective>
Make **SC1** true and prove it where it is actually at risk: on a stream, where the OpenAI-compatible
wire protocol has an explicit flag for suppressing usage and the caller supplies the parameter bag that
flag lives in.

A-089 is unambiguous — *"provider-access always requests usage from the provider; it is never a caller
option"* — and AC-4 asserts it in the one shape that can fail: *"Given a streaming dispatch, when the
caller did not ask for usage in any way, then the upstream request still asks for it and the returned
result carries a usage object — the caller has no parameter that can turn it off."*

This plan also builds the SSE reader, because ADR-0047's Consequences hand it to this module in as many
words: *"SSE parsing is now this module's code, roughly thirty lines, and it is on the per-chunk 1 ms
budget. It is unit-testable against recorded provider streams, which the SDK's internal parser was
not."*

**D-184 — Parameters are copied verbatim, then exactly two keys are overwritten, and the list of two is
a constant.**

Chosen: the upstream body is `{"model": …, "messages": …, **parameters}`, then
`body["stream"] = stream` and, when streaming, `body["stream_options"] = {**caller_stream_options,
"include_usage": True}`. The two forced keys live in a module constant `FORCED_UPSTREAM_KEYS =
("stream", "stream_options.include_usage")` and the docstring names both and nothing else.

**A-097 and A-089 collide here and the collision is resolved rather than papered over.** A-097 says
generation parameters pass through **verbatim** and that a parameter the provider rejects is a defect in
an approved revision. A-089 says usage is **never a caller option**. A caller sending
`stream_options: {"include_usage": false}` makes both true and false at once.

The resolution is a distinction that holds up: **`stream_options.include_usage` is not a generation
parameter.** It changes nothing about what the model produces — it changes what the provider *reports*
about what it produced. A-097's whole argument is about the model's behaviour ("a temperature range, a
parameter the model does not support, a JSON-mode flag on a model without it") and about an eval suite
having run the real binding. Forcing a reporting flag does not make the eval suite measure different
text. `stream` is the same category: it is the transport shape, chosen by the caller's own `stream`
argument, not by the revision's parameter bag.

Rejected: **refusing a caller who sends `include_usage: false`** with an `invalid_request`. It is the
tidier-looking option and it is wrong in both directions — it turns a harmless request into a hard
failure for the gateway, and it leaves the property depending on every caller behaving.

Rejected: **merging with the caller's value winning.** That is the flag being a caller option, which
A-089 forbids by name and AC-4 asserts against.

Consequence, stated: a streaming caller who asked for no usage receives an extra usage-only chunk it did
not expect. That is **the gateway's** to strip, and ADR-0015 says so explicitly — *"the gateway keeps
the caller-facing half — stripping the extra usage-only chunk from a stream whose caller did not ask for
it."* Phase 21 owns it. Recorded here so phase 21 finds the sentence rather than the surprise.

Reversibility: **cheap** as code; **one-way** as a property, because a released revision whose costs
were recorded from forced usage cannot have them re-derived later.

---

**D-185 — The stream's terminal failure is a value on the iterator, not an exception across the seam.**

Chosen: `dispatch(stream=True)` returns a `DispatchResult` whose `stream` is an
`AsyncIterator[Mapping[str, Any] | DispatchError]`. Chunks are mappings. The final item is **either**
nothing more (a clean end) **or** a `DispatchError`. `DispatchResult.usage` is populated by the time the
iterator is exhausted, from whatever usage the provider sent — including a partial stream that carried
one.

Rejected: **raising out of the async generator.** The lock file's mid-stream failure mode requires the
opposite in its own words: *"The stream contract surfaces a terminal error as a value on the iterator
rather than an exception thrown across the seam, so the caller always receives what was generated before
it."* An exception out of an `async for` discards the loop body's progress at the call site and gives
the gateway nothing to truncate honestly with.

Rejected: **a sentinel object that is not a `DispatchError`.** ORCHESTRATION §3's *no fourth state*. The
caller already branches on `DispatchError`; a second failure shape is a second branch to forget, and the
gateway's `fallback_eligible` read would have nowhere to come from.

Rejected: **returning the raw `httpx` response and letting the caller iterate.** It leaks the client into
the seam, makes the connection's lifetime the caller's problem, and puts the framing in whichever module
happens to consume it — which is exactly what ADR-0015 rejected for responses.

Reversibility: **one-way in practice.** Phase 21 is written against this shape.

---

**D-186 — The SSE reader is byte-oriented and is tested against recorded byte streams, not strings.**

Chosen: `read_sse(aiter_bytes)` accumulates a `bytearray`, splits on the double newline that terminates
an event, tolerates both `\n\n` and `\r\n\r\n`, ignores comment lines beginning with `:`, joins multiple
`data:` lines within one event with `\n` per the SSE specification, and stops on the literal `data:
[DONE]` sentinel. It yields decoded JSON mappings and never a model.

Rejected: **splitting the decoded text on `"\n\n"`.** It is the version that works on every test written
by the person who wrote the parser and fails on the first provider that sends CRLF, and it decodes bytes
at an arbitrary boundary, which corrupts any multi-byte character split across TCP reads. Vietnamese
prompt text makes that a certainty rather than a theory (ADR-0053 makes the interface Vietnamese; the
prompts are the workspace's own).

Rejected: **`httpx`'s `aiter_lines`.** It hides the framing decision inside a library whose line
semantics are its own, and the whole reason this code exists is that ADR-0047 took the framing away from
a library so it could be unit-tested against recorded streams.

The tests feed **bytes**, deliberately split at hostile boundaries: inside a JSON object, inside a
multi-byte UTF-8 character, between `\r` and `\n`, and between the two newlines that end an event.

Reversibility: **cheap.**

**`src/prope/provider_access/usage.py` — one function, and it is where a success metric lives.**

`def parse_usage(payload: Mapping[str, Any]) -> Usage | None`. It reads the OpenAI-compatible
`usage` object — `prompt_tokens`, `completion_tokens`, `total_tokens` — and produces the `Usage` value
object 11-01 defined, keeping the provider's own object on `Usage.raw`.

Four rules, each written at the code rather than assumed:

1. **Absent means absent.** No `usage` key, or `usage` present and not a mapping, returns `None`. It
   does **not** return a `Usage` of zeros. `00_context.md`'s non-negotiable — *"cost must be measured
   from actual runs, never inferred from prompt token length"* — and ORCHESTRATION §3's *never zero* are
   the same rule seen from two sides, and call-ledger's `usage_status = unknown` is the column built to
   receive this `None`.
2. **A field present but not an integer is absent for that field**, not zero, and not a coerced float.
   Say why at the branch: a provider returning `"prompt_tokens": null` during an outage is a real shape,
   and a `0` written into a priced call record is a cost figure that is wrong rather than missing.
3. **`total_tokens` is read, never computed.** If the provider sent it, it is theirs; if it did not, it
   stays `None`. Computing it would make the ±2% metric measure Prope's arithmetic instead of the
   provider's report, which is the one thing the metric is not about.
4. **The field-name table is data, and it is the extension point A-094 keeps.** Write the OpenAI-
   compatible names as a module constant with a comment that a second adapter (OQ-016, post-MVP) adds a
   second entry here rather than a second parser. Do not build an adapter registry — plan 11-03 owns
   that seam; this is a named constant that 11-03 will reach for.

**`src/prope/provider_access/dispatch.py` — what happens when a registered provider sends no usage.**

On the non-streaming path, after a `200` decodes: call `parse_usage`. When it returns `None`:

- increment `prope_provider_access_usage_missing_total` (unlabelled — the lock file's list gives it no
  labels, and its whole job is to be zero, so it needs a baseline more than it needs a dimension);
- return a `DispatchError` with class `provider_contract_violation`, `origin=provider`,
  `fallback_eligible=True`, `retryable=False`. Argue all three at the call site: the provider **answered**,
  so the origin is theirs; the gateway serving a fallback is a truthful response to "we cannot account
  for this call", which is the same posture `credential_rejected` takes; and a second attempt would

- **Do not return the response with `usage=None`.** That is the tempting middle ground and it is the
  failure the alert exists to catch: the call would look successful, the record would carry
  `usage_status = unknown`, and *"two success metrics quietly develop a hole"* — the lock file's own
  sentence for this failure mode.

**A-030's admission rule is phase 10's and this is its runtime half**, and the two must not be confused
in either direction. Phase 10 refuses to *register* a provider that returns no usage. This plan handles

**`src/prope/provider_access/streaming.py` — the framing, and nothing else.**

`async def read_sse(chunks: AsyncIterator[bytes]) -> AsyncIterator[Mapping[str, Any]]`.

The algorithm, stated so an executor writes the same thing an auditor would check:

- Accumulate into a `bytearray`. Never decode a partial buffer — a UTF-8 character split across two TCP
  reads decodes to a replacement character or raises, and either one silently corrupts a prompt's text.
  Decode **only** a complete event's `data` payload.
- An event ends at `\n\n` **or** `\r\n\r\n`. Handle both; the specification allows both and providers
  differ. Write that at the split.
- Within an event, ignore lines beginning with `:` (SSE comments — some providers use them as
  keep-alives, and a keep-alive parsed as a chunk is a `json.JSONDecodeError` mid-stream).
- Join **multiple** `data:` lines in one event with `\n` before decoding, per the specification. A
  provider that pretty-prints its JSON produces exactly this shape and a single-`data`-line reader
  fails on it.
- Strip exactly one leading space after `data:` — the specification says one, and stripping all of them
  would corrupt a payload that legitimately starts with whitespace.
- `data: [DONE]` terminates the iterator and is not yielded. Compare against the decoded, stripped
  payload rather than searching the raw buffer for the substring.
- Anything that is not valid JSON after `[DONE]` handling is a framing failure: **do not skip it.**
  Yield nothing further and let the caller's classifier turn it into
  `provider_contract_violation`. A parser that skips what it cannot read is a parser that turns a
  broken provider into a short answer.
- A buffer that grows past `#: MAX_SSE_EVENT_BYTES` without completing an event is a framing failure
  too. Set it to 1 MiB with the argument in a `#:` comment: a chat-completion chunk is a delta of a few
  tokens, so a megabyte is four orders of magnitude of headroom, and an unbounded buffer on a stream
  from a third party is an out-of-memory condition the module chose not to have.

**The 1 ms budget is a ceiling and the code should be readable about it.** One `bytes` decode and one
`json.loads` per event, no regular expressions, no per-chunk logging, and **no per-chunk metric
observation** — a histogram observation per chunk at 200 chunks a response is a cardinality and CPU cost
for a number the load test can get from the total. Say that at the loop.

**`tests/unit/test_sse_reader.py` — recorded byte streams, split at hostile boundaries.**

Build one realistic recorded stream as a `bytes` constant: a role chunk, several content deltas
including one with non-ASCII Vietnamese text, a finish-reason chunk, a usage-only chunk, and `[DONE]`.
Then a helper that feeds it to `read_sse` in slices of size *n*, and a test parameterised over
`n in (1, 2, 3, 7, 64, len(stream))`. **A slice size of 1 is the point**: it splits every boundary the
protocol has, including the middle of a multi-byte character and the gap between `\r` and `\n`, and it
is the cheapest possible proof that the reader is buffering rather than assuming.

Individual cases beyond the slicing sweep:

- CRLF framing throughout → the same events as the `\n\n` version, asserted by equality of the yielded
  list.
- A comment line (`: keep-alive`) between two events → ignored, and the two events still arrive.
