## D-235 — One folded statement, in one module, folding both sides the same way

**Chosen.** `src/prope/prompt_registry/search.py` holds the single keyword statement:

```sql
search_text LIKE '%' || public.unaccent(lower(:term)) || '%'
```

written inline inside a complete `text("""…""")` constant, with the term **bound**. The stored document
is folded by `registry.compose_search_text` (plan 13-01) and the query folds the term with the same two
functions in the same order. Nothing is folded in Python.

**Folding on one side only is the failure mode, and it is silent.** The stored column holds
`tieu de`; a user types `tiêu đề`; an unfolded `LIKE` returns nothing, with no error and no metric —
ADR-0048's *"indistinguishable from 'nobody wrote a prompt about that'"* arriving through a different
door. The MVP ships in Vietnamese only (ADR-0053), so this is the ordinary case and not an edge one.

**Rejected: folding the term in Python** with `unicodedata.normalize("NFKD", …)` and a combining-mark
strip. It is the reflex answer, it needs no round trip, and it is wrong for a specific reason:
PostgreSQL's `unaccent` is a **dictionary lookup** against `unaccent.rules`, not Unicode decomposition.
The two agree on most Latin text and disagree exactly where a dictionary has an entry that decomposition
does not, or the reverse — `đ` is the case that matters here, because it is not a `d` with a combining
mark and NFKD leaves it alone while `unaccent.rules` maps it. A search that works in the tests and misses
`đường` is worse than one that misses everything.

**Rejected: `ILIKE` with an unfolded term.** `ILIKE` handles case and not diacritics, so it solves half
the problem and hides the other half behind a passing test on ASCII input.

**Both sides are lower-cased as well as unaccented, so `LIKE` is correct and `ILIKE` is redundant.** Use
`LIKE`, and say at the statement that the case-insensitivity users see comes from the fold, not from the
operator — because somebody who "fixes" this to `ILIKE` later will assume the fold is redundant and
remove it.

**Reversibility: costly.** The stored column is folded; changing the fold means recomputing
`search_text` for every property.

## D-236 — A source gate over the whole package, not a rule in a docstring

**Chosen.** `tests/architecture/test_registry_search_statements.py` parses every module under
`src/prope/prompt_registry/` with `ast`, finds every `text(...)` call, and asserts four things about the
statements it finds. **The file list is discovered by `rglob`, never written down**, so a query added in
phase 14 or 15 is covered on the day it is written.

The four:

1. No statement contains `to_tsvector`, `tsquery`, `plainto_tsquery`, `websearch_to_tsquery` or `@@`.
2. No statement contains `SELECT *`.
3. No statement names `search_text` between its `SELECT` and its `FROM` — the column may appear in a
   `WHERE` clause and nowhere else.
4. Every statement that mentions `search_text` also contains the exact substring
   `public.unaccent(lower(`.

**This is the same shape as `tests/architecture/test_no_sql_interpolation.py`** and it is chosen for that
file's stated reason, quoted rather than paraphrased: *"It is deliberately a property of the SOURCE
rather than of a test's call sites: a runtime test can only prove that the inputs it happened to try
were safe, while this proves that no interpolated statement exists to try."* Substitute *"no tsvector
query exists to run"* and the argument is unchanged.

**Rejected: asserting the behaviour only.** A behavioural test that `'thentic'` matches would keep
passing under a `tsvector` implementation that added a trigram index beside it, and would fail
mysteriously under one that did not — after the change, in a phase that did not make it.

**Rejected: putting the rule in a docstring.** ADR-0048's own consequence bullet is that a trigger's
absence must be *"a build failure rather than a code-review responsibility"*. The same argument covers
the query.

**Clause 3 is deliberately syntactic and deliberately crude**, and the plan says so: it will not catch
`SELECT p.* FROM prompt_property p` (clause 2 does) and it will not catch a column list built in Python
(the interpolation gate does). It catches the thing that actually happens, which is somebody adding
`search_text` to a select list while debugging and not removing it.

**Reversibility: cheap.**

**`src/prope/prompt_registry/search.py`.** Module docstring in this repository's density, carrying five
things:

1. **What a match means, in the words a user would recognise**: substring, case-insensitive,
   diacritic-insensitive, matching inside words and inside model names. `thentic` finds *"authentication

   searchable, and the change-summary fold is what recovers most of that recall at 0.6% of the cost.
   Name `OQ-074` here: the latest body is the latest regardless of status, so a `Draft` saved on top of a
   released revision takes the released body out of the index. That is the specified behaviour, it is
   asserted in Task 2, and the question is open.
3. **The three filters stack and none substitutes for another** — RLS supplies the workspace boundary
   invisibly (ADR-0035/0045), A-118's `visible_subject_filter` set form supplies the within-workspace

**`tests/integration/test_search_text_trigger.py`** — the owed **AC-8**.

Module docstring: ADR-0048 makes the trigger's **absence** a build failure rather than a code-review
responsibility, in the same shape as ADR-0025's privilege test and ADR-0045's coverage test, because *"a
trigger is invisible at the call site"*. This file is that build failure. Its second half exists because
existence is not enough: a trigger that exists and does not fire on the write that matters is the same
outcome with more confidence attached.

1. **Existence, in the catalogue.** Query `pg_trigger` joined to `pg_class` and `pg_namespace` for
   `nspname = 'registry'`, excluding internal constraint triggers (`NOT tgisinternal`). Assert the set of
   `(table, trigger name)` pairs is **exactly** the two plan 13-01 created. An equality, not a
   containment: a third trigger appearing in this schema is something somebody should have to edit this
   line to add. Assert the composer function exists too, and that all three functions in `registry` have
   `prosecdef = false` — the same claim `test_schema_invariants` makes generically, restated here because
   a `SECURITY DEFINER` trigger is the specific thing a future author would reach for.
2. **It fires on a direct `INSERT` that bypasses the application.** This is AC-8's load-bearing half.
   Register a property through `register_prompt_property`, then insert a revision with **raw SQL** as
   `prope_app` inside a `workspace_transaction` — `INSERT_REVISION` from the test package, not
   `create_revision` — carrying a distinctive marker phrase in its body. Then read the parent's
   `search_text` through `migrate_engine` and assert the folded marker is present. Say in the test's
   docstring why the application is bypassed: the criterion is about the **database** maintaining the
   column, and a test that went through `create_revision` would pass equally well against an
   implementation that wrote the column from Python.
3. **It fires on the `UPDATE` side too.** A direct `UPDATE registry.prompt_property SET title = …` as
   `prope_app` rewrites `search_text`. Plan 13-03 asserts the same thing through the command; this one
   asserts it with the command bypassed. ADR-0048 names both firing conditions and one test each is what
   makes "both" true.
4. **The mutation check.** As the owner, in a `try`: `DROP TRIGGER revision_touches_parent ON
   registry.revision`, repeat step 2 with a second marker, and assert the parent's `search_text` does
   **not** contain it — the drift ADR-0048 describes, produced deliberately so the assertion in step 2 is
   known to be about the trigger. In the `finally`, recreate the trigger with the exact DDL from the
   migration and assert `pg_trigger` holds it again. Write at the `finally` that a failure here must not
   leave the schema without the trigger for every test that follows in the session.
5. **`prope_app` cannot write the column even when it tries.** `UPDATE registry.prompt_property SET
   search_text = 'x'` is refused. Plan 13-02's privilege module asserts this too; asserting it here as
   well is deliberate and the docstring says why — this is the file somebody reads when they ask *"what
   maintains `search_text`"*, and the answer is incomplete without *"and nothing else can"*.

**This module mutates shared container state and must never run concurrently with another plan**
(ORCHESTRATION §7a(b)). Name the window between the `DROP TRIGGER` and the `finally`: a concurrent test
creating a revision in that window would silently get a stale `search_text` and fail somewhere else
entirely.
