<objective>
Close PR-01. Make an edit create the next revision and leave every earlier one exactly as it was —
proven byte for byte rather than by a row count, and backed by a privilege matrix that refuses the
`UPDATE` the assertion is about.

`00_context.md#problem` is the reason this is the first behaviour built on top of the schema: 11 of 11
respondents cannot identify the latest revision and 5 of 11 cannot identify which prompt caused a
failure. ADR-0002's opening sentence is the answer — *"provenance is not a feature layered on top of a
mutable store; it is a property of the store or it is absent"* — and this plan is where the store gets
the property.

Two things this plan deliberately does **not** build, named so the verifier does not read them as
omissions:

- **No routes.** `POST /api/v1/prompts` and `POST /api/v1/prompts/{id}/revisions` are **phase 14's**.
  What ships here is the command underneath them, callable from a test with a sessionmaker, in exactly
  the shape `register_provider_config` and `create_workspace` already established.
- **No permission check.** Every endpoint resolves permission through access-control *at the edge*, and
  the edge is phase 14's. `create_revision` takes the actor as a parameter and decides nothing about

## D-238 — `register_prompt_property` lands private, `Active`, and with no released pointer

**Chosen.** Every registration writes `access_level = 'private'` unless the caller passes something
else, `status = 'Active'`, all three released-pointer columns NULL, and one `property_created` event, in
one transaction.

**`private` is the default because BR-01 is a non-negotiable and a default is where it is actually
decided.** Phase 7 already made the same call one module over — `Subject.access_level` defaults to
`AccessLevel.PRIVATE`, described there as *"the fail-closed default"* — and two defaults that disagree
would mean a prompt registered as private is authorised as workspace-visible or the reverse.

**Rejected: no default, with `access_level` required.** It is the more explicit shape and it is refused
because it puts BR-01's answer at every call site, which is a place a new call site can forget. A
required argument protects against forgetting to *think*; a private default protects against forgetting
to *type*, and only the second failure ships silently.

**Reversibility: cheap** — a default argument.

## D-231 — The revision number is allocated in the transaction, arbitrated by the constraint, and retried once

**Chosen.** Inside the one `workspace_transaction`:
`SELECT coalesce(max(revision_number), 0) + 1 FROM registry.revision WHERE prompt_id = :prompt_id`, then
the `INSERT`. On an `IntegrityError` naming `uq_revision_prompt_revision_number`, increment
`prope_registry_revision_conflict_total`, **open a new transaction and try exactly once more.** A second
collision raises a domain error the caller surfaces.

This is A-048 implemented literally — *"allocated inside the creating transaction, arbitrated by a unique
constraint"* — and the lock's failure-mode row states the retry policy: *"The loser retries once
automatically; on a second collision the editor reloads with both bodies preserved client-side."*

**Rejected: a sequence per prompt.** Sequences are non-transactional by design, so a rolled-back create
would burn a number and A-048's *"numbers are gapless and a failed create allocates nothing"* would
become false. Gaplessness is what makes `@3` a usable pin (INT-009).

**Rejected: `SELECT … FOR UPDATE` on the parent, or a PostgreSQL advisory lock.** Both remove the race by
serialising every save on one prompt. The race is rare — two people saving the same prompt in the same
instant — and the constraint already turns it into a clean loser rather than a lost edit. Paying a lock
on every save to remove a retry from a rare path is the wrong trade, and the lock is one more thing to
hold correctly across the history append inside the same transaction.

**The retry must be a NEW transaction, not a re-`INSERT` inside the failed one.** A PostgreSQL
transaction that has hit an integrity error is aborted and every subsequent statement in it fails with
`current transaction is aborted`. Write that at the retry, because retrying in place is the first thing
somebody tries and it fails in a way that reads as a second, unrelated bug.

**Reversibility: cheap.**

---

## D-239 — The two A-050 checks are at the edge of the command, before anything is opened

**Chosen.** `create_revision` measures `len(body.encode("utf-8"))` and `len(change_summary)` and raises
a domain error naming the **actual size and the cap** before it opens a transaction.

Before, not inside, for two reasons worth writing down: a 32 KiB body that is going to be refused should
not travel to the database at all, and a refusal raised inside a transaction that has already appended a
history event has to unwind an event about something that did not happen.

**The error names a size and never a fragment of the text.** A-046 keeps bodies out of logs, and an
exception message is a log line one `except` away.

**Reversibility: cheap.**

### `src/prope/prompt_registry/domain.py` — the errors and the model-name value

Add, as frozen slotted dataclasses or plain exception classes in the file's existing style:

- `ModelName` — a `@dataclass(frozen=True, slots=True)` of `(namespace: str, name: str)` with
  `parse(raw: str) -> ModelName` and `__str__` returning `f"{namespace}/{name}"`. `parse` splits on the
  **first and only** `/`: a raw value with zero or two or more slashes is refused. It also refuses an
  empty part, leading or trailing whitespace, any character below 0x20, and either part longer than the
  migration's caps (64 / 128). **It does not lower-case**, and the docstring says why: A-021's
  case-insensitivity is a uniqueness rule carried by
  `uq_prompt_property_model_name (workspace_id, lower(namespace), lower(name))`, and rewriting what
  somebody typed is the same class of edit A-050 forbids one column over. `OQ-073` is named here.
- `PromptBodyTooLarge(actual_bytes, limit_bytes)`, `ChangeSummaryTooLong(actual_chars, limit_chars)`,
  `ChangeSummaryRequired`, `InvalidModelName(reason)`, `RevisionNumberConflict(prompt_id)`,
  `PromptPropertyNotFound(prompt_id)`. Every one carries **numbers and identifiers, never text
  fragments** — write that rule once, at the top of the group, citing A-046 and the fact that an
  exception message is a log line one `except` away.

Each error's docstring says which HTTP shape phase 14 will map it to (422 with `details` for the four
validation errors, 409 for the conflict, 404 for not-found), and states plainly that **this module does
not do the mapping** — the module that owns the edge does. That sentence is what stops phase 14 from
inventing a second error vocabulary.

### `src/prope/prompt_registry/properties.py`

```python
async def register_prompt_property(
    sessionmaker,
    *,
    workspace_id: str,
    model_name: ModelName,
    title: str,
    purpose: str,
    owner_id: str,
    actor_id: str,
    tags: Sequence[str] = (),
    access_level: AccessLevel = AccessLevel.PRIVATE,
    now: datetime,
) -> str
```

Returns the minted `prm_` id. Keyword-only after the sessionmaker, because eight positional strings is
the shape a caller gets wrong silently. `now` is an **argument, never a clock read** — this repository's
standing convention, stated in four existing module docstrings; say which caller supplies it (phase 14's
route, from its one sanctioned clock site) and that a test supplies a fixed instant so the assertions are
equalities.

Body, in order:

1. Mint `prm_` + `ULID()` in `call_ledger/api.py`'s idiom.
2. Open one `workspace_transaction(sessionmaker, workspace_id)`.
3. `INSERT INTO registry.prompt_property (…)` — a whole `text("""…""")` module constant with every value
   bound. **`search_text` is not in the column list** and there is a comment above the statement saying
   so: the trigger writes it, `prope_app` holds no `UPDATE` privilege on it, and adding it here is a
   runtime failure rather than a silent one. `created_at` and `updated_at` both take `now`.
4. `await append(session, HistoryEventDraft(...))` on the **same session** — `action="property_created"`,
   `target_type="property"`, `target_id=<the new prm_ id>`, `scope_prompt_id=<the same id>`,
   `details={}`, `occurred_at=now`, `actor_type` whatever phase 4's registry seeds for a person.
   `scope_prompt_id` is stamped because A-119 is what makes phase 14's Activity endpoint one indexed
   read; say so at the call.
5. Return the id.

**Do not catch the append's exception** (INT-006). **Do not catch the unique-index violation on the model
name either** — let it surface; phase 14 maps it. Say at the `INSERT` that `uq_prompt_property_model_name`
is the arbiter and that a `SELECT`-then-`INSERT` pre-check would be a race, which is the same argument
A-048 makes for revision numbers one module-file over.

Module docstring in `seams.py`'s density: what the module owns, the one-transaction rule and what it
buys (a property with no `property_created` event cannot exist), the private-by-default decision (D-238)
with BR-01 named, and the sentence about permission being the edge's job.

### `src/prope/prompt_registry/revisions.py`

```python
async def create_revision(
    sessionmaker,
    *,
    workspace_id: str,
    prompt_id: str,
    body: str,
    provider_config_id: str,
    upstream_model: str,
    parameters: Mapping[str, object],
    fallback_answer: str | None,
    change_summary: str,
    author_id: str,
    now: datetime,
) -> RevisionCreated
```

`RevisionCreated` is a frozen slotted dataclass of `(version_id, revision_number)` — a tuple would make
every unpack site a positional guess, and the pair travels to the route, to the history event and to the
test.

Body, in order:

1. **The two edge checks, before any transaction opens** (D-239). `len(body.encode("utf-8"))` against
   `MAX_BODY_BYTES`; `change_summary` non-empty after `strip()` and `len(change_summary)` against
   `MAX_CHANGE_SUMMARY_CHARS`. Raise the domain error carrying the actual figure. Comment that
   `octet_length` in the CHECK constraint and `len(...encode("utf-8"))` here are deliberately the same
   measurement, and that the constraint is the second writer's backstop rather than a duplicate.
2. `_attempt(...)`, an inner coroutine, called at most twice:
   - open one `workspace_transaction`;
   - `SELECT coalesce(max(revision_number), 0) + 1 FROM registry.revision WHERE prompt_id = :prompt_id`
     — a whole `text(...)` constant. If the property does not exist, this returns 1 and the `INSERT` then
     fails the parent foreign key; **check the property exists first**, in the same transaction, with a
     `SELECT 1 FROM registry.prompt_property WHERE id = :prompt_id` that raises
     `PromptPropertyNotFound`, so a missing prompt is a named error rather than a foreign-key message.
     Note at that read that under the tenant policy a prompt in another workspace is **indistinguishable
     from one that does not exist**, which is A-116's not-found-never-forbidden falling out of the policy
     rather than being implemented;
   - mint `rev_` + `ULID()`;
   - `INSERT INTO registry.revision (…)` with `status` **defaulted to `Draft` in the statement's bound
     value**, not left to the column default — a caller reading this file should see the status a new
     revision has without opening the migration;
   - `await append(session, HistoryEventDraft(...))` on the same session — `action="revision_created"`,
     `target_type="revision"`, `target_id=<version_id>`, `scope_prompt_id=<prompt_id>`, `details={}`,
     `occurred_at=now`;
   - return `RevisionCreated`.
3. Wrap the call: on `IntegrityError` whose message names `uq_revision_prompt_revision_number`,
   `revision_conflict_total.inc()` and call `_attempt` **once** more in a fresh transaction (D-231 — write
   the aborted-transaction sentence at the retry). A second such error raises
   `RevisionNumberConflict`. Any other `IntegrityError` propagates untouched: a foreign-key or CHECK
   violation is not a revision-number race and retrying it would be a loop.
4. On success, `revision_created_total.labels(workspace=workspace_id).inc()`.

Also in this module: `get_revision(session, version_id) -> Revision | None`, a plain read returning a
frozen dataclass with **every** column INT-011 names (body, provider config, upstream model, parameters,
fallback answer, author, timestamp, change summary, status, revision number) — plan 13-05's diff reads
through it, and phase 14's `GET /api/v1/revisions/{version_id}` composes it. **The `SELECT` names its
columns explicitly and never uses `*`**; write the T-017 reason at the statement even though `revision`
has no `search_text` column, because the habit is what phase 15 asserts and a habit with an exception is
not one.

Module docstring, in the density this repository uses, carrying four things: ADR-0002's *"a revision is
never updated and never deleted"* and the one carve-out; A-048's allocation rule and why the constraint
rather than a lock is the arbiter; A-014's *"the append shares the transaction"* and what a rollback
therefore leaves (neither); and the A-046 declaration — **this module handles a prompt body on every
call and logs none of it**, and every error it raises names a size or an identifier.
