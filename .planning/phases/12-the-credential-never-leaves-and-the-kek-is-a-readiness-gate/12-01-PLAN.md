<objective>
Close the server-side request forgery primitive that `base_url` is, at **both** moments the lock file
names, and prove the half that the lock file's own text cannot prove.

This is the phase's tracer: one thin path through every layer phase 12 touches — a management route, the
address guard, the pinned transport, the failure taxonomy, a metric and a log line — driven against the
live engine and a real socket.

**PITFALLS gap 2 restates AC-11 and the restatement is the whole point of this plan.** As written, AC-11
says a private-resolving `base_url` is refused *"when it is saved and again when it is dispatched"*, and
PITFALLS says of that sentence: it *"passes today with the TOCTOU still open."* Both refusals can be
implemented by checking, and a checked address that is then handed to an HTTP client as a **hostname** is
re-resolved by the client on connect. The window does not close; it moves from *between save and
dispatch* to *between check and connect*. The meaningful assertion is the one ADR-0047 describes: a
resolver that answers a **public** address on the validation call and a **private** one immediately
afterwards, and the proof that the connection went to the **first**.

So this plan does two things phase 11 could not: it makes the **resolver** an injected seam (a guard
whose resolver cannot be scripted cannot be tested against a resolver that changes its mind), and it
closes the **save-time** half against the real routes.

**D-200 — The production scheme allow-list is `{"https"}`. `http` is dropped.**
`checkpoint:decision`, adopted UNCONFIRMED, recorded in `deferred-items.md`.

Chosen: `PRODUCTION_POLICY.allowed_schemes == frozenset({"https"})`.

Rejected: **keeping `http` for a self-hosted OpenAI-compatible endpoint on a private network**, which is
the reason phase 11 left it in and is a real pilot shape. It does not survive its own premise. The guard
already refuses every loopback, link-local and private answer, so the **only** targets an `http` base URL
could still reach are **globally routable** ones — which means the one thing `http` buys is the
workspace's bearer credential travelling in cleartext across the public internet. That is precisely the
disclosure ADR-0014 and A-025 exist to prevent, arrived at through the field the SSRF guard is watching.
A private-network endpoint is refused for being private, not for being `http`, so removing `http` costs
that workspace nothing it had.

Consequence, stated: a pilot workspace pointing at `http://` gets a refusal naming
`scheme_not_allowed`, and the fix is a certificate rather than a Prope change. There is no such workspace
today; the pilot has not run (A-020).

Reversibility: **cheap** as code — one frozenset — and **one-way for any workspace already configured**,
because reversing it later means telling somebody their configuration was accepted and then was not.
None exists yet, which is why the decision is taken now rather than after the pilot.

**D-201 — The resolver joins the predicate as an injected seam, and both collapse into one
`AddressPolicy` object.**

Chosen: `resolve_and_pin(base_url, *, policy: AddressPolicy = PRODUCTION_POLICY, resolve: Resolver =
resolve_with_getaddrinfo) -> PinnedTarget`, where `AddressPolicy` is a frozen, slotted object carrying
`allowed_schemes: frozenset[str]` and `is_allowed: Callable[[str], bool]`.

Rejected: **leaving phase 11's bare `is_allowed=` parameter and adding a second, separate `resolve=`
parameter.** Two loose keyword arguments is two places a caller can override half the policy and think it
overrode all of it — a test that installs a permissive predicate and forgets the scheme set gets a
refusal it will "fix" by widening the production default. One object is one override.

Rejected: **monkeypatching `socket.getaddrinfo` in the test.** It is global, it is shared with every other
socket in the process including PostgreSQL's and the stub server's, and a test that patches DNS for the
whole interpreter to prove a property of one function has proved something about the interpreter.

The seam is why the restated AC-11 is assertable at all: `MutatingResolver` answers a globally routable
address on call 1 and a private address on every call after, and the assertion is arithmetic on what the
transport was given.

Reversibility: **cheap.** One dataclass and one parameter, in one module.

---

**D-202 — The guard runs before the credential is touched, on all three paths.**

Chosen: on save, on verify and on dispatch, the order is **validate the address, then decrypt (or seal)
the credential, then open the socket.** Never the reverse.

This is what turns SC2's second clause — *"and no request carrying the credential is issued"* — from an
observation into a structural property. Observing that no request was issued proves the socket did not
open on **this** run. Ordering the operations proves the plaintext was never in the process at all, so
there is no request that *could* have carried it, and no later refactor that reorders two lines can
quietly break it without the spy in `tests/integration/test_provider_base_url_refused_at_save.py`
noticing.

Rejected: **decrypting first because the credential is needed anyway on the happy path.** It is one
microsecond of pipelining bought with the guarantee the phase exists to make.

Reversibility: **cheap** as code; the property is the point, so the test is what holds it.

**D-203 — A Prope-side address refusal is its own error class: `address_refused`, `origin = prope`,
`fallback_eligible = true`, `retryable = false`. `OQ-067`.**

`docs/adr/0017`'s eight classes and `interfaces.md` INT-015's seven are both lists of things **the
provider** did. Neither has a member for a failure Prope itself decided, yet `error_total`'s declared
labels are `class, origin = prope | provider, fallback_eligible, retryable`, and the lock's own failure
modes describe at least four Prope-origin conditions (KEK unavailable, admission shed, address refused, a
deadline consumed before any request). Phase 10's table already added two of them.

Chosen: `address_refused`. **fallback_eligible true** — the gateway must serve the revision's fallback
answer, because the caller's prompt still needs one and nothing the caller did caused this.
**retryable false** — the refusal is deterministic against a configuration that has not changed, so a
retry is a second identical refusal and evaluation's transport-error retry policy (A-053) must not fire
on it.

`OQ-067` names the gap. It is **not** `OQ-055` or `OQ-060` — those two are about the same set being
written with different names and different counts. This one is about the set having no member of a
**kind** the metric's own label declares, and it is raised separately so a resolver answering the
naming question does not think it has answered this one.

Consequence: phase 10's `tests/architecture/test_error_taxonomy_is_closed.py` asserts *"exactly two
classes carry `origin = prope`"*. This plan moves it to three **in the same change**, with the reason
written at the constant. A count assertion that is edited without a reason is how a closed set stops
being closed.

Reversibility: **costly.** Two consumer modules branch on the taxonomy and every call record stores a
member of it.

**D-204 — A save-time refusal is a 422 that never names the address it rejected.**

Chosen: `422` with the A-045 envelope and a machine `code` the client translates (ADR-0053), carrying the
closed reason token — `scheme_not_allowed`, `unresolvable`, `blocked_address` — and **nothing else**. The
resolved address goes nowhere: not into the envelope, not into `details`, not into a log line, not into a
metric label.

INT-027 already gives `422` to *"when the live probe fails, with the record not saved active"*, and a
blocked address is refused **before** the probe. Same status, different `code`, because both are "the
configuration you submitted cannot be used" and inventing a fourth status for a refusal the client
handles identically would be a shape nobody asked for.

Rejected: **echoing the resolved address so the operator can debug it.** That is the SSRF answering
helpfully: an attacker who cannot reach `10.0.0.7` can still learn that `evil.example.com` resolves to it,
which is host discovery through an authenticated form. The operator's channel is
`verification_total{result=fail, reason=blocked_address}` plus their own DNS.

Reversibility: **costly** — the response shape is INT-027 and a client is written against it.

**The question.** ADR-0047 and the lock file both require an allow-list of schemes and neither names its
members. Phase 11 shipped `frozenset({"https", "http"})` with a comment saying phase 12 owns whether
`http` survives. It has to be decided now, because after this phase nobody in M4 looks at it again.

**Option A — keep `http` in the allow-list.**
*Pros:* a self-hosted OpenAI-compatible endpoint is a legitimate pilot shape and many of them ship
without TLS. `interfaces.md` and the lock file both say "allow-list" and neither says "https only", so
keeping both is the reading that adds nothing to the spec. It also means no phase-11 test changes.
*Cons:* the private-range refusal already blocks every loopback, link-local and private answer, so the
**only** address an `http` base URL can still reach is a globally routable one. The single behaviour
`http` therefore enables is the workspace's bearer credential crossing the public internet in cleartext —
readable by every hop — which is the exact disclosure ADR-0014's envelope encryption and A-025's
never-returned rule exist to prevent, reached through the one field the SSRF guard is already watching.

**Option B — `frozenset({"https"})`.**

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the dashboard -> `base_url` (B2) | A workspace admin types an arbitrary URL into a field the server then fetches **with a bearer credential attached**. This is the SSRF primitive, and it is authenticated on both sides. |
| provider-access -> the workspace's upstream provider (B3) | **Prope's only outbound internet egress.** |
| the resolver -> the guard | DNS is a third party's answer and it is attacker-influenceable between any two calls. This boundary is the whole of ADR-0047. |
| the guard -> the socket | The gap ADR-0047 closes. Anything that re-resolves in this gap re-opens the hole. |
| a refusal -> the caller | An error body that names the address it refused is host discovery through an authenticated form. |
