<objective>
Assert the project's single strongest form of the credential rule.

`.claude/CLAUDE.md`'s constraints and `00_context.md#constraints` both say it without qualification:
*"Provider credentials are supplied by the workspace, encrypted at rest, never returned by a read API,
and redacted in logs and audit records."* AC-1 turns that into six read paths — **list, detail, after
update, in an error body, and in the property-history event** — and adds the only thing that may cross:
*"the only credential-derived value present is its last four characters."*

**The method is the point, and it is not a field check.** ADR-0014 already made one half structural: the
ciphertext lives in its own table, so every configuration read path is incapable of returning it and no
reviewer has to notice an omitted column. The other half — the plaintext, the wrapped key, and the
places a credential ends up that nobody modelled — cannot be made structural, so it is asserted the way
phase 2 asserted the ceiling: **a marker placed where the secret travels, and the assertion that it
appears in zero bytes of everything that leaves the process.** Phase 2 searched `repr`, `asdict` and
every captured log record. This plan searches those plus every response body, every refusal body, every
column of every history row, and every metric label value.

---

**D-205 — The sweep is a corpus scan over serialized bytes, with a positive control on every path.**

Chosen: drive all ten INT-027 operations plus five refusal shapes, capture each **response body as
bytes** before anything parses it, and assert the forbidden corpus is absent from the union.

Rejected: **asserting per endpoint that the response model has no credential field.** That is a claim
about the model, and the failure this test exists for is a value that reaches the wire through something
that is not the model — an exception string, a validation error's `input`, a `details` dict, a serializer
that dumps an object it was handed. The lock file says it in terms: *"a constraint enforced by
remembering to exclude a column is a constraint that fails the first time someone writes SELECT *."*

Rejected: **scanning the parsed response.** Parsing is the application's own account of what it sent.

**Every absence assertion is paired with a positive control** — the last four are present, the route
answered the status it should, the history row exists and has the actor in it. A file of absence
assertions run against an application that 500s everywhere is green, and that is the way this class of
test actually fails.

Reversibility: **cheap.** It is a test.

---

**D-206 — Six renderings of five secrets, and a partial leak is a leak.**

The forbidden corpus for one configuration is five values — the credential **plaintext**, its stored
**ciphertext**, its **nonce**, its **wrapped data key**, and the **key-encryption key** — each in six
renderings: raw bytes, utf-8, standard base64, url-safe base64, lowercase hex, and the `repr` escape form
(`\xNN`). The base-64 pair is not paranoia: a `bytes` column serialized by a JSON encoder that does not
know what to do with it is base64 far more often than it is anything else, and the lock file's own line
is *"the base-64 length of a ciphertext is not a redaction."*

**And a run of five or more consecutive characters of the plaintext counts as a leak**, not only the
whole value. A truncation bug that emits the first half of a key has emitted half a key. The marker is
generated from a distinctive high-entropy alphabet precisely so a five-character collision with an
ordinary JSON body is not a thing that happens, and that reasoning is written at the constant so the
next reader does not lower the threshold to make a flake go away.

**The inbound credential field becomes a redacting type** (`pydantic.SecretStr` or the module's own
equivalent) in `schemas.py`, so that `repr`, `model_dump()` and a logger handed the model each fail
closed. This is the one production change the plan makes by default rather than in response to a finding.

Reversibility: **cheap** for the corpus; **costly** for the field type, because a `SecretStr` on the
request model changes what every call site downstream is holding.

---

**D-207 — The generated schema is a second line, and it is labelled as the weaker one.**

`app.openapi()` is walked for the ten provider routes and asserted to declare no response property whose
name is in a closed secret-shaped set (`credential`, `api_key`, `apikey`, `secret`, `token`, `password`,
`ciphertext`, `nonce`, `wrapped_dek`, `kek`). That is a name check and a name check is exactly what D-205
rejects as the primary method — so it is written down as the *second* line, in its own file, with a
docstring saying plainly what it proves (nobody declared a field called `credential`) and what it does
not (that no value reaches the wire). It earns its place for one reason: it catches the leak at the
moment somebody **adds the field**, in a diff, rather than at the moment a test happens to exercise that
route.

Rejected: **folding it into the sweep.** A weaker claim living next to a stronger one gets read as part
of it, and then somebody deletes the stronger one because "the schema test covers it".

Reversibility: **cheap.**

---

**The finding this plan expects to make, written in advance so it is not a surprise.** AC-1's *"in an
error body"* has one concrete, likely instance: **pydantic v2 puts the offending value into every
validation error dict under the key `input`.** A `POST /api/v1/providers` whose credential fails a length
or pattern rule therefore produces a `422` that echoes the credential back to the caller, through a code
path nobody wrote. Phase 8's `install_error_envelope` may already strip it; if it does not, this plan
strips it in `management_api.py` for **every** module rather than for this one, because the same shape is
waiting on every request model in Prope that carries a secret. This is named here rather than discovered
by the executor because it is the single most likely way SC1 fails.

**`tests/security/_forbidden_renderings.py`.** A module of pure functions, no fixtures, importable from
anywhere in the suite.

- `CREDENTIAL_ALPHABET` and `def make_credential_marker() -> str` — generate an `sk-` prefixed token of
  at least 40 characters from a **distinctive** alphabet. Write at the constant why the alphabet matters:
  the rule below treats a five-character run as a leak, and a five-character run drawn from
  `[A-Za-z0-9]` collides with ordinary JSON often enough to make the suite flaky. A marker built from an
  unusual but URL-safe set does not. **Do not lower the five-character threshold to fix a flake — change
  the alphabet.**
- `def forbidden_renderings(*secrets: str | bytes) -> frozenset[bytes]` — for each secret, emit: the raw
  bytes; utf-8 encoded; standard base64; url-safe base64; lowercase hex; uppercase hex; and the `repr`
  escape form. De-duplicate, drop anything shorter than five bytes (a rendering that short would match
  everything), and return the set. The docstring names each rendering with the reason it is there, and
  base64 gets the lock file's own sentence.
- `def substrings_of_at_least(value: str, n: int = 5) -> frozenset[bytes]` — every contiguous run of `n`
  or more characters. Used only for the **plaintext**, because a partial ciphertext is not a usable
  secret while a partial credential is a partial credential. Say that at the function, because applying
  it to all five values would make the assertion quadratic and no stronger.
- `def assert_absent(corpus: Iterable[bytes], forbidden: frozenset[bytes], *, evidence: str) -> None` —
  the one assertion. On failure it reports **which** rendering matched and **which** corpus item, and it
  reports **no more than the first eight bytes** of the match, because a test failure message that prints
  a leaked credential to CI logs has leaked it a second time. Write that sentence at the function.
- `def registry_label_values() -> list[str]` — every label value currently in the default registry, the
  same shape as `tests/broker/test_publish_confirm_failures.py`'s `_every_metric_label_value`. Import
  that one if it is importable; duplicate it with a comment naming the original if it is not.

## Trust Boundaries

|----------|-------------|
| provider-access -> the SPA (B2) | Ten management operations, six of which read. The credential is write-only across the whole seam and that is non-negotiable. |
| provider-access -> `history.history_event` | An **append-only, permanent** record. A secret written here cannot be taken back out at the database privilege level, which is what makes this the worst of the six paths. |
| process -> stdout / metrics registry | Log lines and label values leave the process and are retained by whatever scrapes or ships them. |
| the upstream provider -> provider-access | A third party's error body is attacker-influenced input, and a provider that echoes the `Authorization` header is how the credential re-enters Prope from outside. |
| an exception -> the caller | A traceback, a `repr`, or a validation error's `input` is the least-modelled path a secret takes out of a process. |
