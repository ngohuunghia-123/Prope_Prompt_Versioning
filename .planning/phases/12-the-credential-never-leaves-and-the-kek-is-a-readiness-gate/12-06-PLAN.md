**D-218 — The module's forbidden edges are asserted as an outbound import allow-list.**

Chosen: `tests/architecture/test_provider_access_boundaries.py` walks every file under
`src/prope/provider_access/` with `ast`, collects every `import` and `from … import`, and asserts that
every `prope.*` target is in an **allow-list** — the modules the lock file's `dependencies` block names
(`access_control`, `property_history`) plus the shared infrastructure every module uses (`db`,
`observability`, `session_auth`, `management_api`, `supervisor`).

Rejected: **a deny-list of the five forbidden modules** (`gateway`, `evaluation`, `prompt_registry`,
`call_ledger`, `release_control`). It is the obvious form and it is the one that fails to fail: it passes
for a module nobody has written yet, and M5 through M8 write four of them. An allow-list refuses the edge
that does not exist yet, which is the only edge that can still be prevented.

Rejected: **an import-linter contract.** `release-control`'s lock file names one and PITFALLS routes it to
phase 24; adding the tool here would take a decision that belongs to that phase and add a dependency this
phase did not argue for.

What this does **not** claim, written in the file: an AST walk sees imports, not behaviour. A module
reaching another module's tables through a raw SQL string is invisible to it — that is what phase 11's
`references.py` and `test_no_sql_interpolation.py` are for, and the file names both.

Reversibility: **cheap.**

**D-219 — `test_plan.e2e`'s BYOK journey is routed to phase 23, and the cross-milestone assignment is
raised. `OQ-066`.**

The lock file's `test_plan.e2e` is one clause and it is the module's whole reason for existing: *"Register
a provider from the dashboard → probe passes → the catalogue populates → a revision binds a model from it
→ the gateway serves a live call through it → the eval runner runs a suite through the same configuration
→ rotate the credential → within 60 s both paths use the new one, with no restart."*

It crosses prompt-registry (M5, phases 13-15), evaluation (M6, 16-18) and the gateway (M7, 19-21). **No
phase of M4 can assert it**, because four of the seven steps run through modules that do not exist. Phase
11's `deferred-items.md` §7 records it as *"not asserted anywhere … Unowned as a single test; phase 12
must route or declare it."*

Chosen: **routed to phase 23 by name.** PITFALLS §5 already establishes the precedent for this exact
shape — the cross-module route-table criteria *"cannot actually run until every module is mounted — i.e.
not before phase 23"* — and phase 23 is the first phase after every module in the journey is built.

Rejected: **declaring it unowned.** §9a's standard is *assert or route with a named owner*, and "somebody
later" is not a name.

Rejected: **asserting a stubbed version inside M4.** Four of the seven steps would be fakes, and a green
e2e test that fakes the majority of its own journey is worse than no test: it is the claim the journey
works, made by something that did not run it.

**`OQ-066` raises what routing it costs**, because it is not free: an acceptance clause belonging to
provider-access's lock file is now assigned to a phase of release-control's milestone, whose ROADMAP entry
does not mention it and whose planner has already run. That is a real assignment nobody has agreed to, and
it is exactly the class of thing §5 says to raise rather than absorb.

Reversibility: **cheap** as a routing decision; the OQ is what makes it visible.

**First, verify — on the disk, not in a plan.** Read `tests/security/test_kek_rewrap_v1_to_v2.py` and

actual test function:

1. after a V1 → V2 re-wrap, **every row reports `kek_version = 2`**;
2. **every credential still decrypts** to exactly what it held before — proven by digest, not by a round
   trip in the same process;
3. **V1 can be removed** — a ring holding only V2 decrypts every credential and a ring holding only V1
   decrypts none;
4. **no plaintext credential was written anywhere** during the operation — not to a column, not to a log
   line, not to a metric label, not to stdout;
5. the operation is **idempotent** — running it again against a corpus already at V2 changes no byte.

Phase 10's plan claims a sixth property worth checking too: `ciphertext` and `nonce` **byte-identical**
