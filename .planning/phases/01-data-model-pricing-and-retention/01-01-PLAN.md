**Planner resolutions of the six Claude's-Discretion items** (from RESEARCH.md `## Resolving Claude's Discretion`, adopted as written):

1. **Money** — `numeric(20,10)` for `input_price_per_1k`, `output_price_per_1k`, `monthly_limit`, `per_run_limit`, `cost`, `total_cost`. Exact decimal arithmetic, quantised to 10 decimal places with `ROUND_HALF_EVEN`. **Never quantised to a currency's minor units** — a representative per-call cost of ~0.00007 becomes 0.00, which is the cost of zero success criterion 2 forbids.
2. **Effective-date boundary** — half-open `[effective_from, next effective_from)`; predicate `effective_from <= created_at`, so a call landing exactly on an `effective_from` resolves to the **new** row. "Rows exist but every `effective_from` is later than the call" is `unpriced` on exactly the same footing as "no row at all".
3. **Write-path seam** — one async `write_records(session, records, *, retention_window)` in `src/prope/call_ledger/writer.py`, and it **does** upsert `workspace_spend` inside its own transaction (A-103, ADR-0040). Deferring the aggregate would make Phase 2 rewrite the transaction boundary of a function three phases depend on.
4. **Retention shape** — ship `delete_expired_bodies(sessionmaker, workspace_id, *, now, chunk_size, max_chunks)` plus its integration test. **No scheduler, no workspace enumerator** (see OQ-C below).
5. **Indexes and constraints** — RESEARCH.md Pattern 1 (index list) and Pattern 4 (CHECK set) adopted verbatim. `text` + named `CHECK`, never a native PostgreSQL `ENUM` (Pitfall 4).
6. **`prope_report` grants** — granted in Phase 1, in the same revision as the role's tables. ADR-0037 already contemplates that this is a full-read credential.

**Planner decisions the repo does not state** (recorded, not inherited):

- **Alembic revision layout: one revision per *slice*, guarantee-per-*helper*.** RESEARCH.md Pattern 10 recommends one revision per kind of guarantee (tables / RLS / grants). TRACER_MODE requires the first table's whole guarantee stack in one applied revision, so this phase instead uses `0001_roles_and_schemas`, `0002_call_record`, `0003_ledger_tables`, and preserves per-kind greppability through `alembic/ddl.py`: every policy is an `enable_tenant_rls(...)` call and every grant line is a `grant_table(...)` call, so a reviewer greps the helper name rather than the revision file. D-04's one linear hand-written chain is unchanged.
- **`alembic_version` lives in `public`** via `version_table_schema="public"` in `env.py`. Inside `ledger` it would fail D-06's coverage walk for having no `workspace_id`, and the fix would be a `GLOBAL_TABLES` entry that dilutes a security-relevant file with a bookkeeping table.
- **Ownership**: revision 0001 runs as the bootstrap superuser (it needs `BYPASSRLS` for `prope_report`); every revision from 0002 onward opens with `assume_migrate_role()` so all DDL is owned by `prope_migrate`, which is what ADR-0035's owner-bypass depends on.
- **Role passwords are set out-of-band, including in the test rig.** The migration bakes none (D-05, ADR-0032); `tests/conftest.py` issues `ALTER ROLE … WITH PASSWORD` as the container superuser after `alembic upgrade head` so the two role-scoped engines can connect.
- **Python version reconciliation**: three versions were in play — ADR-0026 pins 3.13.x, only 3.14.2 is installed, and `ruff.toml` declared `py311`. All three are reconciled to **3.13** in Task 1.

## Open questions carried upstream (do NOT resolve here, do NOT edit any spec)

- **OQ-A** — `docs/adr/0035-tenant-isolation-is-a-database-policy.md:43` and `docs/adr/0045-…:89-90` write the policy predicate with a `::uuid` cast, which raises `invalid input syntax for type uuid` against a `wsp_`-prefixed ULID. Phase 1 writes the first five policies in the project and every later module inherits the type. Adopted reading above; the ADR wording needs upstream correction.
- **OQ-B** — `docs/modules/call-ledger.lock.yml` declares `PUT /api/v1/workspaces/{id}/retention` in `apis.exposes` while no table in `data.owns` carries a retention column. The setting has no declared home. Phase 2 needs the answer.
- **OQ-C** — the retention job's cross-tenant workspace enumeration has no Phase-1 mechanism. ADR-0051 names `access.list_workspaces()` as *the* mechanism and names call-ledger's retention job directly, but the `access` schema does not exist until Phase 7 and access-control sits in call-ledger's `forbidden_dependencies`. Whether a `GRANT EXECUTE` on an `access` function counts as the forbidden edge is settled nowhere. **This phase does not solve it and must not add a fifth `SECURITY DEFINER` function** — a project test asserts the sanctioned set is exactly four.
- **OQ-D** — `docs/adr/0040-…` says "bounded chunks inside that workspace's transaction" (singular). Adopted reading above; the wording needs upstream clarification.
- **OQ-E** — gateway's GATE-04 describes a pre-first-byte fallback recorded "with zero tokens and zero cost", while this phase's encoding gives that row `usage_status='unknown'` / `cost_status='not_applicable'` / NULL cost / NULL tokens — never a zero. Phase 1 asserts the never-zero reading in a unit test (plan 01-03) so Phase 19 inherits it rather than inventing a zero. The two documents use different words for the same row.
- **`data.owns` vs `apis.exposes`** — the general form of OQ-B: the lock file exposes a route whose state has no owned table. Raised so the choice is made upstream rather than by whoever writes the Phase 2 route.

## Flagged assumptions (surfaced, not silently adopted)

- **A9 — the migration connection is a superuser.** `CREATE ROLE prope_report LOGIN BYPASSRLS` requires it. In testcontainers the default user *is* superuser, so this passes locally and would fail on a real deploy where a DBA issued a non-superuser `prope_migrate`. Named here rather than assumed.
- **A10 — truncate-between-tests, not transaction-rollback isolation.** The rollback pattern is the conventional one and would silently break every cross-tenant test (Pitfall 3b: `session.begin()` becomes a savepoint, and the transaction-scoped GUC survives it).
- **A1 — `greenlet` pinned explicitly** for SQLAlchemy's asyncio extension. Surfaces immediately as an import error if wrong.
- **Canon-referral breadcrumbs (prohibition probe, stage 2).** Three recalled must-NOTs are canon security/compliance items owned by dedicated tooling and are **not** minted as prohibitions: SQL injection through the tenant identifier, cross-tenant access control, and generic PII/data-retention compliance are canon — covered by `/gsd-secure-phase` and by the `<threat_model>` blocks in all four plans (T-01-02, T-01-01, T-01-13/T-01-21). Recorded so their absence from `must_haves.prohibitions` reads as a decision rather than a miss. Three bespoke prohibitions survived and are authored descriptor-less, one per plan: no second resting place for a body (01-02), no estimated or back-filled cost (01-03), no read path for `ledger.call_body` (01-04).
- **Package legitimacy** — all 15 PyPI packages returned `[SUS]`, uniformly for `unknown-downloads` (PyPI's JSON API exposes no download counts) and `too-new` (the heuristic reads latest-release date, not package age). No `[SLOP]`. Every package is named by an in-repo specification rather than discovered by search. The researcher's written disposition is that this is a metadata artefact and that 15 blocking checkpoints would be noise; Task 1's `<verify>` carries a single `human-check` covering the whole set instead.
