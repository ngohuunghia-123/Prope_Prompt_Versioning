## D-167 — ADR-0017's eight class names are adopted; INT-015's seven are not

**Chosen.** `credential_rejected`, `rate_limited`, `upstream_unavailable`, `timeout`,
`model_not_available`, `content_filtered`, `invalid_request`, `provider_contract_violation`.

**Three authorities name three different closed sets**, and this is the same shape as the vocabulary
that was written as 30 in six places and 31 in five:

| Authority | The set it names |
|---|---|
| `docs/adr/0017-…` line 31 | `credential_rejected`, `rate_limited`, **`upstream_unavailable`**, `timeout`, `model_not_available`, `content_filtered`, **`invalid_request`**, `provider_contract_violation` — **eight** |
| `docs/architecture/interfaces.md` INT-015 line 552 | `timeout`, `rate_limited`, `credential_rejected`, **`upstream_5xx`**, **`bad_request`**, `content_filtered`, **`transport`** — **seven**, three spelled differently, two missing |
| `docs/modules/provider-access.lock.yml` | uses `rate_limited`, `credential_rejected`, `invalid_request`, `upstream_unavailable` in its own `failure_modes` and `external_services` prose, and names `ProviderContractViolation` in `risks` |

**The lock file is authority rank 1** (ORCHESTRATION §1) and it spells three of ADR-0017's names
itself, in its own text, while spelling none of INT-015's. ADR-0017 is the document that **decides**
the taxonomy; INT-015 is a registry **summarising** it for consumers. Two of three authorities agree
and the middle-ranked one is the outlier — which is a different situation from a straight precedence
conflict and is why this does not simply follow rank.

**On INT-015's `transport`, which has no ADR-0017 equivalent.** A-053 gives evaluation *"retry
transport errors only"*, so something has to carry that distinction. It is carried by **`retryable`**,
not by a class: ADR-0017 says in as many words that *"Evaluation reads `retryable` and applies A-053"*.
A `transport` class would put the same judgement in two places, which is the drift ADR-0017 rejected
"let each caller classify" over. Recorded in `OQ-055` so the answer is a decision rather than an
omission.

**Rejected: adopt INT-015's spellings** because it outranks the ADR. Refused because the lock outranks
both and uses the ADR's, and because `upstream_5xx` is a name that describes a status code rather than
a condition — a connection reset has no 5xx and belongs in the same class, which is exactly what
`upstream_unavailable` says and `upstream_5xx` does not. `prope_gateway_fallback_total`'s declared
`reason` label uses `upstream_5xx`, so **the gateway's own metric will need a translation or a
correction** — that consequence is stated in `OQ-055` rather than left for phase 19 to discover.

**Reversibility: costly.** Phases 16, 18, 19, 20 and 21 branch on these names, and every call record
stores one, so a rename after traffic exists is a rename plus a data migration.

## D-168 — Two `prope`-origin classes are added; the closed set is ten, not eight

**Chosen.** `kek_unavailable` and `admission_shed` join the eight, both with `origin = prope`.

`origin` is a declared fact with exactly two values, and ADR-0017 documents `prope` as *"Prope's own
admission gate (ADR-0016)"* — but **not one of its eight classes has that origin.** Two of this
module's own refusals therefore have nowhere to land:

- **AC-12** requires that with the KEK unavailable *"the dispatch fails with a class distinct from
  every provider-origin class"*. A dispatch has to return something, and none of the eight is it.
- **AC-6 / PA-06** requires that a shed batch dispatch is counted and reported. `shed_total` is a
  declared metric, so shedding is an observable outcome; `dispatch()` returns `DispatchResult |
  DispatchError` and a shed dispatch produces neither a result nor one of the eight.

**Rejected: reusing an existing class with `origin = prope`.** It satisfies AC-12's letter — the
`(class, origin)` pair is distinct — and it is refused because the class is what a human reads in an
alert and a call record. `upstream_unavailable{origin=prope}` is the exact confusion ADR-0014 and the
`ProviderKekUnavailable` alert exist to prevent: *"This must never be mistaken for a provider outage,
which is why it is its own gauge and its own page."* Its own gauge deserves its own class.

**Rejected: letting phase 11 and phase 12 each add their own member when they need it.** A closed set
that grows in three phases is not closed, and it is precisely how a vocabulary comes to be written as
30 in six places. Both members are declared **here**, with no producer yet, on D-40's precedent:
`kek_unavailable` is produced by phase 12 (PA-12) and `admission_shed` by phase 11 (PA-06). Their rows
in the table are complete today and their increment sites are not, and the plan says which is which so
a later reader does not read an unused member as dead code.

**Reversibility: costly**, for D-167's reason.

## D-169 — Classification takes the status, the provider error code and the finish reason; never the status alone

**Chosen.** `classify_failure(*, status, error_code, error_type, finish_reason, usage_present)` — and
the transport-level entry point is separate, taking an exception.

**AC-5 is what forces this and it is easy to miss.** It requires *"a content-policy refusal and a 400
on a bad parameter"* to map to **different classes**. On an OpenAI-compatible endpoint both are a 400,
distinguished only by the error object's `code` / `type`. A classifier keyed on status alone cannot
express AC-5, and would pass a test suite that only ever sent one kind of 400.

It also makes ADR-0017's central rejection concrete. *"The gateway classifies from the HTTP status.
Rejected: status codes are not portable across providers … It also cannot see the transport-level
cases at all, since by the time an error reaches the gateway as a status there was no status."* The
signature is that rejection written down: there is no way to call this function with only a status and
get an answer for the interesting cases.

**Rejected: one function taking a whole `httpx.Response`.** It puts an HTTP type in the signature of a
pure function and makes every unit-test row construct a response object; it also drags `httpx` into a
module that otherwise needs no dependency at all. The adapter layer (phase 11) extracts the five
fields; this module maps them.

**Reversibility: cheap.** A signature inside one module, with two call sites, both in this phase's
successors.
</objective>

### `src/prope/provider_access/failures.py`

Module docstring at `crypto.py`'s density, carrying five things:

1. **What this module is for**, in ADR-0017's framing: two consumers, opposite responses, one
   taxonomy. The gateway reads `fallback_eligible` and applies ADR-0013's pre-first-byte rule;
   evaluation reads `retryable` and applies A-053. Both read the same value and neither reads the
   other's flag.
2. **The three prohibitions, with their reasons**, not as a list of don'ts: no retry (A-088 — and note
   that this is how A-084's *never* and A-053's *transport only* are **both** true without either
   policy living here); no fallback decision (A-034, ADR-0013 — `fallback_eligible` is a fact, and a
   module that served the fallback itself could hand one to an eval run, which A-034 forbids outright);
   and no provider error **message** anywhere, ever, because *"a provider that echoes the request back
   inside its error message is the ORDINARY way a prompt body reaches a log file"* (T-026).
3. **Why the redaction is an allow-list**, quoted: *"denying a known list of fields does not survive a
   provider adding a new one."*
4. **D-167 and D-168**, with `OQ-055` cited by name and the sentence that this module ships ADR-0017's
   spellings while INT-015 carries three different ones.
5. **The two members with no producer yet** — `kek_unavailable` (phase 12, PA-12) and `admission_shed`
   (phase 11, PA-06) — so a reader does not delete them as dead code.

Then:

```python
class ErrorClass(StrEnum):
    credential_rejected = "credential_rejected"
    rate_limited = "rate_limited"
    upstream_unavailable = "upstream_unavailable"
    timeout = "timeout"
    model_not_available = "model_not_available"
    content_filtered = "content_filtered"
    invalid_request = "invalid_request"
    provider_contract_violation = "provider_contract_violation"
    kek_unavailable = "kek_unavailable"          # origin=prope, produced in phase 12
    admission_shed = "admission_shed"            # origin=prope, produced in phase 11


class Origin(StrEnum):
    provider = "provider"     # the upstream said so
    prope = "prope"           # Prope's own gate or Prope's own missing key
```

`StrEnum` rather than a bare constant set, and the docstring says why: the value goes into a metric
label, a log field, and eventually a `ledger.call_record` column, and a `StrEnum` member is a `str`
everywhere those three need one while still being an enumerable closed set for the equality assertions
in `tests/architecture/test_error_taxonomy_is_closed.py`.

**`ErrorFacts`**, frozen and slotted: `origin: Origin`, `fallback_eligible: bool`, `retryable: bool`.

**`CLASSIFICATION: Mapping[ErrorClass, ErrorFacts]`**, wrapped in `MappingProxyType` so it cannot be
mutated at runtime — the same posture `load_action_registry` takes. Every row carries a comment
justifying **the two flags**, not the class, because the flags are what a reasonable person gets wrong:

| class | origin | fallback_eligible | retryable | The comment must say |
|---|---|---|---|---|
| `credential_rejected` | provider | **true** | **false** | ADR-0017: fallback-eligible but not retryable, *and it pages*. The workspace revoked the key at the provider and did not tell Prope; the fallback hides the cause perfectly, which is why `ProviderCredentialRejected` is a page rather than a warning |
| `rate_limited` | provider | **true** | **true** | The one class that is both. `retry_after_ms` is carried when the provider sent a `Retry-After` |
| `upstream_unavailable` | provider | **true** | **true** | A 5xx **or** a connection reset — the reason this class is not named after a status code (D-167). Retryable because a second attempt could plausibly succeed; whether anyone makes one is the caller's, not this module's |
| `timeout` | provider | **true** | **true** | ADR-0017: *"A timeout is both, but only for a caller with no latency budget"* — which is exactly why `retryable` is advice and not an instruction. `origin = provider`, because the deadline is Prope's but the silence is the upstream's; `prope` is reserved for the two things Prope itself refused |
| `model_not_available` | provider | **true** | **false** | ADR-0017 groups it with `credential_rejected`: both fallback-eligible, neither retryable, both page. *"The fallback buys hours; the alert stops those hours becoming a quarter"* |
| `content_filtered` | provider | **false** | **false** | ADR-0017's first "reasonable person gets this wrong": the provider **did not fail, it refused**, deliberately and deterministically. A canned answer in its place replaces a safety refusal with something that looks like a normal response, every time |
| `invalid_request` | provider | **false** | **false** | ADR-0017's second: a parameter the provider rejects is a defect in an **approved revision** (A-097), and masking it would let a revision whose binding never successfully ran sit in production looking healthy. The eval run is where this is meant to be caught |
| `provider_contract_violation` | provider | **true** | **false** | The response parsed but broke the contract — no usage object, a malformed stream frame, a redirect. Fallback-eligible because the upstream genuinely failed to deliver; **not** retryable because it will do the same thing again. This is the class `ProviderContractViolation` fires on |
| `kek_unavailable` | **prope** | **true** | **false** | Phase 12. Fallback-eligible on a stated argument: with no key, **every** call in Prope fails, and serving fallbacks beats returning 500s to every consuming product at once. Not retryable — recovery is `.env` plus a restart. `origin = prope` is what makes AC-12's *"distinct from every provider-origin class"* structurally true |
| `admission_shed` | **prope** | **true** | **true** | Phase 11. Prope's own ceiling, not the provider's — which is why `origin` exists as a label at all (A-095), so *"the two are never one number"*. Retryable in the ordinary sense that a slot frees; the interactive path still fails fast rather than queueing, because *"on the hot path, a queue is just a slower error"* |

error_class: ErrorClass

construction site can set inconsistently, and the whole value of a table is that there is one place
the answer lives. This is also what makes the `test_error_taxonomy_is_closed.py` set equality a
complete assertion rather than a partial one.

**`classify_failure`**, pure:

```python
def classify_failure(
    *,
    status: int | None,
    error_code: str | None = None,
    error_type: str | None = None,
    finish_reason: str | None = None,
    usage_present: bool = True,
) -> ErrorClass
```

The rules, in the order they are evaluated, with the order itself justified in the docstring because
the ordering is where the bugs are:

1. **A successful response can still be a failure.** `status` in the 2xx range and
   `finish_reason == "content_filter"` → `content_filtered`. This is checked **first**, before any
   status-range logic, because nothing failed at the HTTP layer and a status-first classifier would
   return "no error" and hand a safety refusal to the caller as a normal answer.
2. 2xx and `usage_present is False` → `provider_contract_violation`, and **increment
   `usage_missing_total`** at the return. This is A-030's admission rule failing *after* the fact and
   is the alert ADR-0013 asked this module to own (`ProviderUsageMissing`).
3. 3xx → `provider_contract_violation`. Redirects are disabled (ADR-0047), so a 3xx is a resolution the
   guard never saw; *"a provider that redirects its completions endpoint fails verification rather than
   being followed at dispatch time."*
4. 401, 403 → `credential_rejected`.
5. 429 → `rate_limited`.
6. 404 → `model_not_available` **if** `error_code` or `error_type` contains `model` (case-insensitive),
   else `invalid_request`. Comment the two real shapes this covers: an OpenAI-compatible endpoint
   answering `model_not_found` for a retired model, and a wrong path answering a bare 404.
7. 400, 422, and any other 4xx → `content_filtered` **if** `error_code` or `error_type` matches the
   content-filter token set, else `invalid_request`. **This is D-169 and AC-5's whole difficulty**, and
   the token set is a module constant, closed and commented:
   `CONTENT_FILTER_TOKENS = ("content_filter", "content_policy", "responsible_ai_policy")` — three
   values because they are the three spellings OpenAI-compatible endpoints actually use, and a
   substring match rather than an equality because providers prefix and suffix them. Say plainly that
   this list **will** need extending per adapter and that ADR-0017 already priced it: *"A new provider
   adapter must fill in this table, and that is the honest cost of adding one."*
8. 5xx → `upstream_unavailable`.
9. Anything else, including `status is None` with no other signal → `provider_contract_violation`, with
   a comment that the default is deliberately the class that means *"the response was not something we
   can act on"* rather than the class that means *"the upstream is down"*. **A default that reads as an
   outage is a default that pages the wrong person.**

**`classify_transport(exc: BaseException) -> ErrorClass`**, also pure, mapping by exception type name
rather than by importing `httpx`:

- a name containing `Timeout` → `timeout`
- `ConnectError`, `ReadError`, `WriteError`, `ConnectTimeout` (already caught by the first rule),
  `RemoteProtocolError`, `PoolTimeout`, any other `TransportError` → `upstream_unavailable`
- a JSON decoding failure or a `KeyError`/`ValueError` from parsing → `provider_contract_violation`

Match on `type(exc).__name__` against module constants, and **write the argument for that at the
function**: importing `httpx` here would make a pure classification module depend on the HTTP client,
which is what D-169 refused, and would make this module untestable without one. The cost is honest and
stated — a rename in httpx breaks the match silently — and the mitigation is that
`tests/unit/test_failure_classification_table.py` exercises the real exception classes by constructing
them, so a rename is a red test rather than a wrong classification.

**`retry_after_ms(header: str | None) -> int | None`.** INT-015 and ADR-0017 both promise
`retry_after_ms` *"when known"*. Parse both RFC-9110 forms: delta-seconds (an integer) and an HTTP
date, the latter with `email.utils.parsedate_to_datetime` and a clamp at zero for a date already past.
Return `None` for absent, empty, or unparseable — **never a default**, and the docstring says why in
the project's own voice: *never zero, and no fourth state*. A substituted default would have a caller
retry on a schedule the provider never asked for.
