nor CL-09 asks for `ledger.workspace_retention`. It is here because D-09 put it here and because
`PUT /api/v1/workspaces/{id}/retention` is one of the `/api/v1` routes the ROADMAP names for Phase 2,
and a route that persists a window the writer never reads would be a route that lies for a phase.

**Why this plan runs in wave 1, beside a plan that opens with a blocking decision checkpoint.** Plan
02-01's first task is a `checkpoint:decision` on classic-durable versus quorum queue type. That
checkpoint blocks 02-01, and the obvious reading is that everything else should wait behind it. This
plan does not, and the reason is that its scope is provably orthogonal to every outcome the checkpoint
can have — not merely "probably unaffected", but with no shared surface at all:

- **No file overlap.** This plan's five files are a migration, `retention_settings.py`, `writer.py`,
  `retention.py` and an OQ file. None appears in 02-01's `files_modified`, and 02-01 touches nothing
  under `alembic/` or `ledger.*` DDL.
- **No import of anything the checkpoint decides.** Nothing here imports `prope.broker`, opens an AMQP
  connection, or reads a queue argument. The queue type is a property of `topology.py`, which this plan
  never sees.
- **The checkpoint's whole decision space is queue-type arguments.** Both branches — classic durable
  with `reject-publish-dlx`, or quorum with the overflow behaviour it actually supports — change which
  `x-` arguments `WORK_QUEUE_ARGUMENTS` carries and nothing else. Neither branch changes what a
  retention window is, where it is stored, how it defaults, or what `write_records` does with it.
- **The dependency runs the other way and lands in wave 2.** 02-01's drain accepts a retention resolver
  through injection with a working default; it does not need this plan's reader to be correct. The two
  meet in `worker.py`, which is plan 02-03, in wave 2, after both have landed.

So the sequencing is deliberate: this is the phase's other independent starting point, and holding it
behind a decision that cannot touch it would idle a wave for no information. If the checkpoint somehow
returns an answer that does touch `ledger` DDL or `writer.py`, that is a signal the decision was scoped
wrongly — stop and re-plan rather than proceeding on this rationale.
