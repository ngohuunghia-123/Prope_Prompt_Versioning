  <behavior>
    - A job that returns cleanly is restarted, and the backoff delay resets to the base value.
    - A job that raises is logged and restarted after the current backoff, and the delay doubles up to a cap.
    - A job that raises does NOT cancel its siblings: with two jobs and one raising repeatedly, the other keeps running and its own iteration count keeps rising.
    - `asyncio.CancelledError` is re-raised, never swallowed and never counted as a crash.
    - Setting the stop event makes every job return and the supervisor return; nothing is left pending.
    - The stop event interrupts a backoff sleep rather than waiting it out, so shutdown latency is bounded by the current iteration, not by the cap.
    - An interval job runs its body, waits the interval, and runs again; setting the stop event during the wait ends it without running the body a second time.
  </behavior>
  <action>
Create `src/prope/supervisor.py`. D-14: one event loop, one process, an `asyncio.TaskGroup` supervising
named jobs, each restarted with exponential backoff, all draining cleanly on a stop signal. No scheduler
library — two interval jobs do not pay for APScheduler's misfire semantics, and A-012's surviving
*debuggable by one person* clause is the standing test. Separate per-job container commands are
rejected because ADR-0033 fixes the runtime at 7 services and 2 images, and that shape grows the service
count for every job any module adds.

Provide `supervise(jobs, stopping)` taking a mapping of name to zero-argument coroutine factory and an
`asyncio.Event`, creating one named task per job inside a `TaskGroup`. Provide the per-job wrapper that
loops until `stopping` is set: awaits the job, resets the delay on a clean return, re-raises
`CancelledError` untouched, and on any other exception logs `job_crashed` with the job name and no body
(A-046) before sleeping the backoff and doubling it up to a cap. Provide `interval_job(body, every,
stopping)` for a plain timer loop, which is what D-14 says a timer job is.

Name the two `TaskGroup` traps in the module docstring rather than leaving them to be discovered. First:
the *first* unhandled exception in any child cancels every sibling and the group re-raises an
`ExceptionGroup` — which is exactly why each job is individually wrapped and why the group itself must
never see an exception in normal operation. Second: the backoff sleep must be interruptible by the stop
event, not a bare `asyncio.sleep`, or a shutdown during a 60-second backoff waits 60 seconds.

Provide `install_stop_handlers(loop, stopping)` that installs `SIGTERM` and `SIGINT` handlers setting
the event, guarded by a `sys.platform` check because `add_signal_handler` is not implemented on Windows,
with the fallback path stated in the docstring. `stopping` is a plain event a test can set directly, so
the graceful-shutdown behaviour is exercisable on the machine this is written on.

Record the accepted cost D-14 states rather than hides: restart, backoff and graceful shutdown become
code this project writes and tests. And record the forward constraint — this supervisor must
accommodate evaluation's claim loop (ADR-0049, Phase 16) and release-control's overdue sweep
(ADR-0051, Phase 22) without being redesigned, so a job is a coroutine factory and an interval, and the
supervisor knows nothing else about it.
