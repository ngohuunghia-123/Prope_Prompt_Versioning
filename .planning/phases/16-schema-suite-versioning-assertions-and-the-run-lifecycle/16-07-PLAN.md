One module, six tests. Its docstring states what the coverage walk (`tests/architecture/test_tenant_coverage.py`)
does and does not prove: the walk proves a column, a setting and a policy **exist** on all four tables;
this file proves what they **do**, in the direction that fails open, on all four.

Seed, as the owner through `migrate_engine`, in one setup block every later test reuses: in
`WORKSPACE_A` — one `eval_suite` (`suite_version=1`, `case_count=1`), one `eval_case` on it, one
`eval_run` on it (`role='candidate'`, `status='queued'`), one `case_result` on that run. The identical
shape in `WORKSPACE_B`. Seeding as the owner keeps the seed independent of the policy under test.

**Test 1 — `test_the_wrong_tenant_sees_only_its_own_rows`.** For each of the four tables, inside
`workspace_transaction(app_sessionmaker, WORKSPACE_B)`: `SELECT count(*)` returns exactly B's own row
count (1), and a `SELECT` filtered to A's known id returns 0 rows. Then, in a separate block through
`migrate_engine`, the same unfiltered count returns 2 — the positive control, without which the whole
file could pass against an empty database (the failure `test_append_only_privilege.py`'s own docstring
names). Do this once per table, not once for the schema — a shared helper parametrised over
`(table, id_column, seeded_a_id, seeded_b_id)` is the right shape and keeps the four assertions from
collapsing into one that only happens to exercise `eval_suite`.

**Test 2 — `test_no_tenant_sees_nothing_rather_than_everything`.** Open a session from
`app_sessionmaker` with **no** `workspace_transaction` — a bare `session.begin()`, nothing else. For
each of the four tables, `SELECT count(*)` returns **0**, and no exception is raised getting there.
Write the paragraph at this test: a policy predicate written with the one-argument `current_setting`
would *raise* here (`unrecognized configuration parameter`), and one written with a `COALESCE` default
would return every workspace's rows. Only the two-argument form with no default produces the direction
this project needs — nothing, quietly, rather than an error or everything.

**Test 3 — `test_a_mis_stamped_insert_is_refused_not_merely_invisible`.** Inside
`workspace_transaction(app_sessionmaker, WORKSPACE_A)`, attempt an `INSERT` into each of the four
tables with every column correctly filled **except** `workspace_id`, which names `WORKSPACE_B`. Expect
a `DBAPIError` naming the row-level security policy (`new row violates row-level security policy`) on
all four. Say at the assertion why this is worse to get wrong than a read leak: without the `WITH
CHECK` half, the row would be *written* and then be invisible to every tenant-scoped query in the
system, including the workspace that unknowingly wrote it — worse than a refusal, because nothing ever
surfaces it.

**Test 4 — `test_a_case_cannot_be_parented_to_another_workspaces_suite`.** Inside
`workspace_transaction(app_sessionmaker, WORKSPACE_A)`, attempt an `INSERT INTO evaluation.eval_case`
correctly stamped `workspace_id=WORKSPACE_A` — so the row-security policy is satisfied — but naming
