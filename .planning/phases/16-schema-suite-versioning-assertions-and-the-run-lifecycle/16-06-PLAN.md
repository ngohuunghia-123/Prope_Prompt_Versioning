**a comparison that refuses rather than lies, and a baseline that is reused by identity rather than
re-measured by habit.**

`comparison.py` is pure — no session, no SQL, no clock. It holds `pair_runs`, which refuses a pair whose
two runs carry different `suite_id`s with `CROSS_SUITE_VERSION_COMPARISON` naming **both** suite

## D-294a — the withholding precedence is an ordered tuple, and `CASE_ERROR` is first

**Chosen.** Six reasons can hold at once and the answer must be one of them, so the order is data rather
than a chain of `if`s a reader has to trace:

| # | Reason | Condition |
|---|---|---|
| 1 | `CASE_ERROR` | the caller reports either run had a case with `outcome='error'` (A-057) |
| 2 | `NO_BASELINE` | `baseline is None` (A-060) |
| 3 | `UNPRICED` | either side's `unpriced_count > 0` |
| 4 | `UNKNOWN_USAGE` | either side's `unknown_usage_count > 0` |
| 5 | `NOT_PRICED_YET` | either side is `None`, or either side's `cost is None` |
| 6 | `CURRENCY_MISMATCH` | the two currencies differ (A-107 — no conversion, ever) |

**`CASE_ERROR` first**, because it is the only member of the six that says the **measurement** is
invalid rather than that the **money** is missing. A-006 fixes the unit as one *full* suite run on each
side, so a run with three errored cases is not that unit at all, and a reviewer told *"no baseline"*
about a run whose real problem was a rate-limited key would go looking for a baseline.

**`UNPRICED` before `NOT_PRICED_YET`**, because the more specific cause wins: `unpriced_count > 0` names
a missing price row that appears on CL-04's unpriced worklist and that an operator can act on, while
`cost is None` with `unpriced_count == 0` means there is simply nothing to price yet — which is this
phase's own state (D-292) and is nobody's ticket.

**`CURRENCY_MISMATCH` last**, because it is the only one that is not *checkable* until the others have
passed: a `None` cost carries a `None` currency (`RunTotals`' own invariant, and
`ck_workspace_spend_total_cost_carries_currency` one schema over), so a currency comparison made earlier
would fire on two absent currencies.

**Rejected: computing every applicable reason and returning a set.** The wire carries one `code` that
the client translates (ADR-0053); a set would move the choice to the SPA, in a language where the
catalogue key is the whole rendering.

**Rejected: a seventh reason for "no candidate totals".** The enum is closed at six (D-294) and a
candidate with no totals has, by construction, nothing priced — `NOT_PRICED_YET` is the true statement,
and Phase 17's `ComparisonBlock.has_completed_run` is where "there is no candidate run at all" is
rendered.

— **Reversibility:** costly. Phase 17's rollup folds these values and the SPA's catalogue keys off them.

## D-294b — `CostDelta`'s invariant is enforced in `__post_init__`, not asserted by a test alone

**Chosen.** `CostDelta(amount, currency, ratio, withheld_reason)` raises `ValueError` unless exactly one
of two shapes holds: `(amount is not None and currency is not None and withheld_reason is None)`, or
`(amount is None and currency is None and withheld_reason is not None)`.

The alternative — a test that checks every construction site — proves what the sites a test happened to
call did. This is `HistoryEventDraft.__post_init__`'s posture one module over, and it is what turns
SC1's *"withheld with a stated reason"* from a promise into a thing that cannot be broken by
forgetting. A number with no unit is the shape this project refuses everywhere; so is a blank with no
reason.

**Rejected: `cost_delta: Decimal | None` with the reason on a sibling field, unvalidated.** That is the
shape D-294 rejected, restated: a `None` states nothing and the review screen has to guess which of six
reasons it meant.

— **Reversibility:** cheap.

## D-293a — the baseline predicate does NOT filter on `role`, and that is the decision

**Chosen.** `resolve_baseline` looks for *the most recent `completed` run whose `version_id` equals the
prompt's current `released_version_id` and whose `suite_id` equals the candidate's* — ADR-0004's rule,
**literally**, and that rule names no role.

Three grounds. ADR-0004's sentence is the specification and it says `completed`, `version_id`,
`suite_id` and nothing else. The requirement being served is *not re-dispatching*, and its strongest
form is exactly the case the role filter would exclude: a revision is reviewed as a **candidate**, is
approved and released, and the next review's baseline is that same run — already measured, at the same
yardstick, against the revision that is now in production. And D-290's index is
`ix_eval_run_baseline_pairing (workspace_id, suite_id, version_id, status, finished_at DESC)` — the
schema this phase ships carries **no `role` column in the index that exists to serve this query**,
which is the design saying the same thing.

**Rejected: `AND role = 'baseline'`.** It costs a residual filter the index does not cover and it
re-dispatches twenty upstream calls, on somebody else's API key, to re-measure a revision that was
measured last week with the identical suite version. `role` exists so a run row can say why it was
created; it is not the pairing key.

**The consequence, stated rather than discovered:** `role` therefore never appears in this module's
pairing SQL, and `tests/integration/test_baseline_reuse.py` seeds the reusable run with
`role='candidate'` **deliberately** — a test that only ever seeded `role='baseline'` would pass under
either implementation and would prove nothing about which one shipped.

— **Reversibility:** cheap on the predicate, costly on the reuse rate the pilot will measure.

## D-293b — `get_released_revision` delegates to `get_revision` rather than joining

**Chosen.** One `SELECT released_version_id FROM registry.prompt_property WHERE id = :prompt_id`, and
then `return await get_revision(session, released_version_id)` when it is not NULL.

INT-011 says `get_released_revision` returns *"the same shape for whatever is released now"*. Delegation
**is** that sentence: the two readers cannot come to return different column sets, because there is only
one reader. A join would restate `registry.revision`'s column list in a second place, on a table whose
column list phase 13 owns, and the first column phase 15 adds would be present in one reader and absent
from the other.

**The cost, honestly: two round trips instead of one.** Both are primary-key reads on indexed columns
inside a transaction that is already open. The pairing is evaluated once per candidate run, not per
case.

**Under the tenant policy a prompt in another workspace returns no row**, so `None` covers both *"this
prompt has nothing released"* and *"this prompt is not yours"* — indistinguishable, which is A-116's
not-found-never-forbidden falling out of ADR-0045 rather than being implemented. Write that as the
docstring's one constraint sentence.

— **Reversibility:** cheap.
