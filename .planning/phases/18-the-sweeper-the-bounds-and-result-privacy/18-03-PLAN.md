## R3 — `batch_concurrency` is measured at the gate, per configuration, and not at the stub

The objective's own words: *"by the admission gate's in-flight high-water mark"*. Three reasons this is
the right instrument and not the stub server's `max_concurrent`:

1. `tests/provider/_stub_provider.py` is plan 11-04's file and is **not** in `files_modified`. 11-04's
   observer counts concurrency **globally**, and the claim under test is *per provider config* — so the
   stub as it stands cannot answer the question even if it were editable.
2. Counting in flight around the `dispatch` call would count coroutines **waiting** on the gate as well
   as admitted ones, which is a different number and always larger.
3. 11-04 asserts each cap holds within its own process using **3 and 2** — deliberately small and
   distinct. It therefore never asserts the shipped **8**. That number, and its per-configuration
   keying, is what is left.

So the gate is constructed and acquired directly, the in-flight counter is incremented **inside** the
acquired context, and the high-water mark is per `provider_config_id`. **Assert equality, not `<=`** —
11-04's stated rule: a gate that admitted one at a time would satisfy an inequality and would be a
different bug.

## R4 — "the only route" is an absence, and an absence is asserted over the source

AC-12's hardest clause — *"the ONLY route by which a row from an unset-tenant context is read"* — is a
claim about every line of code in the module, so no runtime test can decide it. It is asserted the way
`tests/architecture/test_no_sql_interpolation.py` and `tests/architecture/test_loggable_fields.py`
assert their claims: an `ast` walk over the package with an `ALLOWED` frozenset holding exactly one
entry and a written policy. Two guards make it non-vacuous — the walk must find at least one call site
overall, and `workspace_transaction` must appear as a called name in at least three modules of the
package, so a walk that silently matched nothing fails loudly.

**An addition to `ALLOWED` is a change to AC-12's claim**, not a maintenance edit. The policy comment
says so, and the executor reports rather than adding.

## R5 — the only writer of `refused`, asserted three ways because one way is not enough

1. **Structural**: 16-04's state machine maps `REFUSED` to exactly one legal predecessor, `RUNNING`.
   `transition(..., to=REFUSED)` from `queued` is refused in code — so no route *can* write `refused`
   before the claim, and the advisory refusal at `POST` therefore cannot write a row even by mistake.
2. **Source**: the literal `refused` and the symbol `RunStatus.REFUSED` appear under `src/prope/` in an
   allow-list of modules — the vocabulary (`evaluation/domain.py`), the state machine
   (`evaluation/runs.py`) and the one refusal branch (`evaluation/executor.py`) — and **no `text(...)`
   constant anywhere under `src/prope/` contains the literal**, so nobody writes the status by raw SQL.
3. **Behavioural**: over one lifecycle, exactly one row reads `refused`, and its `started_at` **is not
   null** — which is the mechanical proof that it passed through the claim, because
   `ck_eval_run_queued_has_no_start` and the claim function are the only things that stamp it.

The third alone would pass against a system with a second, unexercised refusal path. The first two
alone assert about code nobody ran.

## R6 — "every run eventually completes" is a bounded tick loop, never a wall clock

`pytest-timeout` is not installed (ORCHESTRATION §3), so an unbounded `while` in a drain test hangs the
whole suite rather than failing it. `claim_and_execute` is 16-05's **one tick**, and it returns what it
claimed precisely so a test can drive a single pass — the same motivation as `sweep_expired_bodies`'
`int` return. So the drain is `for _ in range(3 * len(runs) + 2)` with a `break` when a tick returns
`None`, and the assertion is that the loop **ran out of work rather than out of iterations**. Any wait
that must genuinely block is an `asyncio.wait_for` whose `TimeoutError` message names the property that
failed, not a sleep.
