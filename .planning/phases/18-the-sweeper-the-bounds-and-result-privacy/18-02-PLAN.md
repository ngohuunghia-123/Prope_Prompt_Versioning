## R1 — the guard is per DISPATCH, not per case, and that is a strengthening with a reason

D-336 says *"one indexed read at the top of each case"*. 16-05's per-case body acquires the semaphore
**around the `dispatch(...)` call only**, inside the retry loop — *"holding it across the assertion
evaluation would make a slow regex reduce the dispatch concurrency"*. So "the top of each case" and
"inside the semaphore" are two different places, and only the second one is guaranteed to precede an
upstream call.

**Chosen: the first statement inside `async with sem:`, before `await dispatch(`.** Three things
follow, and the third is the one that makes the guard provable:

1. It is **strictly stronger**. A run reaped during attempt 1's 60 s timeout does not pay for attempt
   2 or attempt 3. Per-case, it would.
2. It costs at most three primary-key reads per case instead of one, against a dispatch budget of up
   to 180 s per case. That is not a cost worth reasoning about.
3. It makes *"every dispatch is preceded by a check"* a **runtime-countable** property: over a healthy
   run, guard invocations equal dispatch invocations. A source grep would prove the tokens are near
   each other; a counter proves the ordering held on the path that ran.

**Rejected: a check before the fan-out only.** All N coroutines would read at t=0 and then dispatch
over the next two minutes, which is a guard that answers a question nobody asked.

## R2 — the abort is an `asyncio.Event` and an early return, never an exception

16-05's R6 gathers the per-case coroutines with `return_exceptions=False` and is safe **because no
per-case coroutine raises**. A guard that raised `RunNoLongerRunning` would propagate out of
`gather`, cancel every sibling, and discard the results of cases that had already been paid for and
written — at the exact moment the plan's purpose is to stop spending money.

**Chosen:** an `asyncio.Event` named `abandoned`, created per `execute_run` call, set by the first
coroutine that observes a non-`running` status. Every coroutine checks it before doing anything
(so the *second* through *Nth* pending cases cost nothing at all, not even a read), and
`execute_run` checks it once more before the completion transition and returns.

**One log line, not N.** After the read returns, `already = abandoned.is_set()`, then
`abandoned.set()`, then `if not already: log.warning(...)`. There is no `await` between the check and
the set, so within one event loop no two coroutines can both take the logging branch. That is what
makes *"exactly one `evaluation.run_abandoned` record per abandoned run"* an assertion rather than a
hope.

### Step 2 — the guard

```python

    sessionmaker: async_sessionmaker[AsyncSession],
    claimed: ClaimedRun,
    abandoned: asyncio.Event,
) -> bool:
    """Whether this run is still `running`, and therefore still worth paying for.

    Sets ``abandoned`` and logs once when it is not. Never raises: a raise here
    would cancel every sibling case (16-05's R6).
    """
```

Body, in this order and no other:

1. `if abandoned.is_set(): return False` — the short-circuit. Once one case has seen the reap, the
   remaining pending cases cost **zero** reads, which is what keeps a 200-case suite from issuing 200
   pointless statements after a reap.
2. Open `async with workspace_transaction(sessionmaker, claimed.workspace_id) as session:` and
   `observed = (await session.execute(RUN_STATUS_NOW, {"run_id": claimed.run_id})).scalar_one_or_none()`.

   existed are both `None` here, and both mean *stop*, so the guard must not raise on either.
3. `if observed == RunStatus.RUNNING: return True` (or `== RunStatus.RUNNING.value` — Task 1 answer 3
   decides which, from whether `RunStatus` is a `StrEnum`).
4. Otherwise, in exactly this order with **no `await` between the first two**:
   `already = abandoned.is_set()`; `abandoned.set()`;
